# C 族（列表型）弹窗改造 · 视觉验收证据

对应提交：`a7eaae4`（关键帧外传审阅）、`83e0c74`（素材语义检索）、
`770999c`（机位同步）。

## 这份证据为什么存在

用户在 2026-11-09 指出：这三个弹窗**没有单独的原型稿**，只有一份覆盖「形态」的
结构稿（`docs/ui-mockups/dialog-system-v2/prototype-list-family.html`），
所以没法验收我改的是否满足要求。

这份目录补的就是这个缺口：**每个弹窗一对 before/after 截图 + 一份取值对照表**。

## 怎么验收

1. 看 `*-before.png` 与 `*-after.png`：同一场景、同视口、同主题；
2. 看下方「取值对照」：每个数字都有实测出处，不是设计声明；
3. 想复核：`apps/desktop/tests/*-align.test.ts / *-table.test.ts` 把取值锁成了断言，
   改回旧值会变红（变异验证记录在各 commit message 里）。

## 场景与视口

- 视口 1280×800，深色主题（Graphite Precision 令牌）
- 截图内容是用**真实 `styles.css` + 与组件一致的 DOM** 渲染的弹窗，
  不是设计稿 —— 所以量到的就是产品里会出现的尺寸

## 1 · 关键帧外传审阅（`a7eaae4`）

**改前**：`keyframe-frame-list` 等类名在样式表里**没有任何专属规则**（只有
`.keyframe-result` 两条），实际用的是浏览器默认 `<ul>`——带圆点与左缩进，
行内元素靠默认排版挤在一起。

| 项 | 改前 | 改后 |
|---|---|---|
| 列表 | 浏览器默认 ul（圆点 + 缩进，无卡片） | 卡片行 + 圆角 + 6px 间距 |
| 行内布局 | 默认 inline 排版 | 主信息 | 徽章 | 按钮 三列 flex |
| 状态 | 无状态显示 | 徽章固定 62px（待外传 / 已移除） |
| 已移除行 | 仅按钮禁用 | 降透明度 + 标题删除线（非颜色单通道） |
| 汇总行位置 | 列表下方 | 列表上方工具栏 |

**对齐实测**（改后，各 1 种取值）：徽章左缘 801 / 宽 62 / 右缘 863；
按钮左缘 875 / 右缘 922；行右缘 935。间距一致 12px。

## 2 · 素材语义检索（`83e0c74`）

**改前**：样式段含 **8 处硬编码色值**（`#d16055` / `#2e211f` / `#eec4be` /
`#303b40`×3 / `#d1a453` / `#8b9aa1`），绕过全部 Graphite 令牌；列表行只有
下划线分隔；状态是纯文字，宽度随文案漂移。

| 项 | 改前 | 改后 |
|---|---|---|
| 色值 | 8 处 `#hex` 硬编码 | 0 处，全部令牌化 |
| 行 | 下划线分隔 | 卡片行 + 圆角 + 6px 间距 |
| 分数列 | 无固定宽，宽度随位数变 | 固定 56px 右对齐 + tabular-nums |
| 状态 | 纯文字 | 徽章固定 62px |

**对齐实测**（改后）：命中行高 36；分数列 x=866 / 右缘 922；
徽章 x=860 / 宽 62 / 右缘 922。两组右缘都落在 **922**。

## 3 · 机位同步（`770999c`）

**改前实测**：表头 13px（与正文同号）；单元格内边距 4px 6px；
**偏移/置信度两个数字列全部左对齐**；分隔线用 `var(--ctl-bg)`（控件填充色）当线色。

| 项 | 改前 | 改后 |
|---|---|---|
| 表头 | 13px，与正文同号 | 10.5px（`--dlg-fs-caption`），分层 |
| 单元格内边距 | 4px 6px | 9px 8px |
| 数字列对齐 | 左对齐 | 偏移 / 置信度**右对齐** + tabular-nums |
| 分隔线 | `var(--ctl-bg)` | `var(--dlg-line)`（发丝线） |
| 表格布局 | auto —— 状态列被撑到 144px | fixed + 六列显式宽度 |
| 状态 | 纯色文字 | 徽章固定 62px，原因独立成行 |

**列宽实测**（改后）：机位 102 / 状态 92 / 偏移 84 / 置信度 72 / 来源 64 / 手填 176。

### 表头与数据对齐（用户二次指出后修正）

用户看图后追问：「左对齐还是右对齐还是中间对齐，需要和其他弹窗统一起来」。

实测确认问题在**状态列**：表头 `text-align: left`，而 td 内是定宽 62px 居中的徽章，
视觉上表头偏左 22px。修法是把该列的 **th 与 td 都设为 center**（只改 th 不够——
td 仍是 left，定宽徽章靠自身居中"伪装"成居中，这也是我第一版改错的地方）。

六列最终对齐方式（表头 = 数据）：

| 列 | 对齐 | 理由 |
|---|---|---|
| 机位 | left | 变长文本 |
| 状态 | **center** | 定宽徽章居中，表头须跟随 |
| 偏移 | right | 数字列，便于纵向比较 |
| 置信度 | right | 数字列 |
| 来源 | left | 短文本 |
| 手填 | left | 表单控件 |

> 与其他弹窗的一致性：keyframe / 语义检索两个弹窗**没有表头**，不存在此问题；
> 三者共用的是「状态徽章定宽 62px 居中」这条契约，本轮未破例。
