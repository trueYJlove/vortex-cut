## 1. 方法与可复现性

**被测对象**：本仓自己的 `aivs_core.media.clip_tokenizer`（真实 BPE，非占位实现），
与本仓入库的 CLIP 官方 `tokenizer.json`。

```
资产：.tmp/clip-probe/tokenizer.json
sha256：f7f3b7af117d467b58374797691a6438d3e6b9e9cef800dfd5dced7f697a90cd
```

**复现命令**（在仓库根目录）：

```bash
.venv/Scripts/python.exe -c "
import sys; sys.path.insert(0, 'services/core/src')
from aivs_core.media.clip_tokenizer import load_tokenizer
tok = load_tokenizer('.tmp/clip-probe/tokenizer.json')
for t in ['cat', 'a person talking', 'a person standing on a beach watching the sunset',
          '猫', '一个人在说话',
          '画面中有一个人站在海边看着远处的落日']:
    ids, mask = tok.encode(t, 77)
    row = ids.tolist()[0]; n = int(sum(mask.tolist()[0])); body = row[1:n-1]
    print(len(t), len(body), body[:8])
"
```

## 2. 读数（实测，原样记录）

| 语言 | 输入字符数 | body tokens | token/字符 | 首 8 个 token id |
|---|---|---|---|---|
| en | 3（`cat`） | **1** | 0.33 | `[2368]` |
| en | 16 | **3** | 0.19 | `[320, 2533, 2578]` |
| en | 48 | **9** | 0.19 | `[320, 2533, 2862, 525, 320, 2117, 2113, 518]` |
| zh | 1（`猫`） | **3** | **3.00** | `[163, 234, 360]` |
| zh | 6 | **13** | **2.17** | `[19759, 222, 19759, 103, 36839, 37746, 101, 164]` |
| zh | 18 | **42** | **2.33** | `[20211, 119, 165, 251, 95, 19759, 255, 19277]` |

**语言内自洽**：英文约 **0.19** token/字符；中文约 **2.2–2.3** token/字符。
**跨语言差约 11–12 倍**（同字符数下）。

## 3. 机制（为什么是这个读数）

CLIP 的 `pre_tokenizer` 用 `[\p{L}]+` 切分。`中` 的 `isalpha()` 为真 ⇒ **整段连续汉字被当作一个"词"**，
送进 BPE。而 CLIP 词表是**英文预训练**的，不含汉字 ⇒ BPE 无法合并，
逐字节回退到 GPT-2 byte-level 映射：

- 一个汉字 = 3 字节 UTF-8 ⇒ 约 **3 个 token**（实测 `猫` → `[163, 234, 360]`）；
- 相邻汉字偶尔能合并少量字节对 ⇒ 长句略降到 **2.2–2.3 token/字符**。

**关键含义（本文件最重要的一条）**：

> 中文经 CLIP 分词得到的 token，**在英文词表里承载的是"字节"而非"语义"**。
> 这不是「中文效果差一点」，而是**中文没有走语义路径**。

## 4. 可推断的后果（含边界）

**可以说的**：

1. **上下文预算被压缩**：CLIP 上下文 77 token，去掉 `<|startoftext|>`/`<|endoftext|>` 后约 75；
   按 2.33 token/字符，中文实词预算约 **32 个汉字**。超过即被截断（截断发生在**语义完成之前**）。
2. **CJK 每个字都能"塞进"词表**：因为是字节回退，**不会报错、不会空串**——失败是**静默的**。
   这一点比直接报错更危险：系统看起来正常工作，只是排序接近噪声。

**不可以说的（必须防误读）**：

1. **本文件没有测端到端中文检索命中率**。证明的是**分词层**劣化，不是 top-k 读数。
2. **「接近随机」是有依据的预期，不是实测结论**。CLIP 训练语料含网络图片与 alt-text，
   可能见过少量中文（中英混排场景不少）。真实值可能**优于**随机——本文件不主张具体数值。
3. **不得据此宣布中文检索不可用**，也不得据此批准任何「适配方案」。本文件**零代码改动**。
