## 为什么能做这件事

W2.1 验收 9 原阻塞于"用户提供真实多机位素材"。AMI 同一场会议提供**多路阵列通道**
（Array1-01…08、Array2-01…08、Mix-Headset）——**同一场景由多个真实设备同时捕获**，
正是验收 9 需要的素材形态。

素材：**ES2004a**（AMI，CC BY 4.0），基准窗起点 300 s。

## 结果一：算法在真实远距设备上**估计正确**

不同阵列（Array1-01 vs Array2-01，物理上相隔较远 ≈ 两个机位）：

| 构造 | 真值 | 粗估 `coarse_us` | 判定 |
|---|---|---|---|
| 对齐 | 0 | **0** | ✅ |
| 成员晚 83 ms | −83 ms | **−80 ms** | ✅（误差 3 ms，小于粗估自身 10 ms 栅格） |
| 成员晚 400 ms | −400 ms | **−400 ms** | ✅ |
| 同阵列相邻（对照） | 0 | 0 → `ready offset=−83 µs` | ✅ |

## 结果二：**置信度口径在真实多设备上失准**（本目录的核心发现）

| 通道对 | 物理关系 | 置信度 | 结论 |
|---|---|---|---|
| Array1-01 ~ Array1-02 | 同阵列**相邻**单元 | **0.970** | `ready` |
| Array1-01 ~ Array1-05 | 同阵列**对角**单元 | **0.916** | `ready` |
| Array1-01 ~ Array2-01 | **不同阵列（远距 ≈ 两机位）** | **0.462** | `unavailable(low_confidence)` |
| Mix-Headset ~ Array | 完全不同设备类型 | 0.09（NLCC） | 拒 |

- **窗长不是原因**：60 / 180 / 420 s 三档置信度恒为 0.462（因为置信度来自 2 s 精细窗）。
- **双窗一致性也不是原因**：被拒样本的 `dual_delta_us` 为 187–312 µs，远在 5 ms 容差内。
- **唯一卡住的是置信度**：0.462–0.468 vs 阈值 `CONFIDENCE_THRESHOLD = 0.5`。

## 机制诊断（`nlcc-diagnostic.txt`）

2 s 窗上的**零均值归一化互相关**（NLCC）：

| 对 | NLCC | 滞后 |
|---|---|---|
| 同阵列相邻 | 0.569 | −0.12 ms |
| 同阵列对角 | 0.571 | +0.12 ms |
| **不同阵列** | **0.525** | **+0.15 ms** |
| Mix-Headset ~ Array | 0.092 | −652 ms |
| 自相关基线 | 1.000 | 0 |
| 人为 +83 ms（方法自检） | 0.488 | **−82.88 ms** ✅ |

⇒ 不同阵列的**原始信号相关性只比同阵列低一点（0.525 vs 0.569），且滞后≈0**——
**信号是可用的**，被拒是**置信度指标/阈值的标定问题**，不是素材问题。

## 结论与建议

1. **W2.1 的估计器在真实远距设备上是正确的**（含已知非零偏移）。
2. **`CONFIDENCE_THRESHOLD = 0.5` 把合法输入拒之门外**：真实远距设备落在 0.46–0.47。
   该阈值原由**合成同源 fixture** 标定（R3：同源 0.788 / 无关 0.052），**未在多设备真实素材上验证过**。
3. **建议**：在真实多设备素材上重标阈值（"无关"实测仅 0.052，即使降到 ~0.35 仍有约 7× 余量），
   或改用更稳的一致性度量（如 NLCC + 双窗一致性联合判据）。**须作为 W2.1 的后续工作项裁决**（P94）。

## 边界（如实）

- AMI 阵列各通道**出厂同步**（实测滞后 +0.15 ms），真值偏移为 0；**已知非零偏移**由本目录的
  "裁切起点"构造给出（合法：同一真实素材、已知平移量），**不是**天然带非零偏移的多机位素材。
- 仅 1 场会议（ES2004a）、1 个时间窗（300 s）。
- **不是** Electron 端到端：本条证据在 Core 算法层，验收 9 的"端到端"部分仍未取证。
