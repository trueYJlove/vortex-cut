# W3.1 中文 CLIP **fp32 双塔** 效果评测 —— 结果

> 严格对照 `PRE_REGISTRATION.md`。**F0–F5 判定见 §2**，其中 **F1/F3 需按下文限定读**。
> 上游：P151（品类词级，quantized 单塔 1.00 vs 现役英文 0.30）、P152（句子级，quantized）。
> 日期：2026-10-20

---

## 1. 一句话结论

> **在 57 张图 / 10 个查询上，fp32 双塔与 quantized 单塔的中文 top1 都是 1.00（10/10），
> 差值为 0 —— 但四组读数全部打满、零方差，本实验无法分辨二者谁更好；
> 只能判定「fp32 双塔中文检索没有可测的退化」。**

多下 754MB **换不来任何可测的效果提升**，也**不带来可测的退化**——
即：若目标是「中文检索效果」，quantized 单塔已足够；fp32 的收益需由**其它**理由（如导出形态
与生产部署一致、量化在更大数据集上的未知风险）来支撑，**不由本实验支撑**。

## 4. ⚠️ 必须同读的限定（否则会高估本实验）

### 4.1 **四组全部打满 ⇒ 主判据零方差，没有鉴别力**

F1 形式上是 PASS，但它是**天花板效应下的 PASS**，与 P151 §3.1 记录的 Z5 问题**同型**：
一个满分、无方差的离散指标无法区分模型优劣。

F1 真正支持的说法只有一句：**「B 至少不比 A 差一条查询以上」**（容差 0.10 = 一条查询）。
它**不能**支持「B 与 A 一样好」的强表述——那需要能分辨 0 与 0.10 之间的读数，本样本给不了。

### 4.2 事后追加的连续诊断（**探索性，非判据**）

离散指标全满后，脚本补了 `margin / mean_rank_same_topic`（预登记 §2.1 已如实登记
「这是**看完 A/B/C/D 之后**追加的」）。读数：

| 组 | mean_margin | min_margin | mean_rank_same_topic |
|---|---|---|---|
| A (quantized, zh) | 0.0674 | **0.0137** | 3.387 |
| B (fp32, zh) | 0.0713 | **0.0284** | 3.370 |
| C (quantized, en) | 0.0686 | 0.0175 | 3.575 |
| D (fp32, en) | 0.0807 | 0.0215 | 3.367 |

逐查询配对差（B−A，n=10）：mean **+0.0040**、中位 +0.0066、**bootstrap 95% CI [−0.0046, +0.0117]（含 0）**、
符号检验 **7/10，p = 0.344**。
逐查询配对差（D−C，n=10）：mean +0.0122、95% CI [+0.0018, +0.0223]、符号检验 8/10，p = 0.109。

**怎么读（不许越界）**：
- **中文侧：fp32 与 quantized 在统计上不可区分**（CI 过 0）。**不能说「fp32 更好」。**
- 英文侧 D−C 的 CI 不含 0，但 p = 0.109、n = 10，**不足以**宣称「fp32 英文更好」；
  只能说「未观察到英文退化」，这与 F3 一致，也正是 P150 提出的那个疑虑的**部分**回应
  （P150 只测了分词长度，本轮测了排序质量）——**不是**答疑，样本太小。
- 唯一值得一提的稳健观察是 **min_margin**：A 的 0.0137 明显小于 B 的 0.0284，
  即 quantized 的最紧一条查询余量更薄。**这是单点观察，未做检验，不得当作结论。**

### 4.3 样本量：N = 10 条查询

一条查询翻转 = 0.10。**任何小于 0.10 的 top1 差异在本样本上不可区分**，
不得当成效应量。§4.2 的连续量虽比 0/1 细，但分母仍是 10 条查询。

### 4.4 未测的部分

- **句子级未复跑**（理由见 §6）；
- **真实视频抽帧未测**（图集是 Commons 照片）；
- **口语化查询未测**（查询是单品名名词）；
- **速度 / 内存 / 体积代价未测**（本轮只测效果）。

## 6. 句子级为何未复跑（已核查，非推断）

- 8 条中文维基百科条目首句**只入库了 1 条**——`2026-10-19-w31-zh-sentence-eval/PRE_REGISTRATION.md:45`
  引用的 bicycle 首句 `自行車是種以人力踩推腳踏板驅動的小型非机动车。`；
- 其余 7 条**不在仓库任何文件中**（全仓 grep 中文句特征零命中，`result.json` 只存聚合读数）；
- 生成它们的脚本**不在 `.tmp/`**（grep `exsentences` 零命中），无法重放；
- 该记录同时写明 `zh.wikipedia.org` 直连不可达、必须经本地代理 ⇒ 重抓依赖网络环境。

⇒ **本轮只做词级**。句子级维持 P152 的 quantized 读数，**不得**把 fp32 结论外推到句子级。

## 7. 结论上限（自限，无论读数多好都成立）

本实验**最多**支持：

> 「在 57 张 Wikimedia Commons 图片、**10 个品类**、**单个品类名词**作查询时，
> fp32 双塔中文 CLIP 的 top1 相对 quantized 单塔的退化**不超过一条查询（0.10）**；
> 二者在本样本上**统计不可区分**。」

**不得**据此宣称：

1. **真实视频抽帧**上的效果——图集是 Commons 照片，不是视频帧；
2. **口语化查询**（「一只猫在沙发上」）——查询是单一品类名词；
3. 更大的样本——**57 图 / 10 品类 / 10 条查询**，单项翻转即 0.10；
4. **句子级**——句级仍是 quantized 读数（§6）；
5. **fp32「更好」或「值得多下 754MB」**——中文侧 CI 含 0（§4.2）；
6. 其他语言、其他模型、其他量化方案；
7. **速度 / 内存 / 体积**的交换比——本轮未测。

## 8. 复现方式

```bash
# 四组（A/B/C/D）一次跑完 + 确定性重跑
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe tools/model_eval/eval_zh_clip.py \
  --images .tmp/zh-eval/img \
  --catalog evidence/2026-10-19-w31-zh-query-eval/catalog.json \
  --tokenizer .tmp/cc-probe/tokenizer.json \
  --merged .tmp/cc-model/model_quantized.onnx \
  --vision .tmp/cc-export/out/vision_model.onnx \
  --text   .tmp/cc-export/out/text_model.onnx \
  --suite --repeat 2 --out .tmp/fp32-eval/result_full.json

# 负向对照（打乱真值）
#   …… --suite --shuffle-truth 20261020
```

**预处理/分词与生产一致性核对**（`services/core/src/aivs_core/media/semantic_service.py`）：

| 环节 | 生产位置 | 本脚本如何保证一致 |
|---|---|---|
| 尺寸 224 | `CLIP_IMAGE_SIZE` **:69**；`scale={CLIP_IMAGE_SIZE}:{CLIP_IMAGE_SIZE}` **:110** | **import 同一常量**，ffmpeg 用同一表达式 |
| 归一化 | `preprocess_image` **:118-123**（`/255` → `(x−MEAN)/STD`） | **直接 import 该函数**，不重写 |
| MEAN/STD | `CLIP_MEAN` **:71** / `CLIP_STD` **:72** | 由 `preprocess_image` 内部使用，同源 |
| 像素格式 | `rgb_frames_args` **:99-115**（rawvideo rgb24） | 同一条 ffmpeg 参数 |
| context len 52 | `ZH_CONTEXT_LEN` **:46** | **import 同一常量** |
| 分词 | `clip_tokenize` **:175-187** → WordPiece 分派 **:185** | **直接 import `load_wordpiece_tokenizer`** |
| 相似度 | `l2_normalize` `semantic.py:31`（:37-41 归一化） | **直接 import**，float64 点积 |

**零新增依赖**：`numpy` + `onnxruntime`（均在 `pyproject.toml:11-12`）+ 仓库自带
`resources/ffmpeg/win-x64/ffmpeg.exe`。**未使用 PIL**（不在依赖清单内）。

## 9. 过程记录（如实登记）

1. **预登记先于读数**：`PRE_REGISTRATION.md` 在任何 fp32 数字之前写定（含 F0–F5 与结论上限）。
2. **事后追加诊断**：四组打满后追加 `margin/rank`，已在预登记 §2.1 明确登记为**事后**，
   并写死「不参与 F1–F5」。这是一次**真实的流程偏离**——理想做法是预登记时就预见到天花板。
3. **修正的一处自身错误**：初版 `n_images_per_query` 用 `57//10 = 5`，而真值是
   每 query 同 topic 图数不等（mushroom 4、lighthouse 5、其余 6，均值 5.7）。已改为实测均值。
   （**不影响 top1/top3**，只影响诊断字段。）
4. **单塔输入独立性已实测**：融合模型 `image_embeds` 对 text 输入的最大差异 = **0.0**，
   `text_embeds` 对 `pixel_values` 的最大差异 = **0.0** ⇒ 给无关输入是安全的；
   且全零 attention_mask 不产生 NaN（未触发，但仍按 `[CLS][SEP]` 喂入）。
