## 0. 现状与量化数据（2026-09-20 实测）

- **瓶颈根因**：`cv_video_args` 的 `select` 滤镜在**全量解码之后**——1080p50 素材 8400 帧全部解码再丢弃 98%。dance（168s）54.6s 墙钟 vs lichun（同为 167 采样点）12.4s，与"50fps×1080p ÷ 30fps×720p ≈ 3.75×解码成本乘积"吻合。
- **优化实测**：`-skip_frame nokey`（解码器跳过非关键帧解码）dance **6.4 倍加速（22.3s→3.5s，纯视频遍历）**，采样输出**逐字节一致**（sha256 对拍）。
- **代价（同素材对拍）**：长 GOP 素材 lichun 的"≥1s 兜底采样"在 skip_frame 下失效——兜底依赖非 I 帧时间戳（解码器已跳过），167 帧→30 帧，最大采样空洞 8.3s（GOP 长度上限）。运动能量信号在空洞内不可见。
- 性能门对照：dance 19.5s/分（超门）——skip_frame 后估算 ≈3-4s/分；lichun 本已达标。

## 1. 裁决请求与建议方案

**裁决项**：采样策略采用何种组合。

**建议方案（混合自适应）**：

1. **默认快路径**：`-skip_frame nokey` + 纯 I 帧采样（`select=eq(pict_type,I)`，去掉 ≥1s 兜底子句——它在 skip_frame 下无意义）。
2. **稀疏回退**：分析器统计采样点最大间隔；**间隔 > 4s（GAP_THRESHOLD，可配）** 的素材自动用全量解码路径重跑（兜底恢复）。代价：长 GOP 素材仍慢（但此类素材少）；收益：无空洞盲区。
3. `algorithm_version` 递增（信号语义变化：运动能量粒度随路径不同——召回层加权不敏感，文档登记）。

**否决方案**：
- 纯 skip_frame 不回退：lichun 类素材 8s 盲区，运动信号失真——否决。
- 维持现状全量解码：性能门在 50fps 高密度素材上持续超标——否决。
- 密度参数用户可调：普通用户无判断依据，搁置（性能门测量后再议）。

## 2. 范围

1. `cv_video_args` 双路径（快/全量），`CvSignalService.run_analysis_job` 稀疏检测与回退编排（首次快路径 → 间隔检查 → 必要时全量重跑；墙钟预算内）。
2. `algorithm_version` 1→2；v21 表结构零变化（`cv_samples` 兼容）。
3. 既有单测适配（ffmpeg 参数断言）；新增对拍测试（纯 I 帧素材双路径逐字节一致——已实测验证的回归锁）；合成长 GOP fixture 的回退触发测试。
4. 性能门复测（dance + lichun + science 三素材，替代性达成 A1 门）。

## 3. 验收（LiuKeAi）

1. 对拍回归：纯 I 帧素材（dance）快路径输出与旧路径逐字节一致（sha256 锁）；
2. 回退正确性：合成长 GOP 素材触发回退，兜底采样点恢复，无 >4s 空洞；
3. 性能门：三素材每分钟源墙钟 ≤10s（dance 预期 ≈4s/分）；
4. 召回层回归：三素材场景段数量/排序与阶段三基线一致（或差异可解释——粒度变化导致的运动排序微调允许，人脸/切点不得回归）；
5. Core 全量 + `algorithm_version` 升级后旧分析行 stale 语义正确。

## 4. 风险

| 风险 | 对策 |
|---|---|
| 稀疏检测阈值 4s 对特定素材不合适 | 可配常量；召回层只加权不硬过滤，粒度损失代价是排序偏移 |
| 双路径增加分析墙钟上界（最坏 2×） | 回退仅长 GOP 素材触发（少数）；性能门以真实素材复测兜底 |
| algorithm_version 升级触发全量重分析 | 召回层取最新 ready；旧行标 stale 不重算（既有机制） |
