## 2. 夹具构成（全部本地，零 egress）

| 素材 | 来源 | 用途 |
|---|---|---|
| 口播素材（夹具） | 真实人声 + 每 5s 插入 **数字静音**（`buildPauseFixture`，视频流原样 copy） | 去停顿 / ASR / L-J |
| BGM 音乐 | 真实音乐 mp3 | 节拍分析 / 卡点 |
| 镜头素材 ×2 片段 | 合成 1080p 60s | 卡点镜头段 |
| 无音轨素材 | 合成 video-only | 卡点「无法检出节拍」 |

**为什么要人工插静音**：CV 的 `audio_energy` 是 1s astats 窗口，真实录音窗口极少低于阈值
（实测原素材 21 个采样全高于 0.05），去停顿时会得到「未检出有效静音」而失去区分力。
夹具把真实人声按 5s 间隔重排，静音段是真正的数字 0 ⇒ 任何采样密度都能检出（且仍用真实人声做 ASR）。

## 5. 观察项（本轮未修，留待裁决）

1. **「BGM / 音频轨」默认选中项不是音乐片段**：面板取 audioClips 末位，L/J 派生出的 A1 音频片段排在音乐之后 ⇒ 用户点「分析节拍」很可能分析到人声而不是 BGM。
2. **素材「改回原样」后仍为 changed**：`refreshAsset` 用新指纹覆盖基准（`projects.refresh_asset`），内容改回原样无法自证 ⇒ availability 停在 changed，且 Core 对任何 TimelinePatch fail-closed（`TIMELINE_SOURCE_INVALID 素材不可用于 Timeline`）。只读语义下需重新导入才能恢复。
3. **卡点采纳的语义是「头部插入一段」**：设计（`BEAT_SYNC_PLANNING_GATE_2026-09-24.md` §2.2）只输出 insert 序列、由调用方负责既有内容 ⇒ 采纳后原有片段整体后移、时间线变长；与「目标成片时长 15s」的字面理解可能不同，建议在用户手册/清单里写清。
4. **节拍 API 集成测试在满载（与本 e2e 并行）下出现过 1 次失败**，单跑与成对跑均绿，未复现；登记备查。

## 6. 仍需人工的部分（签字项）

- 听感：J/L 入声错位的**听感**是否自然；卡点成片是否「对拍」；去停顿后的跳切是否顺畅。
- 真机素材：本自动化用「真实人声 + 人工静音」夹具保证确定性；建议再用一段**未经加工**的真实口播做一次人工去停顿时验收（尤其阈值 0.05 是否合适）。
- 真机项目上的端到端观感（时间线闭合、预览播放、导出前观感）。
