# P235 OpenFilm 时间线完整对照计划

项目状态只见 [`docs/STATUS.md`](../STATUS.md)。P235 接续 P234 的未完成目标；P234 的定向验证与滚轮结果仅作历史证据，不代表时间线整体对齐。OpenFilm 对照版本固定为本地 checkout commit `b125a3d9`。

## 目标与设计决策

以 OpenFilm 时间线用户可观察的布局、手势与编辑结果为准，在 Vortex Cut 的 TimelineDocument 和 Core `TimelinePatch` 上实现相同行为。用户已明确要求完整对齐；任何已知功能差异、明确拒绝或未完成的视觉/性能证据都不能计作 parity 通过。保留 Canvas 渲染与 Core 修订边界，不搬整套 OpenFilm React 组件。手势开始时固定指针抓取信息、被操作对象和选择组；每次预览都读取最新文档、偏好、播放头和轨道，修订变化时重新规划，松手时用最后指针坐标针对最新文档同步规划并提交。若最新修订无法安全提交则取消。预览、松手提交和一次撤销都必须源自同一份完整编辑计划。

范围是时间线及从素材栏到时间线的放置；OpenFilm 应用壳的跨面板停靠/移交不属于时间线编辑。操作模式按源码区分：内部素材移动为 `Place`、`Insert` 或经确认的 `Replace`；素材栏拖入的媒体另测 `Overwrite`。移动时按住/松开 Alt 会在 `Place` 和 `Insert` 间动态切换；移动开始时 Alt 已按下代表复制；修剪开始时 Alt 不带动显式链接伙伴，但同轨 main-track magnet 引起的后继 ripple 仍生效。

## 1. 受控视觉基线

锁库中的原生 Electron 运行时不同（OpenFilm 44.9.3、Vortex 36.2.1），不能声称它们是相同构建。严格像素对照使用同一台机器、同一个固定 Chrome `157.0.8103.51` binary（manifest 记录 binary SHA-256），OpenFilm 的 browser 支持入口与 Vortex 的 Timeline renderer fixture route 在同一 Chromium build、同尺寸独立页面中呈现。产品集成另对原生 OpenFilm 44.9.3 与 Vortex 36.2.1 以相同 fixture 截屏；每个组件几何≤1px、computed colors/fonts/radii/states 与 renderer harness 的值逐项一致，独立记录 native per-region raster 差异，不把不同 Electron 字形栅格差冒充布局错误或忽略 native 结果。窗口内容尺寸 2130×1120、DPR 1、深色主题；只对齐实际 timeline 区域的 380px 高截图，时间线轨道面板都固定为 380px。构造同一个视觉夹具：相同媒体字节、四条轨道 `V3/V2/V1/A1`、相同轨类型/顺序、至少八段视频与音频片段、相同源区间/正速度/开始/结束时间、主轨/副轨内容、波形和播放头位置。

将同一夹具清单和构建脚本纳入仓库，固定 OpenFilm commit、Vortex commit、媒体文件 SHA-256、窗口/DPR/主题、项目帧率固定为 30000/1001（29.97fps）、全部轨道 ID/类型/顺序/锁定/可见/solo/行高、每个 clip 的 ID/源素材/源入出点/速度/方向/link group/时间线入出点、转场/标题/音量、选中/目标轨/播放头/标记/工具模式，以及两端运行时版本。先清除并校验用户 profile 对缩放和轨高的覆盖。两边精确设成 28 CSS px/s、scrollX=0、标尺起点 00:00、播放头 00:08、标准行高和展开 Solo 控件。不可各自 Fit-to-content，也不可沿用用户 profile 中保存的缩放和轨高。固定工具模式、选中素材和标记点状态。夹具任一字段不同、图片/波形解码尚未就绪、或区域布局尺寸不同，该样本作废。

用 DOM/Canvas 读数加同区域 PNG 验收：

- 工具栏、标尺、轨头、封面列、逐轨行框和 clip 矩形几何锚点误差 ≤1 CSS px；每秒刻度位置误差 ≤1 px，像素/秒数值必须相等。
- 每个视觉区域独立判定，禁止全屏/整轨聚合掩盖局部差异：工具栏、标尺、轨头、封面列、播放头/标记及每条行背景分别达到 99% 非文字像素的 RGB 通道差 ≤3；每个 clip body、标题条和边框分别达到 99%；每个缩略帧 strip、每段 waveform 分别达到 97%。文字区域单独对比：95% 字形像素 RGB 差 ≤8，字体/字号/基线/名称截断位置误差 ≤1px。各区 mask/坐标随 fixture manifest 固定。
- 记录截图、全部几何读数和区域化差异图。若控件状态或媒体内容不同，该样本不能用于接受视觉项。

## 2. 拖动与时间线功能

### 手势时序

- 时间线 clip/cue 的移动与修剪使用 Pointer Events/pointer capture。按下时记录 gesture identity、起始几何、抓取偏移、选择组；不冻结文档快照。每次移动从 latest 文档/偏好/播放头/轨道重新规划；如果 Core revision 改变则基于最新修订重算。clip/cue move 在 `|dx| >= 5px` 或 `|dy| >= 5px` 时进入拖动态；空白区框选仅在 `|dx| >= 5px` 时进入拖动态，纵向移动不触发；trim 与 speed edge 仅在 `|dx| >= 1px` 时进入拖动态，纯垂直移动不触发修剪。未达到对应阈值时保持点击行为；越出画布、滚过预览 iframe 仍接收指针。
- 素材栏资源与 Windows 文件拖入保持 OpenFilm 原生 HTML5 Drag and Drop/DataTransfer 路径，不套用 clip 的 pointer capture/5px 状态机。dragover 按真实 Transfer type 与当前文件/资源判断 dropEffect、时间/轨道目标、Alt、Replace 与 Overwrite 预览；drop 同步读取受保护的 Transfer data 再创建/替换/导入。dragend、有效区域外的 dragleave、Esc/cancel 清空提示且不提交；文件多选、无效 payload、锁轨、拒绝 Replace、drop 边缘和失败态都纳入矩阵。
- 事件合并至每帧最多一次。松手前按最后指针坐标对最新文档同步重算；无法对最新修订安全提交时取消。pointercancel、Escape、window blur 只取消，不写 patch。
- 48px 边缘区自动滚动，速度按距离从 6px/frame 增至 24px/frame；指针不动时落点仍随滚动更新。
- 普通移动预览保留片段内抓取偏移，修剪边/速度边即时跟手。缩放改变时以相同 8 CSS px 吸附门限量化时间。
- 交互规划在写入 TimelinePatch 前按 OpenFilm `timeline-edit.ts` 的 `sec(ms) => Math.round(ms) / 1000` 规则量化到整毫秒；内部仍用整数微秒，但同一次手势的 preview、commit、undo/redo 对照不得留下亚毫秒位置差。

### 落点与编辑计划

- 同轨空隙/相邻边、同轨重叠、跨轨空位、目标轨内现有素材，以及轨道上下 `DropBand` 均纳入。Clip 左右边缘宽度为 `min(12px, clipWidth/4)` 且优先于上下角；上下边缘宽度为 `min(4px, rowHeight/6)`；行 gap 映射为下一行 `above`，行组外上/下分别创建第一/最后轨。素材左右边缘分为 before / after，素材中部为 replace，素材上下窄边优先开新轨。显式 clip before/after 会覆盖 row band，作为 `insertAtMs` 无论 Alt 状态都强制 Insert；它把来源落点对齐目标边，不关闭来源空隙，除非主轨 magnet 单独要求关闭。无显式边缘 Insert 点时，Alt Insert 才在所有来源轨关闭被提起的 source spans，再按插入点推动目的轨后继。
- 仅试指针实际指向的轨道，不把整组自动挪到另一个“能放下”的轨道。整组选区保持轨道差/时间差；任一成员落在锁轨、媒体类型不符、组内重叠或不存在的行时整组拒绝。Place 冲突新视觉轨插在目标上方、音频轨插在目标下方；DropBand 顶/底按指向处创建兼容的新轨。能通过新增轨道解决的整组占位冲突须按组每条源轨开新行并保持相对轨道/时间形状，不把它当作拒绝落位。音频轨可多个并能按目标位置排序；锁定轨不作为目标，兼容性及行变化在预览中立即显示。
- 默认 `Place` 在占用位置开轨保留原素材；普通 Alt `Insert` 从来源拿出并在目标落点推开后继。显式 before/after edge Insert 是特例：无论 Alt 都按目标边界插入，但不因这次移动关闭来源空隙（主轨 magnet 独立适用）。中心 `Replace` 仅接受一个来源片段且不支持 group move；确认后单删 target（保留 target 的 link partners），来源落在 target 起点。来源比 target 长时推动 target 后继；来源更短时仅在目标为主轨且 magnet 开启时关闭时长差，否则留下空隙。素材栏新媒体放入同时核对默认放置与其明确的 overwrite 命令。改变邻接关系不会仅因当前转场记录的配对过期而拒绝 move/insert；按提交后的 clips/fades 和兼容轨邻接重新计算有效 transition marker/effect。
- 片段组、显式 link group 和主轨 riders 分别处理。主轨 magnet 决定波纹关闭/修剪；linkage 决定 rider 随动；显式链接伙伴按链接选择同行。复制时不复制自动 main-track riders。Alt 在 pointerdown 已按下才复制；点击的片段未选中时复制该片段及其显式链接伙伴，已选中时复制所选组及其中链接伙伴。仅普通 move 在手势开始后按下/松开 Alt 才动态切换 Place/Insert，不切换复制；pointerdown 已按下 Alt 的 Copy 后续始终按 Place 规划。Alt 在修剪 pointerdown 跳过显式链接伙伴，但不关闭由 main-track magnet 引起的同轨后继 ripple。分别开关时结果仍符合 OpenFilm。
- 跨轨落点检查音频/视觉类型、锁定、片段源边界和同轨冲突，冲突时预览给出原因并且不允许部分落位。OpenFilm 的 transition 由 clip fades + 落点推导：fades 随 clip 移动，marker 由新布局重新计算；transition 不作为独立的落点拒绝条件。
- 吸附目标含时间零、片段两边、播放头和标记，距离为 8 CSS px；参与移动的成员不得互相吸附。相邻浮点/帧取整应保持可见贴齐，不得因此额外打开新轨。
- 缩放 slider、+/- 按钮、zoom reset、fit、Ctrl/Cmd+wheel/pinch 锚点缩放、水平触控板/Shift+wheel 平移、普通垂直滚动传播、缩放最小/最大值都需源代码对照并实测。以连续采样验证锚点时间留在同一屏幕 x、比例及边界与 OpenFilm 一致；Fit 后首个时间和片尾/右侧留白一致；缩放前后标尺、播放头、片段位置同步，无跳变/抖动。timeline duration 因编辑变化时，OpenFilm 用 `zoomForPxPerMs` 保持同一 px/ms；空时间线首次加入 ≤18s 内容时保持原 18s opening view，首次载入更长项目则按默认 relative zoom。Vortex 需覆盖扩展/缩短/清空/空线首次放入/长项目首次载入。基线 fixture 的 28 CSS px/s 仅用于静态视觉比较，不能替代缩放交互验收。
- 当前目标轨、轨道排序、添加/删除/重排行、行高调整、锁定/隐藏/静音/solo、标记/播放头/时间显示、工具选择和右键菜单逐项盘点 OpenFilm 的 timeline 入口。已有 Vortex 能力也必须走同一夹具做结果对照，不能仅凭“存在实现”视为通过。素材栏拖入、时间线复制/剪切/粘贴到播放头与目标轨、选区/框选/全选、常规删除/波纹删除/关闭空隙、roll/slip/slide、速度边、转场/淡入淡出/音量手势都列入源码行为矩阵；源端确有且 Vortex 缺失的行为补齐，或在记录中给出明确的源行为与兼容裁决并经 Design Gate 审核，不得静默缩小范围。

### 转场投影规则

OpenFilm 的转场标记由 `findTransitions` 根据编辑后的 clip fades、`moveIn` 动画、同类轨道关系、交叠/相贴关系、link/fade 状态和匹配 span 的 white-page clip 推导（涵盖 dissolve/crossfade、dip-black、dip-white 与 move）。Vortex 投影必须覆盖这些来源，不能只查 fade/adjacency。`TimelineTransition` 不再作为 OpenFilm-compatible Core/render 转场身份源；有效 pair 来自 final projector。每次 move/insert/overwrite/trim/delete/split/duplicate 后基于最终 layout 重建 pair 和 marker。旧显式 transition 记录仅作为 compatibility extension，增加并固定 `incoming_clip_id`，不得在后续 Patch 中重新解析到另一个后继；其 pair 不再有效时休眠且不得阻止编辑。移走一侧时 marker/effect 随新布局重算，不因旧配对失效拒绝移动；无合格 pair 时旧 transition 不参与渲染、时长和碰撞校验，不能阻止编辑，新布局满足源规则时重算/激活。split 把 outgoing fade/transition anchor 放在右半，把 incoming fade 留在左半；只有重算后的边界满足完整源规则时标记转场，不在新内部切口自动加转场。copy 保留 clip fade/moveIn/white-page 相关属性，根据副本最终布局重建，不能盲目复制旧 transition record。验收同时覆盖两个端点一起移动、只移 outgoing、只移 incoming、split 两端及破坏/恢复邻接，并分别覆盖 fade、moveIn 与 dip-white 条件。
`set_clip_transition_facts` 的 DTO 冻结为 `{op,clip_id,picture_fade_in_us?,picture_fade_out_us?,move_in?,move_out?}`。字段省略表示保留，显式 `null` 或 `0` 清除；`move_in/move_out` 是 `{preset_id,duration_us}` 或 null，preset ID 必须属于 pinned OpenFilm transition/motion preset enum。duration 是非负安全整数微秒，正值不得超过 clip duration；visual fade in+out 总和不得超过 clip duration。`set_audio` 仍是 sound fade 的唯一写操作。`TimelineState` 增加 `active_transitions[]`，每项包括稳定 `transition_id,outgoing_clip_id,incoming_clip_id,kind,start_us,end_us,cut_us,on_clip_id`，可选 `rest_clip_id,white_page_asset_id,incoming_move_preset_id,outgoing_move_preset_id`。`move` 的发现只看 incoming `move_in`（与源一致），outgoing preset 若存在用于渲染其配对半段，不改变配对结果。

Core projector 逐条复现 pinned `findTransitions`：按 tracks 数组顺序及每轨时间顺序枚举；incoming 候选是非-white 且 picture fade-in>0 或 move-in 存在的 clip。outgoing 画面候选先于音频候选，保持源的稳定顺序；每个 outgoing/incoming 最多消费一次。`EPS=1.5ms`，用于独立取整后的重叠长度、淡变长度及切点相贴；`TOUCH_MS=1ms` 仍只用于 OpenFilm 指定的相邻/重叠辅助比较。令 `lap=outgoing.end-incoming.start`：move 要求 picture、`lap>EPS`、incoming 轨位于 outgoing 上方且 `abs(move_in.duration-lap)<=EPS`；跨轨 overlap dissolve/crossfade 要求 `lap>EPS`、incoming fade-in 与 lap 相等、且 outgoing fade-out 与 lap 相等，或 picture outgoing 无 fade-out 且 incoming 在其上方；同轨 touch dip 要求 outgoing fade-out>0 且 `abs(incoming.start-outgoing.end)<=EPS`。dip-white 仅在 picture touch dip 且 system white-page 的 start/end 与推导 span 各相差不超过 EPS 时成立，否则是 dip-black。overlap pair 的 `rest_clip_id` 只在 incoming head 与另轨 clip 同 link、同 kind/source、时间相贴且 source range 连续（speed-adjusted tolerance）时派生。最后移除与同 outgoing/incoming link pair 重复的音频转场，避免画面和 linked sound 重复显示。任何无效 pair dormant；不得做 per-operation projector。

旧 `add_transition/update_transition/remove_transition` 继续接受作为显式 Vortex compatibility effects，但不参与 OpenFilm `active_transitions` 推导。`add_transition` 在 patch 的 pre-state 把 outgoing 与当时匹配的 incoming 固定成一对并持久化；旧记录无法唯一解析时 dormant。update/remove 只作用于其固定 pair。transition marker/renderer 先消费 active source-fact projection，再消费仍相邻且 pair identity 未变的 compatibility effect；旧 effect 不得仅因 outgoing 仍有新后继而迁移过去。compatibility effect 休眠时不参与时长、碰撞或最终文档拒绝。

### 修剪、复制与键盘

- 拖动左/右边遵守 source range、OpenFilm 正速度映射、`MIN_BLOCK_MS=100ms` 最短段、相邻片段 fence 和 main-track ripple；Alt 在修剪开始时不带动显式 link group 伙伴，但若 main-track magnet 开启，同轨后继 ripple 仍按 OpenFilm 执行。速度头按 OpenFilm 两条速度边规则验证。Core、DTO、最终文档校验对所有素材类型采用一致的 100ms 最短片段；既有需要 500ms 的独立媒体任务/数据库约束不变。
- Alt 在开始移动之前按下时复制已选单片/组合；复制完整保留素材引用、源/时间线区间、轨道相对布局、正速度、音频设置及淡变、变换、关键帧、蒙版、抠像、标题/字幕/音频轨属性。被复制集合中同一 link group 至少含两个成员时，副本成员获得新的 link ID；只复制一个成员则副本不链接。自动 main-track riders 不随 Alt 拷贝。Vortex 扩展的 reverse clip 保留为单独回归项，不放入 OpenFilm parity fixture；OpenFilm parity 只比较其正速度范围内的片段。Transition marker/effect 根据复制后的 clips/fades 和邻接重算；仅当复制后的关系可形成源端 transition 时生成有效映射，不以原 transition record 盲拷贝。复制只产生一个原子修订，且一次撤销移除全组。
- 时间线快捷键与上下文菜单的 copy/cut/paste、粘贴到 playhead/target lane、duplicate 均建立逐项矩阵。OpenFilm 复制选择的 blocks；cue 是独立 clipboard item，不因复制视频而自动复制其旁边 cue。粘贴优先指针下轨、其次已选 clip 所在轨、再回退每项的原轨；多轨保留组内轨道/时间差。粘贴时仍存在的源 clip 读最新内容，已删除的源按缓存副本用新 ID 还原。链接只在同次粘贴至少两名原 linked members 时重建新 link。剪切、链接重建和失败撤销行为都比对 OpenFilm；Ctrl/Cmd C/X/V/D 在可编辑文本焦点时遵守桌面文本编辑语义。
- Q/W lead 顺序：传入 `given` 时只在其列表中找首个合格 lead；未传 `given` 时先在已选 blocks 中找；这两种候选都找不到时，再按主轨、目标轨、全部 blocks 顺序回退。`inside` 要求存在 `clipId` 且严格满足 `start + 1ms < playhead < end - 1ms`，locked 跳过，但不按 hidden 过滤。cue stand-in 带合成 `clipId` 且进入 `editModelOf`，所以播放头在未锁定 cue 内时 cue 可直接成为 lead；`ProjectView.edit` 再由 `cueEditOf` 把计划写回对应 VTT。Q 对 cue 保持原始开始和文本，缩短 cue 结束并 ripple 后续内容；W 把 cue 结束修到播放头（受最短时长约束）并 ripple 后续内容。Q 后播放头回到 lead 的原始入点。焦点在可编辑文本/控件时不截获。逐项比较显式 `given` 替代 selection、选中且命中 cue、cue 未命中/锁定时回退、隐藏 cue 仍命中、恰好位于 `start+1ms` / `end-1ms` 与紧邻内部时间、及无任何合格 block。
- 当前主项目具备有效 timebase 时，J/K/L 即使播放头不在片段内也可操作；同方向重复 J/L 依 1×/2×/4× shuttle，反向画面 seek 约 40ms 且不倒放音频。K 停止，按住 K 后按 J/L 逐帧移动。source viewer、文本输入、对话框焦点不截获；素材两端及时间基准按 OpenFilm 映射验收。OpenFilm 不支持 reverse clip playback；reverse clip 的 split/trim 保持独立 Vortex 回归覆盖，不列为对齐行为。
- 开启 skimming 且暂停、select mode、鼠标 pointer 且无 Alt/Meta/Ctrl/Shift modifier、无任何按钮/手势时，移动指针预览片段下方画面。trim/fade/volume/实际 marker/clip-marker/keyframe control、in-hand drag、对话框/菜单/popover、关闭 skimming 或播放时不触发；空白 marker lane 本身不抑制 skimming（marker 行背景 pointer-events 穿透到下方时间线）。松开/离开不会更改 seek/playhead。
- 单拆沿用目标/选区规则；split-all 对 playhead 下全部 unlocked 可拆 blocks 执行一次原子拆分，包含明确被选中的 video/audio/image clip 与独立 caption cue。非 cue clip 拆分由 `clip_ids[]` 给出，字幕由 `caption_ids[]` 给出；locked/未达最短时长的 blocks 在 UI target 解析时跳过，提交操作中显式传入的 locked/无效 ID 则整批拒绝。cue 两半都至少 100ms；文本按 OpenFilm `splitCue`：有 word timestamp 时从第一个不早于切点的 timestamp 分开，否则按 cue 时间比例找 surrogate-safe 字符边界。原 cue ID 留左半，新 ID 给右半，保留 cue style/source metadata。transcript caption 的每个 source segment midpoint 先按其 `source_clip_id` clip 映射到 project time 再归属：正速度为 `timeline_start + round((source_midpoint - source_start) * 1000 / speed_milli)` 微秒；Vortex reverse regression 使用 `timeline_start + round((source_end - source_midpoint) * 1000 / speed_milli)`。映射前裁掉超出 clip source window 的 segment；midpoint 恰等 split time 时归左侧；引用的 source clip/segment 不存在或无法映射时整批拒绝。每个 segment ID 只分配给一个半段；没有 source segments 的一半转为 `origin=user`, `source_clip_id=null`, `source_segment_ids=[]`, `edited=true`，不破坏 Provider 的 segment→caption 唯一映射。若 caption 与同批拆分的 `source_clip_id` 对应，则仍具 transcript source 的半段映射到对应 clip half；user 半段不保留 source link。linked clip right halves 仅在同一 group 至少两个成员同时切开时新建 link group，否则右侧解除链接；左侧保留原 group。正速度映射源区间，图片只拆时间区间。过渡效果跨拆点按 OpenFilm 规则：入点 fade 留左半，出点 fade 留右半，motion/keyframe 时间原点在右半按 cut rebased。若 split-all 同时切开 transition 的 outgoing 与 incoming 两端，outgoing anchor 映射到 outgoing right、incoming fade 留在 incoming left，再用两半的真实布局重算；不再满足源 fade/邻接条件则 transition dormant、无 marker/effect 且不报错，不在内部新切口自动新增转场。
- 目标轨 (target lane) 点击后供无选区拆分/插入快捷操作使用；普通点击空白处、目标轨、跨行框选和多轨组合移动分别验收。
- 若 cue 含 source-media word timestamps，同样必须先经 owning clip 的统一 `sourceToTimelineUs()` 映射到 project time，再选取第一个 mapped timestamp `>= timeline_time_us`；仅当该 timestamp 的文本索引大于 0 时才直接按 timestamp 切，索引为 0 时与找不到 timestamp 一样回退比例文本算法（OpenFilm `splitCue` 条件）。正速度使用 `timeline_start_us + roundHalfUp((word_us-source_start_us)*1000/speed_milli)`，Vortex reverse regression 使用 `timeline_start_us + roundHalfUp((source_end_us-word_us)*1000/speed_milli)`。word timestamp 和 segment midpoint 共用整数 round-half-up 微秒算法；映射超出 source window 的 timestamp 丢弃；timestamp 等于切点且索引大于 0 时该 timestamp tag 和后续文字归右半。user caption 无 source clip 时，word timestamp 按 cue 自身 timeline clock 处理（`caption.start_us + relative_word_us`），不会套用媒体时钟。source segment midpoint 的 metadata 独立按 midpoint 归属，恰等切点时归左。
- 没有 word timestamp 时，cue 文本切分按 OpenFilm `cutIndex`：以 cue 时间比例得到字符目标，优先选最近的空格后边界；没有空格时选最近可用 CJK 字符边界；边界不能落在闭合标点前或 surrogate pair 中。若仍无合法边界，才从文本中点切并确保字符完整。该算法、tie behavior 与 `caption-edits.ts` 的单测逐项对照。
- 键盘-only 矩阵：Tab/Shift+Tab 进入工具栏与具名 clip/track 列表，方向键在 clip/track 项间导航，Enter 聚焦/设定目标轨，Space 选择/取消选择；Mod+A 全选，Mod+C/X/V/D 复制/剪切/粘贴/复制组，Delete/Shift+Delete 普通/波纹删除，Mod+B/Mod+Shift+B 单拆/全拆，Q/W ripple trim start/end，Alt+Left/Right 按项目帧率各移动一帧，Alt+Up/Down 在兼容轨间移动，M/Shift+M/Alt+M 加/下一个/上一个标记，+/- 缩放，Mod+0 reset，Shift+Z fit，Ctrl/Meta+wheel 与触控板缩放/平移；Esc 取消预览且不改文档。每一步记录焦点顺序、控件名称、可用状态、选区/目标轨/时间状态和修订号；可编辑文本、viewer、对话框不截获其原生键盘操作。关闭轨道菜单里的新增/删除/重排/锁定/隐藏/静音/solo 也可用焦点键盘操作。该可访问路径不改变默认对照夹具的视觉布局。

### 显式 Core 增量

设计审查确认 Core 需要明确的批量拆分、复制、媒体 Replace 与转场 source-facts 操作，且这些编辑操作不加入 AI 白名单。拖动由 Desktop 计算完整终态，再经现有 `position_clips` 原子提交。实际已登记的 patch operation、migration 与白名单事实只见 [`docs/STATUS.md`](../STATUS.md) §1；实现前先核对该事实，除非代码确实缺少所需语义，不得重复新增已有操作。若代码变更实际加入或移除操作，须在同一变更更新 STATUS §1。

1. `split_timeline_clips` 接收 `clip_ids[]`、`caption_ids[]` 与 `timeline_time_us`；数组无 per-item 数量上限，但受本 gate 增加的 TimelinePatch raw JSON 4 MiB 硬上限约束，并在一个 revision 内一起处理。ASGI guard 同时检查 Content-Length 与 chunked 实际字节，在 JSON parse / DB patch 之前超限返回 413。视频/音频按 OpenFilm 正速度映射源区间，静态图片只拆时间区间；保留原 ID 给左片，右片生成新 ID。显式列表任一目标无效则整批拒绝。caption/cue 按上节的 100ms、文本与 metadata 规则同一事务拆分；TimelineCaption validator 与所有 Core caption mutation/final-document 最短时长规则统一为 100ms。左侧保留原 link group；同组至少两个成员一起拆时右片组成新的 link group，只拆一个成员则右片为 null。Incoming fade 留左片、outgoing fade 留右片；右半 motion/keyframe 时间原点按 cut rebased。若 transition 的 outgoing clip 是拆分目标，将 outgoing anchor 改到其右半 ID；若 incoming clip 是拆分目标，incoming fade 随左半。两端都拆时两个重映射一起应用，再按新时间/轨道关系重算；不满足 OpenFilm fade/邻接条件的 transition 变 dormant，不渲染、不可见、不阻止 patch，且内部新切口不继承旧 transition。Core `timeline_diff` 的 split detection 覆盖 video/audio/image。
2. `duplicate_timeline_items` 接收 `copies[]`，每项为 clip 或独立 caption/cue、source ID、Desktop 预分配且唯一的新 `copy_id`、最终目标轨/时间和可选 clipboard snapshot。Core 对每个新 ID 做格式/冲突验证。源 ID 仍存在时以 Core 最新文档值复制；源已删除时仅用剪贴板 snapshot 恢复并由 Core 重新验证媒体/字幕引用；禁止信任 snapshot 覆盖仍存在的源。多轨/多类型 items 的时间与轨道相对偏移由调用方保留。数组无 per-item 数量上限，但受同一 4 MiB raw JSON guard 限制，同次操作原子成功/拒绝。保留 clip 的源区间、speed/reverse、gain/fades、transform/keyframes/mask/keying 及 cue 的 text/style/time。caption clone 一律转为独立 `origin=user`, `source_clip_id=null`, `source_segment_ids=[]`, `edited=true`，即使原 caption 来自 transcript，以免 Provider segment→caption 唯一映射冲突；clipboard snapshot 的 parent clip 已删除也依此规则恢复，不留下悬空引用。自动 main-track riders 不复制。同一 link group 同批至少两个成员时 clone 使用新 link ID；单成员 clone 不链接。Alt-copy 始终按 Place：指针下具体 clip 的 before/after/replace zone 和单行内 above/below edge 不参与命中，但指针越过整组轨道外侧仍按新轨道目标处理；兼容轨道目标与普通 Place 冲突开轨仍生效。指针下主轨且 main-track magnet 开启时，复制源保持不动，发往主轨的 copies 按 hand 下 insert point end-to-end 插入并推动后继，非主轨 copies 仍按 Place 落位/冲突开轨，riders 不复制。Desktop 预分配 copy_id，使同一 Patch 后续 `position_clips` 能引用新片段，并将 ripple 终态与 copies 一起提交。Transition marker/effect 从复制后的 clip/fade/邻接重算；只在复制后 clips 符合 OpenFilm 派生规则时出现有效 transition。检查源/目标锁定、轨类型、区间和最终文档约束，一次 revision/undo 原子成功或完全无修改拒绝。

3. `position_clips` 承载 Desktop drag planner 计算的完整终态，`placements[]` 不再有 100 项上限；唯一大小限制是整个 TimelinePatch raw JSON 4 MiB body guard。保留 Patch 的 100 operations 上限。Core 对本操作文档中任何被移动的显式 link group 要求完整 placement：所有未在同 Patch 删除的成员都必须在 placements 中，且拥有相同 timeline delta；Core 检查各成员 source/target 锁、目标轨类型和最终布局。目标先被同 Patch 删除时从完整性集合排除；删除后只剩一名成员的 link_group_id 在 final normalization 清除。普通 clip move 没有 independent link 模式；显式链接伙伴永远同行。Main-track magnet 和 rider linkage 是独立开关：Desktop planner 按它们算出应收拢的源间隙与 rider placements，显式传入完整 placement 集，Core 不从时间重叠猜 rider。一次拖动只生成一个 Patch/revision；超过 4 MiB 在 JSON parse/DB 前 413 拒绝。此限制同样覆盖超大 ripple 的 `position_clips`，并加入 B1 Content-Length 与 chunked 边界用例。
4. `replace_clip_source` 用于素材库/系统文件的 Replace，与时间线 clip-to-clip Replace 不同。输入目标 `clip_id` 和已导入项目的 `asset_id`；目标 clip ID、track、timeline start、layout 与可复用外观属性保留。新源从 0 开始播放。视觉目标接收 video/image；音频目标接收 audio 或任意 video，不要求 video 有音轨，也不需要额外 `as_audio` 标志。video 被音频目标引用时保留音频 clip 语义；有音轨则使用它，无音轨则生成等时长静音段，与 OpenFilm `canReplace` 对任意 video 的接纳行为一致。为兑现这项可观察行为，Core `insert_asset_clip` 的静音 video-as-audio 拒绝仅在通用拖入路径保留；Replace 操作显式允许它，TimelineDocument 最终 validator 必须接受 video-backed audio clip（`audio.enabled=true`），RenderPlanCompiler 不得再因缺失音轨拒绝；FFmpeg 已有的 `anullsrc` 路径负责产出静音。TimelineCanvas 不请求该素材的 waveform，显示空波形带但仍可编辑音量/淡变；实时播放、authoritative preview 与 final export 都应静音且成功。若 `resolution="original"`，只从视觉 clips 计算源分辨率；仅用于 audio clip 的 video source 不得抬高输出分辨率或增加导出成本。图片/still 保持目标时长并清除不适用的 speed/audio；有限 video/audio 保持目标 speed 和目标时长上限，来源不足时截短 clip 并在预览反馈差值，源足够长则保持原时长。为了保留超过 30s 的目标片段时长，Vortex 取消静态 image clip 的 30s 上限，image 时长改为最短 100ms、最长 `Number.MAX_SAFE_INTEGER` 微秒；该规则同步 TimelineDocument validator、asset insert、`set_image_duration` 与 Core 最终校验。G2 必须覆盖 >30s 的 image Replace 仍保持原 timeline end。若有限来源截短后短于 Vortex 100ms 最短 clip，Core 拒绝整个 Patch。OpenFilm 对未知有限源时长按目标所需长度规划，Vortex 也必须保留该 Replace 时长与编辑可用性：asset duration 缺失时以目标时长作为暂定源区间，不以“元数据未探测”拒绝 Replace；解码器遇到真实 EOF 时通过统一媒体边界反馈截短/缺帧，且撤销、预览与导出须保持同一最终时长语义。G2/F1 覆盖 duration 已知/未知及真实 EOF 两种情况。保留可复用的 layout/transform/keyframes/mask/keying/audio gain/fades/link group；源不支持的音频/视频效果按新 source kind 清理。新 asset 必须属于同 project 且 ready；同一 asset、锁定目标/轨、无法满足 100ms 下限或最终时间线重叠都整 Patch 拒绝。Replace 不自动 ripple 后继（与 OpenFilm 改写同一 clip 属性一致），但 transition projection 在最终布局后更新。

**HTML page 功能（P235-R4，必须纳入本工作包）：** OpenFilm `canReplace` 接受 `kind: page` 或 `.html/.htm`，有限 page 按 1× 计算源长度，endless page 保持目标时长；替换清除 page 的 speed/volume 与页面元素级 keyed overrides，但保留 clip 自身 fades。page 是执行 `window.film` 的 HTML 页面，不是静态图片。Vortex 必须实现可导入/引用、时间线拖入与 Replace、有限/无限时长、可见页面帧、时间线编辑、撤销/重做、实时预览、authoritative preview 与 final export 的一致行为。页面不能在主应用权限上下文中执行：Design Gate 必须冻结独立内容 origin/进程、sandbox/context isolation、禁用 Node 与特权 preload、项目资源根白名单、导航/弹窗/下载与网络策略、最小 `window.film` 帧时钟合同，以及预览/导出使用同一确定性帧源的实现；不能只用静态 poster 或把 HTML 转成静态图片冒充页面播放。G2/F1 必须覆盖有限和无限 page、来源属性清理、隔离越权负例、页面帧时间推进、预览/权威渲染/成片帧一致与缓存失效。页面端到端合同通过独立安全复核前，不开始执行用户 HTML；该安全门不构成功能验收通过。
page import 的 bundle root 是用户在“导入页面包”中明确选定的目录，另选一个目录内 `.html/.htm` entrypoint；从文件拖入时该文件的 parent folder 作为候选 root，先显示即将纳入的文件数/字节数，再作为一个导入动作提交。导入器递归复制 root 中所有 regular files（包含动态构造的相对路径依赖），按规范化相对路径+每个文件 SHA-256 生成不可变 bundle hash；symlink/reparse point、绝对路径、`..` 越界、重复规范化路径和超限 bundle 整包拒绝，不产生 asset。页面只通过 `app-page://<asset>/<relative-path>` 读取同 bundle 文件，默认无网络；跨域/公网/localhost 请求 fail-closed，用户须把资源纳入 bundle 才可用。entrypoint 相对依赖变化会改变 bundle hash 并失效缓存。system white-page 是 Core 内置、用户不可替换的 `transition_white` role。

`window.film` v1 为 `{duration?: number, ready?: Promise<void>|(()=>Promise<void>), frame(tSeconds):void|Promise<void>}`；有限 duration 以秒表示，缺省/非正时长表示 endless。页面 load 后等待 `ready` 与 `document.fonts.ready`（最多 60s）；每次 seek 调 `frame(t)`，最多等待 15s，再等两个 compositor RAF 后捕获。宿主使用 pinned OpenFilm `FILM_CLOCK` 语义：固定 epoch 的 `Date/Date.now`、`performance.now=t`、RAF timestamp=t、`Math.random` 按 frame time 可复现，并把 CSS/Web Animations currentTime 设置到同一时间；无 wall-clock 计时推进。用户脚本只能靠 `frame(t)` 或这些冻结时钟驱动画面。

进程/IPС所有权冻结为：Electron main 的 `PageFrameBroker` 是唯一入口并持有 job nonce；broker 为每个 bundle 启动独立 sandbox Electron utility renderer/Chromium session，使用 OS ACL 私有 named pipe 传递 `{bundle_hash,frame_times,size,nonce}`，utility 只回 PNG 帧与依赖读取记录。utility webContents 开 `sandbox/contextIsolation/webSecurity`、nodeIntegration 关闭、无 preload、默认断网、`app-page://` protocol allowlist、deny navigation/window.open/download；每帧/打开均有超时及取消，超时销毁该 page session。Core 不读 HTML、不启动浏览器，只接收 broker 生成的只读、job-scoped frame manifest/cache token 并将这些帧交给 FFmpeg。Timeline live preview 与 authoritative preview/export 都通过同一个 Broker、Chromium build、bundle snapshot、时间映射及缓存键；cache key 还含 overrides、frame time、尺寸和 renderer version。安全 reviewer 可在不削弱此边界的前提下收紧资源预算。

**Page DTO 与迁移身份补充冻结：** `TimelineClip.asset_kind` 扩展为 `video|image|audio|page`；`page` 只接受同 project 的 `Asset.kind=page`，源窗是非负安全整数微秒且 `source_end_us > source_start_us`，时间线跨度必须等于源跨度（`speed_milli=1000`、`reverse_playback` 不得启用），不请求 waveform/音频解码且 `audio.enabled=false`、音频 fades 不得设置。有限 page 新建/Replace 从 0 开始并将窗口取为 `[0,min(targetDuration,asset.duration_us))`；endless page 的窗口为 `[0,targetDuration)`。用户之后延长有限 page clip 时允许源窗越过 `duration_us`，帧服务按 OpenFilm 规则 clamp 到最后一帧；该 hold-last-frame 行为不改变有限 page Replace 依据真实源长度截短的规则。`page_overrides[]` 仅允许 page clip，元素必须有非空 `at` CSS selector（最多 512 字符）；允许 OpenFilm 字段 `n`（正整数）、`t`（两个有限数）、`s`（正数或两个正数）、`r`（有限数）、`style`（最多 24 项，合法 CSS/custom-property 名称，值为最多 2000 字符文本或有限数字）、`lock:true`、`text`（最多 2000 字符）、`split={by:'char'|'word'|'line',animation:非空且最多200字符,stagger:0..10,start?:非负有限数,order?:'forward'|'reverse'|'center'|'random'}`；未知键或错误 kind 一律在 Contract 和 Core validator 拒绝，数组总大小受 4 MiB patch body guard 约束。所有 source Replace 清空 `page_overrides[]`，保留 clip-level picture fade/move facts；page overrides 作为独立渲染输入在所有帧上按 OpenFilm 顺序应用。Bundle identity 定义为 SHA-256 of canonical JSON `{entrypoint: normalizedRelativePath, files: [{path: normalizedRelativePath, sha256}, ...]}`，文件记录按路径 ordinal 排序；缓存键直接包含此 bundle hash，确保不同 entrypoint 即使共享目录也不会碰撞。旧 transition migration 45 仅能从不可变历史创建修订/操作快照唯一还原原 incoming clip 时回填 `incoming_clip_id`；禁止从迁移时当前相邻 clip 推断。无该可信历史的旧记录写 nullable `incoming_clip_id=null` 并持续 dormant；DB migration、旧文档读取与 projector 采用同一规则，永不按新后继重新绑定。

**转场来源事实与终态投影（P235-R3，必须纳入本工作包）：** 独立复核确认现有 `{after_clip_id, kind, duration_us}` 记录无法区分原 incoming/outgoing pair，也不能重建 OpenFilm 的 fade、move-in 或 dip-white 条件。Design Gate 必须定义受校验且随片段复制/拆分的源事实（picture/sound fades、move-in preset 与时长、white-page 语义）及明确的 outgoing/incoming clip identity；整批 TimelinePatch 操作完成后按最终布局只投影一次。有效 pair 供时间线、预览、IR/FFmpeg 共用；不符合布局条件的 pair 休眠且不参与渲染、时长、碰撞和编辑拒绝，原始 clip facts 保留以便条件恢复后重新激活。移动一端/两端、Insert、Replace、split、duplicate、破坏与恢复邻接都必须遵循 OpenFilm 的 `findTransitions` 规则；`_overwrite_track_range` 不能再因可在终态重算的旧配对拒绝编辑。投影必须在孤立 link 清理后、最终校验前执行，不得逐 operation 投影。

复合移动 Patch 顺序固定为：先 `add_track`/`move_track` 创建并排好所有目标行；Alt-copy 的 `duplicate_timeline_items` 接收 Desktop 预分配的新 clip/caption IDs 与最终落点，使后续 ripple placements 可引用这些 ID；再 `remove_clip(ignore_link:true)` 删除已确认且允许单独替换的 target；随后用单个 `position_clips` 写入所有已有素材及 Insert/rider ripple 的终态。若无位置变化可省略该 op。Replace target 不纳入来源组的 `position_clips` 成员校验；target 长度差依上述源语义先规划对后续片段的 push/close。全部操作只应用于事务内文档副本；操作组完成后先做 link orphan normalization，再从最终 clips/fades/moveIn/white-page facts 重投影有效 transition，最后统一执行文档校验和 revision 写入。任一锁、轨类型、链接完整性、时间区间、同轨冲突或转场重投影失败都拒绝整个 Patch，不产生 revision。Transition projection 不得在每条中间操作后运行，否则合法的 swap/Replace/Insert 会受中间重叠阻断。

`TimelineDocument.schema_version` 保持 v1，但 `TimelinePatchOperation` 是有意扩展的 contract：更新 `packages/contracts/src/index.ts` 类型与 runtime validator、Core `PATCH_OPERATIONS`/dispatcher/operation validator/normalizer/final document validator、desktop request 与 patch builder、类型/状态守卫测试。DTO 形状冻结如下：`split_timeline_clips` 接受 `{clip_ids, caption_ids, timeline_time_us}`；`duplicate_timeline_items` 接受 `copies[]`，每项含 `item_kind, source_id, copy_id, timeline_start_us`，clip 项还含 `track_id`，caption 项不含；`snapshot` 仅在原来源已删除时提供完整 clip/caption 缓存，来源仍存在时 Core 必须拷贝最新文档对象。`replace_clip_source` 接受 `{clip_id, ## 设计门冻结决议（2026-11-23）

以下决议冻结实现架构，不代表 P235 验收通过。完整 parity 仍要等 V1–R1 证据及 acceptance cross-check 全部过关。

1. **UI 度量与缩放：** 保留当前 Canvas 绘制，但采用 OpenFilm 的度量：展开轨头 108+24=132px、收起 28px、空编辑 12px；封面 tile 固定 38×38px 并在 51px rail 内居中；toolbar 34px、ruler 20px、zoom slider 78px（thumb/轨道颜色与 hover/disabled 状态逐项取 OpenFilm token）、row gap 2px、主轨 68px、普通视觉轨 52px、overlay 28px、音轨 42px、字幕轨 24px，标准行组上下至少 10px。支持 OpenFilm 的轨高档位和 28–160px resize clamp。初始缩放比较包含清除 profile 覆盖后的 60s 与 155.5s 项目，记录初始 px/s、fit 后片尾留白与首个可见时间。缩放保存为相对项目长度的 zoom（默认 0.8、每步 ×1.6、最窄视图 1s、最宽为项目时长的 4× 且至少 30s），像素/秒由视口宽与当前 zoom 推导；空项目显示 18s。Fit、slider、按钮、wheel/pinch、横向平移与滚动边界都使用该模型。ruler frame positions 使用 `fps_num/fps_den` 有理数，禁止先把 29.97 round 成 30。
2. **拖动终态：** 多轨组合严格按指针目标 lane 相对 lead lane 的同一行偏移计算每个成员目标；类型/锁/行越界或组内冲突则整组拒绝；占用冲突按目标轨各开一条并维持组行次序。组合不命中单片 before/after/Replace edge；Alt-copy 忽略单行 clip/band edge，但越过整组最上/最下行仍开轨。主轨 magnet 的 rider 在目标 lane 撞上静止素材时，按 OpenFilm settle 先找最近可用同类非主轨，平局向视觉上方（音频向下），没有空轨时开新轨；链接成员时间偏移保持一致。同轨 V1 多片组选中且 main magnet 开启时按时间顺序连续 packing，并移动 downstream 与 linked riders；V1 Alt-copy 保留原组、按指针 cut 插入副本、链接伙伴按相同 delta 对齐并获得新 link group，整个动作一个 revision。磁吸 planner 不得按 clip/placement 数量做硬 100 限额；仅保留每 patch 100 operations 和整体 4 MiB raw body 限制，必须覆盖 >100 个实际移动片段的原子操作。单片 Replace 只有“新源更长”总会推后继；“新源更短”仅当 target 在 V1 且主轨 magnet 开启时回收空隙。拖拽新增行按最终 tracks 顺序一次规划和提交，动态轨 ID 从该类型现有最大序号递增。
3. **转场合同：** clip 保存可校验的源事实：`picture_fade_in_us`、`picture_fade_out_us`、`move_in={preset_id,duration_us}`、`move_out={preset_id,duration_us}`；音频淡变沿用 `audio.fade_in_us/fade_out_us`。dip-white 只来自 Core 管理的系统 `transition_white` page role，不能由用户提供布尔值伪造。新增 `set_clip_transition_facts` TimelinePatch op（实现后 `patch_operations=43`，AI whitelist 不变，TimelineDocument v1 使用可选增量字段）。`TimelineTransition` 投影最少给出 `transition_id,outgoing_clip_id,incoming_clip_id,kind,cut_us,start_us,end_us`，按需带 `rest_clip_id,white_page_asset_id,incoming_move_preset_id,outgoing_move_preset_id`。旧显式 transition record 加入 nullable `incoming_clip_id` identity；migration 45 只从不可变历史创建修订/操作快照唯一还原原 incoming 时回填，禁止用当前邻接推断；否则保留 null/dormant。读取器、migration 与 projector 对 null identity 一致处理，不能绑定未来后继。一个纯 Core projector 在整批 patch 与 link orphan normalization 完成后运行一次；active projection 供时间线 marker、实时预览、authoritative preview、RenderPlan/FFmpeg 与冲突验证共用。无效 pair dormant，不删除 source facts、不渲染、不阻止编辑；新布局满足源规则时可重新激活。Core 与 Desktop 预览 projector 必须共享同一 fixtures 和规则。
4. **HTML page 合同和隔离：** 数据库 migration 45 新增 `Asset.kind=page` 与不可变 bundle manifest（规范化 entrypoint、依赖 SHA-256、有限 `duration_us` 或 `endless=true`、画布尺寸、系统 asset role）；bundle hash 包含规范化 entrypoint 和排序后的全部依赖路径/SHA-256。Timeline clip 的 page 源窗口/validator 与元素 `page_overrides[]` DTO、Replace 清理规则按 §2 的 Page DTO 合同；有限 page 按 1× 映射，endless page 按落点目标长度。导入器只复制项目内 bundle，拒绝绝对路径、目录穿越、越出 bundle 资源与 symlink。`window.film` v1 合同为可选有限 `duration`、`ready`、`frame(t)`；独立 sandbox Electron renderer 采用 `sandbox/contextIsolation/webSecurity`、Node/特权 preload 关闭、默认断网、仅 `app-page://` bundle 源可读、阻止导航/弹窗/下载、帧超时与取消。唯一最小桥接由宿主控制时间；同一个 hash 固定的 Chromium frame service 同时供实时预览、authoritative preview 与 export，输出带项目 timebase 的帧给 FFmpeg。页面缓存键含 bundle hash（包含 entrypoint）、page overrides、frame time、尺寸和 renderer version。独立安全复核通过前禁止执行用户 HTML；此安全门不会代替功能验收。
5. **Gate 状态：** 本决议由 Architect 汇总 Core/Contracts、Desktop 与 independent review 意见冻结；P235 可以继续实现。任何上面列出的实现缺口或失败证据都继续留在 STATUS §4，不得把设计决议、unit-test 数或 planner-only benchmark 写成整体通过。Acceptance cross-check 必须逐项覆盖 V1–R1，包含结果、链接证据和仍存限制。

## 3. 性能对照

保留 P234 合成滚轮测试作为窄历史样本，不将其计入此门。性能同时跑 renderer harness 同 Chrome `157.0.8103.51` 对照与原生产品对照（OpenFilm Electron 44.9.3 / Vortex 36.2.1）；同一 OS/驱动/显示刷新率、内存相同媒体和 TimelineDocument 负载。视觉/手势基线用 30000/1001fps、60s 项目、四轨八片段；zoom 初始态另测 60s 与 155.5s 项目。功能 fixture 加 A2；完整 renderer 压力负载用 16 条轨道、1000 段、20 分钟时间线；纯 planner 压力负载额外覆盖 10k clips 的同轨 Insert、V1 group reorder 与 Alt-copy Insert，并包含 >100 个实际移动片段。**热稳态**每个 harness/native 进程空转 30 秒后，以实际被测媒体预热缩略图/波形/帧池，再采集各场景 1000 个有效样本；三轮独立进程，样本期间不清缓存，并逐次报告命中率。**应用冷首次使用**对 harness 和 native 的抽帧/波形/skimming/scrub 场景分别做 30 次独立 fresh profile/process：应用运行时空转 30 秒但不加载/触碰测试媒体，然后只测一次首次媒体访问；报告 p50/p95（N=30，不报告不可靠的 p99）。应用 disk/memory/profile caches 每轮均为空。Windows 文件页缓存、GPU/驱动缓存无法保证清除，统一标为 warm/uncontrolled 并在双端成对比较。Zoom、move ghost、planner 不依赖媒体 cache，只测热稳态。报告 OS/驱动、Chrome/Electron/Chromium 完整 runtime build、显示刷新率、DPR、媒体字节、源帧数、缓存状态、采集数和每轮原始样本。

分别采集拖动指针到 ghost、缩放输入到锚点绘制、悬停到 skimming 帧更新、标尺 scrub 到预览帧、平移/滚动到绘制、请求到 patch revision 的 p50/p95/p99，画面呈现 FPS/丢帧率、planner/draw 用时、rAF 合并/跳过次数、抽帧/波形缓存命中率和内存峰值。renderer harness 在固定 Chrome `157.0.8103.51` 上对双端都用 CDP `Page.startScreencast` 记录 compositor 实际交付帧；在截图帧中检测带唯一颜色/坐标的 ghost/playhead/zoom anchor，首个包含期望变化的帧时间减去输入事件时间为 input→compositor-feedback。此值不是显示器面板 photon latency。native app 再分别通过其实际 Electron renderer 的 CDP 录制并记录 Electron/Chromium 完整版本。播放另用逐帧唯一编号的测试视频，按 capture 中可见帧号计算实际呈现 FPS/掉帧；每轮至少连续采集 60 秒（不少于 1000 个预期视频帧），三轮共至少 180 秒。不得用合成输入后等两次 rAF 或仅记录 Canvas draw 调用代替呈现测量。

另设可审计的 **audio-only video 不解码画面**场景：时间线上保留一个 1080p 视觉主片段，再将 4K 和 8K video 分别 Replace 到音频目标；每个分辨率同时测有音轨与无音轨（静音占位）两种素材。两端按同一画面/音轨区间运行 60 秒播放和一次 `resolution="original"` 预览/导出。RenderPlan/IR input 保留底层 `asset_kind`，增加 `video_required` 与 `audio_required` stream-usage 标记；前者表示存在可见 video clip 消费者，后者表示存在音频 clip/启用的内嵌音频消费者且源确有音轨。两者必须按 asset 汇总，支持同一 asset 同时被视觉和音频消费者使用。`has_audio` 继续仅表达源流可用性：video-backed audio-only 有音轨时为 `(video_required=false,audio_required=true,has_audio=true)`，无音轨时为 `(false,false,false)`；与普通音频文件相同，使用源票据只解音频。静音占位不能打开源媒体解码。IR 对 `video_required=false` 的底层 video 不读取/要求视频 geometry/HDR，也不得把它投影到任何视觉 segment/layer。Desktop sourceResolver、代理/缩略图请求、compositor 输入、video decoder rig、输入池与 decode-budget 都按 `video_required` 过滤；audio segment 仍用原始同 asset 音频票据，proxy URL 只能供视觉 decoder 使用，不得替换共享 asset 的音频源票据。当前 FFmpeg 每个 timeline segment 有独立 `-i`：仅底层 source family 为 video 且该 segment 的 timeline `asset_kind="audio"` 时，在该 audio-role `-i` 前加 input-side `-vn`；同一 asset 的视觉 segment 有自己的 `-i`，保留 `:v` 解码及视觉映射。如果未来实现共享同一 FFmpeg input，则必须按角色拆成 audio `-vn` 与 visual 正常映射的两个输入。无音轨 audio-role segment 继续由 `anullsrc` 静音，不能打开源媒体解码。IR 和 audio-role FFmpeg stream mapping/filter graph 不引用该输入的 `:v` stream。FFmpeg 导出用同 source/config 的 instrumented build 按 input/stream 记录 `AVCodecContext.frame_num` 或等价 decoder-return 帧计数，只作零解码证据；正式 CPU、内存和 latency 性能采样必须另用未插桩发布 binary，使用相同命令和素材，插桩日志不得进入性能数字。播放/实时预览按 input_id 计数 Desktop decoder `decode()` 输入提交数和 decoder output callback 数，并记录视觉 rig、source resolve、proxy/thumbnail/waveform 请求；只测 output/presented frame 不足以证明没有解码。若预览选择 Core FFmpeg 解码后端，也须记录请求数和 decoder-return 帧数。期望 audio-only input 的视频 rig/source resolve/proxy/decode submission/decoded frame/thumbnail/waveform 均为 0，1080p 视觉输入有非零解码；同一 4K/8K asset 同时有视觉和音频消费者时只因视觉消费者创建 rig，移除视觉消费者后这些视频计数归零。`ffprobe -count_frames`、成片帧数、`-progress frame` 或单看 filter graph 都不算输入视觉解码计数证据。成片帧数只由 1080p 主片段帧率/时长决定。三轮配对收集 wall time、CPU time、峰值 working set、output dimensions、各层实际解码帧数，并保留命令、filter graph、计数器日志和原始 CSV；Vortex 在该场景的视觉解码数须为 0，CPU/内存和 latency 不高于 OpenFilm 同样的 video-as-sound 源，且新增 video-as-audio 相较等长 audio asset 不得触发额外视觉解码或尺寸上升。仅证明输出分辨率不变不足以通过 P1。

分位数采用 nearest-rank：排序后第 `ceil(p×N)` 个样本。热稳态每轮分别计算 p50/p95/p99，跨三轮对这三个分位数各自取中位数；每场景以 Vortex 的三项中位数逐项不高于 OpenFilm 为相对性能通过；10k clips planner 热稳态 p95 还必须 <16ms，避免两端同时卡顿时相对比较被误判通过。冷首次使用 N=30 分别报告/比较 p50、p95；Vortex 两项都不得高于 OpenFilm，同一对运行若 OS/GPU cache 状态不一致则作废重跑。播放不使用冷首次媒体访问数字；三轮每轮连续 capture 至少60秒（≥1000 个 expected frames），presented-FPS/丢帧率各自先取 run-level，再取跨轮中位数，要求 FPS 不低、丢帧率不高于 OpenFilm。原始逐样本 CSV、配对运行顺序与异常都保留；性能不可见或两端数据/状态未匹配的运行判无效并重跑。

## 5. 协作与状态边界

P235 在 Design Gate 明确通过后才进入实现。最终关门前，实施记录必须含以上 V1–R1 每项的明确 outcome、可打开的证据与限制；失败项保持开放并回 STATUS，不得用合计测试通过数或“源码已核对”代替。
