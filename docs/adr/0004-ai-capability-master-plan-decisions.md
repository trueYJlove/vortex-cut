# ADR-0004：AI 能力总纲的九项架构裁决

- 状态：已批准
- 日期：2026-09-24
- 记录人：LiuWei（架构师），基于 2026-09-24 方向讨论与代码级走读
- 决策人：用户（产品负责人）于 2026-09-24 批准全部九项，采纳建议方案
- 关联：ADR-0003（AI 方向与隐私硬承诺，D1–D6 不变）、`docs/design/AI_CAPABILITY_MASTER_PLAN.md`（本 ADR 为其 §14 决策登记表的固化）
- 执行：W0.3 由 ZhangSan（Core）实施；W1.4/W2.3 依赖本 ADR 的 D1、D2、D7

## 背景

`docs/design/AI_CAPABILITY_MASTER_PLAN.md` §14 登记了九项需用户裁决的架构决策。这些决策
共同约束 Wave 0–4 的全部工作包，且其中多项**改变既有行为或数据模型**，不能由实施方自行决定。
用户于 2026-09-24 批准全部九项，均采纳总纲建议方案。本 ADR 将其固化为可引用的门禁依据。

裁决前的事实基线（2026-09-24，HEAD `2f52454`，分支 `ai/stability-polish`，迁移 v22）：

- 全仓库无声画链接概念（grep 无 `linked`/`link_group`/`group_id`）；
- V1 为唯一权威视觉轨，非 V1 视频轨按画中画 overlay 处理（`rendering/ffmpeg.py:168`）；
- 转场仅作用于 V1 相邻片段（`timeline.py:1686`），关键帧仅允许 V1（`rendering/ir.py:115`）；
- 全 core 无 beat/diarization 实现；
- `candidate_source: auto` 语义为"有 ready 转录用转录、否则 CV 场景段"（CV 仅兜底）；
- CV 分析性能门未达标（dance 1080p50 实测 19.5s/分钟源，门 ≤10s），根因已定位为
  `select` 滤镜前的全量解码，`-skip_frame nokey` 实测 6.4 倍加速但长 GOP 采样退化。

## 决策

### D1 · 声画链接语义：新建 A/V 对默认链接，联动 trim/move/remove，提供显式解除联动

**内容**：时间线文档新增链接组字段（**文档 schema 增量，非 SQL 迁移**——时间线文档以 JSON 存于
revision）。同一素材的画面段与音频段默认进入同一链接组，`trim_clip` / `move_clip` / `remove_clip`
对链接组成员**联动生效**；提供显式"解除联动"操作。对齐剪映/Resolve 的"联动"默认语义。

**理由**：剪映与 Resolve 均以"联动"为默认并提供显式解除，这是用户已形成的操作直觉；
若默认不链接，L/J cut 与多机位产出的片段在后续手动微调时会散架，"AI 出底稿 + 用户微调"
的产品形态（ADR-0003 D5）不成立。

**后果**：
- 这是**第一个改变既有 op 行为的文档增量**，必须补"旧文档（无链接字段）行为逐字节不变"的强断言；
- W0.3 交付面包含 Desktop 联动开关；
- 阻塞 W1.4（L/J cut）与 W2.3（多机位切换）。

### D2 · 多机位表达：V1 展平 + 机位映射元数据（可重算）

**内容**：多机位不引入"角度组 + 选择轨"新模型。切换决策**展平为 V1 上的切点序列**；
同时把机位映射元数据（各机位时间偏移、切换点对应机位、同步数据引用）落盘，
使"换机位"= 用同一同步数据重算规划，而非手工重剪。

**理由**：受 ADR-0004 前置约束——V1 是唯一权威视觉轨，非 V1 视频轨为 overlay 语义；
且转场仅作用于 V1 相邻片段、关键帧仅允许 V1。若用 V2/V3 存机位并切换，多机位产物将
**失去转场与关键帧能力**，且与 IR 的 overlay 语义冲突。映射元数据在不引入新模型的前提下
拿回大部分可逆性，是成本与能力的最优折中。

**后果**：W2.3 产出必须全部落在 V1；元数据表随 W2.1 的同步偏移表一并设计。

### D3 · 说话人分离选型：先做可行性 spike，据真实数据裁决，不预设方案

**内容**：不预设重方案（pyannote 级）/ 轻方案（声纹聚类 + 能量主导）/ 折中方案
（whisper 词级 + 音频特征聚类）。**先立项 spike**，产出真实素材上的精度、内存占用、
耗时数据后，再单独裁决选型与是否立项。

**理由**：这是全方案中成本最高、不确定性最大的一项，且三种方案存在明确的精度/资源
二选一权衡，在没有真实数据前任何选择都是猜测。多机位不阻塞 Wave 1/3，具备先 spike 的条件。

**后果**：W2.2 拆为"spike 单"与"立项单"两步；spike 未通过则多机位线（W2.1/W2.3）冻结，
不影响其余 Wave。

### D4 · Layer 1（本地 VLM）：继续搁置

**内容**：维持 ADR-0003 D3 原判，不立项。待 W3.1（本地语义索引）落地并取得真实数据后，
结合用户硬件分布再议。

**理由**：ADR-0003 已裁决"待真实用户硬件分布数据后再决策是否立项"；该前置数据至今不存在。
在缺少硬件分布数据时立项，等于以猜测替代证据。

### D5 · 语义索引模型选型：本地 CLIP 级先行，Layer 2 作为增强

**内容**：W3.1 的素材池语义检索采用**本地轻量 embedding 模型**（经 `model_registry` 受信接入，
体积上限 ≤50MB 级）；云端关键帧理解（W3.3）作为可选增强，不替代本地路径。

**理由**：守住 ADR-0003 D4/I6"本地自立"——从不开启云端的用户也必须得到完整的语义检索体验。
这是本产品相对云优先架构的结构性差异，不能在第一项语义能力上就让步。

**后果**：W3.1 的验收含"本地路径零 egress 断言"与模型体积门；
W3.3 成为纯粹的增强项而非依赖项。

### D6 · 采样密度与长 GOP 空洞：默认自适应 + 高级用户可调

**内容**：默认采用 `-skip_frame nokey`（只解 I 帧）以获得达标性能，**并对长 GOP 素材自动
回退全量解码**（检测到 GOP 超阈值时）；同时把采样密度开放为高级用户可调参数。

**理由**：`-skip_frame nokey` 已实测 6.4 倍加速且输出逐字节一致，但代价是长 GOP 素材
（lichun 有 8.3s GOP）的"≥1s 兜底采样"失效（167 帧→30 帧），8s 空洞内的快速运动不可见。
纯默认方案会静默降低这类素材的信号质量；纯可调方案则把达标责任推给用户。两者结合：
默认路径保证性能门达标且对长 GOP 自动补偿，可调路径保留专业用户的控制权。

**后果**：W0.2 交付面包含自适应策略 + 两档性能门校准 + 参数暴露；
`algorithm_version` 需递增，旧信号行标记 stale（不做原地重算）。

### D7 · 新 op 白名单准入：`split_edit` 等语法层 op 准入

**内容**：剪辑语法层产出的语义化 op（首项为 `split_edit`，后续 `beat_sync` /
`multicam_switch` 视实施裁决）**进 AI 白名单**，走"白名单 + `TIMELINE_PATCH_OPERATIONS_SCHEMA`
oneOf + `_PATCH_FIELDS`"三处同步准入。

**理由**：`insert_asset_clip` 作为结构性 op 被排除在 AI 白名单外，导致 AI **当前无法构造
L/J cut**。若维持排除，E3（L/J cut）对 AI 永久不可用，只能人工操作——这与"AI 出 80% 底稿"
的产品形态直接冲突。语义化 op 比让模型拼多个底层 op 更可控：一次表达完整意图，
校验面收敛，失败模式清晰。

**后果**：扩大 AI 误操作面，须以沙盒用例逐 op 覆盖（既有纪律）；
三处同步一致性由测试钉死（`test_provider_operations_consistency`）。

### D8 · 时间线文档 schema 版本策略：维持可选字段缺省语义，链接字段补强断言

**内容**：不引入显式文档级 `schema_version`，维持"新可选字段缺省即旧语义"的既有策略。
但针对 D1 引入的链接组字段（**首个改变既有 op 行为的增量**），必须补"旧文档零行为变化"
的强断言与逐 op 回归矩阵。

**理由**：仓库既有惯例（`speed_milli` / `reverse_playback` / `keyframes` / `transform` /
`mask` / `keying` 均为可选字段增量）已被证明可行，引入版本号是较大改动且收益不明。
但 D1 的性质不同于此前所有增量——以往增量是"新增能力"，D1 是"改变既有行为"，
故以强断言替代版本号来约束风险。

**后果**：W0.3 的验收必须包含旧文档（无链接字段）的 trim/move/remove 行为逐字节不变断言。

### D9 · `candidate_source: auto` 语义：由"择一"改为"融合"

**内容**：`auto` 不再表示"有 ready 转录用转录、否则 CV"，而表示**多源融合**——
转录 + CV 视觉信号 + 节拍 + 说话人联合参与召回与排序。显式 `transcript` / `cv` 选择保持
为强制单源的调试与专业入口。

**理由**：现状把 CV 当作转录缺席时的兜底，导致**有转录素材的 CV 信号完全不被使用**——
而 CV 信号对"节奏、运动匹配、卡点"这类需求携带转录文本根本不具备的信息。CV 是**独立信息源**，
不是转录的替补。

**后果**：这是对"AI 粗剪 = LLM 从转录选段"这一认知漂移的直接纠正（总纲 §0 漂移 1）；
契约侧须保证旧客户端不传新字段时行为不变；融合权重以评测集（W0.4）钉死。

## 影响

- **门禁**：D1–D9 进入后续所有 Planning Gate 的核对清单；工作包若与本 ADR 冲突，
  须先走 ADR 修订而非在实施中偏移。
- **数据模型**：新增 SQL 迁移 v23 起（beat grid / embedding 索引 / 说话人轮次 / 机位偏移）；
  D1 的链接组字段为文档 schema 增量，不产生迁移。
- **契约面**：`split_edit` 等新 op 走三处同步；`prepare` 新增可选入参；
  `candidate_source` 枚举语义修正；**PROTOCOL_VERSION 保持不动**。
- **隐私面**：本 ADR 全部决策**不新增 egress**；唯一新增 egress 面（W3.3 关键帧）
  由 D5 定位为可选增强。
- **实施顺序**：W0.3（D1/D8）→ W1.4（D7）；W2.2 先 spike（D3）；
  W0.2 按 D6 交付。

## 否决方案

- **声画对默认不链接、仅显式建立**：否决——与剪映/Resolve 用户直觉相反，
  L/J cut 与多机位产物在微调时散架。
- **无链接模型、L/J cut 一次性构造**：否决——数据模型债越晚越贵，且无法支撑多机位。
- **多机位引入"角度组 + 选择轨"新模型**：否决——与 V1 权威语义和 IR 约束冲突，
  产出的多机位将失去转场与关键帧能力。
- **diarization 直接选型立项**：否决——无真实数据支撑的选型等于猜测。
- **Layer 1 本地 VLM 立即立项**：否决——ADR-0003 D3 的前置条件（硬件分布数据）未满足。
- **语义索引直接走 Layer 2 云端**：否决——违反 ADR-0003 D4"本地自立"，
  且放弃最干净的差异化。
- **采样密度纯默认或纯可调**：否决——前者静默降低长 GOP 素材质量，后者把达标责任推给用户。
- **`split_edit` 维持 AI 白名单外**：否决——E3 对 AI 永久不可用，与产品形态冲突。
- **引入文档级 `schema_version`**：否决——既有可选字段惯例已足够，收益不明；
  以强断言约束 D1 的行为变更风险。
- **`auto` 维持择一语义**：否决——CV 信号在占多数的有转录素材上被完全浪费。
