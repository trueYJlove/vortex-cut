# ADR-0003：AI 方向决策与隐私硬承诺

- 状态：已批准
- 日期：2026-09-20
- 记录人：AI 战略会话（基于 2026-09-20 产品定位讨论与代码库现状调研）
- 决策人：用户（产品负责人）于 2026-09-20 批准大方向与隐私硬承诺
- 关联：ADR-0002（架构结构债）、`ARCHITECTURE.md` 阶段规划、`docs/M2_ROADMAP.md`（"所有 UI 操作必须有对应程序化接口，供 AI Agent 调用"约束）

## 背景

产品定位：通过 AI 降低视频剪辑门槛——普通用户用 AI 完成大多数生活、娱乐视频的剪辑，兼顾一定的专业性。本文沉淀 2026-09-20 产品方向讨论的六项战略决策，作为后续所有规划门（Planning Gate）可引用的约束基线。

现状判断（依据代码库调研，2026-09-18 基线）：编辑核心功能基本齐全且验收纪律严格（Core 794 项测试、Desktop 635+ 项、迁移 v1–v19 逐版本测试）；AI 作为受控内部能力已跑通完整闭环（Stage 2A 粗剪三候选、Stage 2B 自然语言 → TimelinePatch 提案、本地 faster-whisper 转录、Stage 4 图片生成）；契约层（`packages/contracts`，PROTOCOL_VERSION=1，`/api/v1` 下 152 个端点）、细粒度结构化 TimelinePatch（约 33 种操作）、WebSocket 事件流、不可变 Revision 链均已具备。

## 决策

### D1 · AI 路线：内置为主，MCP 接口为辅

面向大众的产品体验必须是内置 AI（"点一个按钮，AI 把视频剪好"）；MCP 适配层作为小投入并行项，服务 power user 与生态（外部 agent 以 MCP 客户端身份接入）。两者共享同一个命令面——现有 REST 端点 + TimelinePatch 操作集即现成的工具清单，MCP 属于"在冻结契约上加暴露层"的工作量，不引入新数据模型。

### D2 · Agent 实现：自建薄编排层，不引入通用 agent 框架

Stage 2B 的单发提案（LLM 一次产出 patch → 校验 → 应用）升级为**有界的多步任务循环**：带校验错误反馈的重试、按工作单编排的步骤链（粗剪 → 字幕 → 样式 → BGM 类）。否决引入通用 agent 框架与嵌入编码类 agent 运行时——视频剪辑是有界操作集 + 强校验的领域，循环管理/上下文压缩/工具发现是框架解决的、而本项目没有的问题；且第三方 agent 运行时自带的网络出口与 prompt 处理链路与本项目 egress preview/consent 受控体系冲突。

### D3 · 视觉理解三层模型

- **Layer 0（无条件开启，纯本地 CPU）**：镜头边界检测、运动能量、音频能量、人脸检测、模糊/抖动检测。与转录文本汇合为多信号召回，解决无语音素材对 AI 不可见的缺口。挂入导入期既有离线分析任务（缩略图/波形同批）。
- **Layer 1（搁置）**：本地小 VLM，硬件 gating。待真实用户硬件分布数据后再决策是否立项。
- **Layer 2（显式 consent，项目级 opt-in）**：云端多模态理解。**传抽样的关键帧（静态图），不传视频**。token 成本与隐私审计粒度双收益：egress preview 呈现"这 N 张关键帧将发送给 Provider X"，用户可逐张审阅。

### D4 · 隐私优先为硬承诺

**云端永不默认、永不静默**；egress preview 必须可逐张审计；默认（纯本地）体验必须自立——从不开启云端的用户也要得到完整的 AI 剪辑体验，召回质量不足时加强本地信号而非翻转云端开关；遥测（若将来引入）只允许技术元数据，帧/转录/时间线内容永不外带。

**操作含义（门禁标准）**：任何削弱 D4 的提案（如"默认上云换免费额度"）在 Planning Gate 直接否决，不再重新权衡。LiuKeAi（独立评审）验证清单增加本项。

### D5 · 产品形态承诺

"AI 出 80% 的底稿，用户在时间线上微调"——非全自动一键成片。提案 + Diff 预览 + 不可变 Revision + 一键采纳/撤销即为此形态设计。滩头阵地为生活/娱乐短视频；长视频与强风格化内容长期手动为主，"兼顾专业性"定位不变。

### D6 · 节奏

1. M3-3 A1 音频混音缺陷收口（硬门槛：AI 产物走同一渲染管线，音频缺陷砸 AI 的招牌）；
2. 多步 agent（D2）与本地 CV 信号层（D3 Layer 0）两单并行；
3. MCP 适配层跟进。

## 影响

- **门禁**：D4 作为硬约束进入 Planning/Verification Gate 检查清单；本 ADR 为否决依据。
- **工作单**：D6 顺序生成三个工作单；D3 Layer 0 与 D2 两单并行立项，各自走五门流程。
- **成本**：D4 有代价——Layer 2 落地前，AI 粗剪质量上限由本地信号 + 转录决定，无语音素材第一版"可用但不出彩"。回报：目标用户（家庭、儿童、室内空间素材）恰为最排斥默认上云的人群，与云端产品形成最干净的差异化；"隐私优先 + AI 可驱动"构成同一架构叙事的两面（用户听到"安全"，生态听到"开放"）。
- **涉及面**：D2/D3 主要新增于 `services/core/src/aivs_core/`（agent 编排、CV 信号分析任务）；MCP 适配层为契约冻结面之上的暴露层，不动 SQLite schema。

## 否决方案

- **纯 MCP、AI 体验完全外包外部生态**：否决——目标用户（普通用户）不会自带 agent，押注未成熟的使用形态。
- **纯内置、不开放接口**：否决——放弃现成架构红利（"AI 可驱动"已是 M2 正式验收约束），失去生态杠杆与外部测试基建。
- **引入通用 agent 框架 / 嵌入编码类 agent 运行时**：否决——见 D2 理由。
- **云端多模态默认开启换质量上限**：否决——违反 D4 硬承诺。
- **传视频原片给云端理解**：否决——抽样关键帧已满足召回层需要，成本与隐私审计粒度双劣。
