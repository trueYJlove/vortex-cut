## 3. 数据模型（v37，冻结）

照抄 `beat_grids` 范式（`algorithm_version` 行化 + 部分唯一索引 + 指纹入键）：

```sql
CREATE TABLE speaker_diarizations (
  id TEXT PRIMARY KEY,
  -- **删除语义（F1，阻断级，必须冻结）**：派生分析数据**随素材自动清**。
  -- 反例警示：beat_grids / cv_analyses 用的是 NO ACTION，实测「插一行分析 ⇒
  -- DELETE FROM assets 直接被 FK 拒绝」（2026-10-11 复现，且 delete_asset 把该拒绝
  -- 报成"被镜头需求或生成记录引用"，原因错、无出路）。本表**不重蹈**：
  asset_id TEXT NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
  source_fingerprint TEXT NOT NULL,
  algorithm_version INTEGER NOT NULL CHECK(algorithm_version >= 1),
  status TEXT NOT NULL CHECK(status IN ('queued','running','ready','failed','unavailable')),
  reason TEXT NULL,
  speaker_count INTEGER NULL,
  turns_json TEXT NOT NULL DEFAULT '[]',
  windows_json TEXT NOT NULL DEFAULT '[]',     -- 窗时间栅格（重聚类的输入之一）
  embeddings_blob BLOB NULL,                   -- float32 (n_windows, dim)：**换 τ 不重跑推理**
  embedding_model TEXT NULL,                   -- 例 "campplus_sv_zh-cn_16k-common"
  model_revision TEXT NULL,
  vad_model TEXT NULL,                         -- 例 "silero_vad_v6"
  threshold REAL NULL,                         -- 本行结论用的 τ
  threshold_strategy TEXT NULL,                -- 哪个策略选的（归因用）
  sample_rate INTEGER NULL,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, finished_at TEXT NULL
);
CREATE INDEX idx_speaker_diarizations_asset
  ON speaker_diarizations(asset_id, algorithm_version, created_at DESC);
CREATE UNIQUE INDEX idx_speaker_diarizations_ready
  ON speaker_diarizations(asset_id, algorithm_version, source_fingerprint)
  WHERE status IN ('ready','unavailable');
```

**为什么存 embedding**：本包已确定瓶颈在 **τ 选择**（见 §5）。存下窗 embedding 后，
换策略/换 τ **只重跑聚类、不重跑 ONNX**。

**量级（2026-10-11 第一手实测，非估计）**：
- **重聚类耗时**：n=527–547 窗 **0.30–0.40 s**；n=1366 窗 **5.1–5.5 s**；n=1639–1697 窗 **7.8–9.4 s**
  （建树是主导项，随窗数**平方**增长）。对照重跑 embedding 的 **71–79 s/场**（AISHELL-4，spike 记录）
  ⇒ 收益是 **约 8–15×**，**是"分钟级→秒级"而非"毫秒级"**（初版口径写错，已改）。
- **体量**：`n_windows × dim × 4 B`。CAM++（192 维）实测 **0.40 MB**（547 窗）–**1.25 MB**（1639 窗）；
  取会话上限约 **1.3 MB/场**。36 场合计约 **15–45 MB**。**✅ 2026-10-14 已实测（§10 O5 / `evidence/2026-10-14-w22-o5-blob-backup/`）**：真实迁移库 + 36 场真实派生行 ⇒ BLOB 合计 **39.01 MiB**（平均 **1109.8 KiB/行**，落在上述预估区间内）；**备份 243 ms / 恢复 215 ms**，恢复后 `integrity_check = ok` 且 BLOB 逐一复原 ⇒ **体积与耗时均可接受、路径无损**。（边界：单次测量；未测大库/慢盘/并发写入。）

> **实现注记**：上表的建树是 spike 级实现（Python 循环的 Lance-Williams，O(n²)）。
> 生产实现应对 1600 窗级会议做优化（优先队列 UPGMA 或向量化更新）；S2 的性能门以实测为准。

## 5. 精度门（**本门最重要的裁决**）

**验收语料（D3 冻结）**：**AMI test 全 16 场**（英文，CC BY 4.0）+ **AISHELL-4 test 全 20 场**（中文，Apache-2.0）。
两者都可公开下载（AMI 单场 ~40 MB / AISHELL-4 单场 ~250 MB，下载路径与镜像已在 spike 的 `sources.txt` 记录）。
**语料不入库**（仓外），仓库内只放派生结果与哈希。

**评分口径**：`tools/quality_eval/diarization.py`（10 ms 帧 / 0.25 s collar / **忽略重叠** / 穷举最优映射）。
**该口径会高估质量**，故门限按此口径设，且**不得与含重叠的公开 DER 直接比大小**（spike §2.7 已声明）。

**门限（切片 1 必须达到）**：

| 指标 | 门限 |
|---|---|
| **自动 τ** 下 DER 均值 | **≤ 40%**（**两个语料都要满足**） |
| **自动 τ** 下 DER 最差场 | **中文 ≤ 55%；英文 ≤ 60%**（**2026-10-12 裁决，见 §5.4**） |
| 资源 | ≤ 10 s/分钟源；峰值 RSS ≤ 600 MB |

> **英文最差场由 55% 放宽到 60%**——裁决依据与反平凡性检验见 **§5.4**。
> 中文线**维持 55% 不变**（中文侧 oracle 有富余，55% 是可达目标）。

> **口径限定（复核 F10，必须写明）**：与此对照的三个参照**不是同一口径**，不得混读——
> ① **每场用真值调 τ**（乐观上界，不可产品化）；② **自动选 τ 家族的每场真值调参上界**；
> ③ 现状的**自动 τ** 实现。三者数值见 spike §2.9/§2.10 与
> `evidence/2026-10-11-ami-diarization/threshold-strategies-summary.txt`、
> `evidence/2026-10-11-aishell4-chinese/threshold-strategies-summary.txt`（**本文件不复述数字**，Rule 5）。
>
> **由此得出的一条硬结论**：40% 这个门限**严于中文语料的"自动选 τ 家族真值调参上界"（44.2%）**。
> 换言之，**它不可能靠继续微调 AHC 阈值启发式达到**——这直接决定下面 §6 的切片结构。

`W2_2_SPEAKER_LAYER_IMPLEMENTATION_2026-10-11.md`。**本文件不复述现役数字**（Rule 5），只记判定。

§5.1 只写到"AMI 的失败在 τ 之前（VAD / embedding / 分段）"——**这句话太粗，会开错药方**。
方案 A 用四层剥离把它拆开（条件对照 / DER 分量分解 / 完美聚类天花板 / 同 embedding 换聚类）：

| 环节 | 判定 | 处置含义 |
|---|---|---|
| **窗栅格 + 轮次化** | ❌ **无问题**（完美聚类天花板极低） | 冻结参数**不动**；不必再调窗长/跳长/碎段门限 |
| **VAD** | ⚠️ **确有漏检，但修它不改善 DER** | **不得**把"修 VAD"当作 AMI 的解药（漏检的收益被串号反向抵消） |
| **聚类算法** | ✅ **有实质余量**（同 embedding 换聚类显著改善） | **这是 B（VBx 级）要作用的环节**，是升级路径的主要依据 |

**对 §5.1 的修正**：§5.1 表格中 AMI 行的"失败应归因于"由
**"τ 之前（VAD / embedding / 分段）"** 更正为
**"embedding + 聚类（**不含** VAD 与窗栅格）"**。

### §5.4 英文验收线裁决 + 仪器缺陷（**2026-10-12 已执行，用户裁决项**）

证据：`evidence/2026-10-12-w22-c-decision-and-instrument/`。**本文件不复述现役数字**（Rule 5），只记判定。

#### ① 裁决：**英文最差场 55% → 60%**（中文维持 55%；均值线两语料都维持 <= 40%）

依据三条：

1. **AMI 的最差场够不着**：现行自动 K、AHC、elbow、真值 K 四条路线里**只有现行自动 K 过 55%**，
   而它靠的是**欠分割的保守偏置**（§三）。⇒ 55% 在英文上等于要求一个**被证明是运气的结果**。
2. **oracle（不可产品化的乐观上界）在最差场上也过不了 55%**（§5.1 已记）。
   ⇒ 该线不是「难」，而是**设在可达到域之外**。
3. **60% 是「最严格口径下也过关」的最小 5% 刻度线**：含重叠口径下 0.55 线必然越线、0.60 线恰好过。
   ⇒ 60% 让英文线的通过**不依赖评分口径的选择**，55% 让它依赖。

**反平凡性（放宽带价，已核）**：英文四条路线中**仍有 3 条被拒**，且均值线未动 ⇒ **门没有失去约束力**。

**语义边界（防误用）**：英文最差场**实际在测 embedding 质量**（最难场是 embedding 地板），
**不得**据它判定「聚类策略已达标」；两语料**不可共用一条最差线**。

#### ② 仪器缺陷（**必须先于任何数字被引用**）

**DER 评分器的最优说话人映射搜索空间不完整**：旧实现只用**序号最小的** `min(n_hyp, n_ref)`
个假设说话人，**从不搜索该挑哪几个**。`n_hyp <= n_ref` 时与全排列等价（故既有 14 项自检全绿），
**一旦过分割（n_hyp > n_ref）就可能跳过真正的匹配对 ⇒ DER 被高估**。

⚠️ **该缺陷是方向性的**：它**只惩罚过分割**，因而**系统性掩盖「欠分割的代价」**——
正是 §5.3 要判的那个问题。**凡引用修复前数字的结论都必须重新审视。**

发现方式：与 **NIST 参考实现 `md-eval-22.pl`** 做独立交叉校验时暴露（一场对不上）。
修复后与参考实现的一致性大幅提高；第二次修复把穷举换成**匈牙利匹配**以解决性能，**结果逐值不变**。
回归锁在 `test_diarization_scorer.py::TestOptimalMappingSubsetSearch`（含负向对照）。

#### ③ 「把自动 K 做稳」的方向判定（**修正 §5.3 的建议**）

§5.3 把方向定为「先把自动 K 做稳」，针对两个机制（K̂ 偏小 + 初值敏感）。本步判定：

  实测在 AMI 上**真值 K 的最差场比现行自动 K 明显更差**。
  ⇒ 「K̂ 偏小」不只是缺陷，**也是现行方案在最差场上过关的机制之一**。
  ⇒ **本门明确否决「以 K̂ 逼近真值 K 为目标」的做法**。
- **可产品化的增量确有**：存在一个不偷看真值、且至少 AMI 侧均值与最差场同时更好的 K 规则；

⇒ **对 §5.3 的修正**：§5.3 写的「若做稳自动 K 后仍不过门，再上 B」**成立，但优先级改变**——
「做稳自动 K」已证明**不能**解决最差场（其目标本身与最差场相冲突）。
**要继续降最差场，须回到聚类 / embedding 族（§5.2 的 B 路径）**，且 B 的验收仍须**分别报均值与最差场**（§5.2 已定）。

### §5.5 方案 A **复跑**判定（**2026-10-12 已执行：§5.2 的核心结论被推翻**）

证据：`evidence/2026-10-12-w22-d-planA-recheck/`。**本文件不复述现役数字**（Rule 5），只记判定。

**为什么复跑**：§5.4 ② 发现验收仪器的最优说话人映射搜索不完整，**只惩罚过分割**。
而 §5.2 的层 ④ 与 AHC 的 τ 曲线**正是要在低 τ / 高 n_hyp 区间取最优** ⇒ **落在缺陷区间内**。
§5.4 已把「复跑 §5.2」定为 O4 的**入场条件**，本节即该条件的判定。

**前置验证（结论成立的前提）**：§5.4 的交叉校验只覆盖 `n_hyp <= n_ref`（K̂ ≤ 4），
**从未覆盖数十至近千个假设说话人的区间**。故先补测：AMI 全场 × 5 个 τ 共 **80 个 (场, τ) 点**
与 NIST `md-eval-22.pl` 对拍，**max|Δ| 0.0154、超 0.02 的点数 0、覆盖 n_hyp 至 982**。
⇒ 修复后仪器在高 n_hyp 区间**可信**，故复跑有效。

#### 判定一：§5.2「聚类算法有实质余量」——**不成立（方向相反）**

§5.2 的 12.9 点余量**是评分器缺陷的产物**。复跑后：
同 embedding、同窗、同评分，**换聚类族不但没有余量，反而更差**。
⇒ **§5.2 表格「聚类算法 ✅ 有实质余量」一行作废。**

#### 判定二：§5.2「VAD 修好不改善 DER」——**不成立（方向相反）**

复跑后 **VAD 修好有正的净收益**。机制：`miss` / `fa` 两列**逐值不变**（不涉及说话人映射），
变的只有 `spkerr`——旧仪器把过多假设说话人全算成串号，
于是 VAD 的 miss 改善**被虚增的 spkerr 抵消**。
⇒ **§5.2 表格「VAD ⚠️ 修它不改善 DER」一行作废**；VAD 从「非解药」改回「**有净收益但不足以单独达标**」。

#### 判定三：§5.2「窗栅格 / 轮次化无问题」——**保持**

完美聚类天花板**逐值不变**。合理性：该层每窗直接给真值标签、几乎不过分割，**不在缺陷区间**。
⇒ **本门该行仍成立**，且它是本批**唯一逐值未变**的一层，可作为「缺陷定位准确」的旁证。

#### 判定四：**§5.1 的触发依据失效**（本批最重的后果）

§5.1 的核心论断是「**AMI 上连 oracle 都过不了最差场门限**」⇒ 失败不在 τ 选择
⇒ 触发升级判据、停在 S1。复跑后 **oracle 过双门**。
⇒ **该论断不成立**，**§5.1「停在 S1、需 VBx 级方案」的触发依据随之失效**；
§5.2「τ 策略修不了最差场」也**失去主要证据**。
（唯一仍成立的相邻论断：**k-means 用真值 K 时最差场仍越线**——但那说明「**K 选到真值反而更差**」，与 τ 选择无关。）

#### 判定五：AMI 的余量在**参数化**，不在**聚类族**

把「选择余地」按族分开比较，**族内余量**：AHC（选 τ）**远大于** k-means（选 K）；
**跨族**（两者都取各自 oracle）**AHC 反而更好**。

**机制（已识别）**：现行的 `silhouette+capK` 把簇数**限定在 [2, 8]**，
而实测最优 τ 常对应**远大于 8** 的 K。⇒ 这不是「聚类算法不好」，
而是**一个先验簇数上限把更好的解挡在门外**。

> **对 §10 O2 的澄清**：O2 已证 `k_max = 8` 对 4–7 人的语料**「有余量」**。
> 但那保证的是「**不切断真值 K**」，**并未**说「最优 K 不会超过 8」。
> 本批实测它**确实常超**——**两者不矛盾**，是 O2 当时未覆盖的维度。

#### 判定六：**AISHELL-4 侧 S1 同步复跑**（门 §6 S1 的中文侧欠账）

中文侧的变化**远小于**英文侧（`silhouette_capK` 与 `distance_mixture` 的两列基本不动），
与「缺陷只在过分割时触发」一致——中文的 K̂ 本就贴近真值。

**两语料复跑后的对称结论**（各自门限：英 mean ≤40% / worst ≤60%；中 mean ≤40% / worst ≤55%）：

| 语料 | 可产品化的 AHC 自动 τ | oracle 上界 |
|---|---|---|
| AMI（英） | ❌ / ❌ | ✅ / ✅ |
| AISHELL-4（中） | ✅ / ❌ | ✅ / ✅ |

⇒ **两语料的 oracle 都过双门**，但**可产品化的 AHC 自动 τ 都过不了最差场**。
这正是「余量在**参数化选择**」的直接体现：**上界够得着，缺的是选对 τ 的方法**。
⇒ **§5.1 的两语料对照表整体作废**（它建立在「AMI oracle 越线」之上）。
#### ⇒ 本门的方向修正（**覆盖 §5.3 与 §5.4 ③ 的优先级结论**）

- **B（VBx 级）的立项依据不成立**：余量不在聚类族（判定一），
  且 oracle 已过门 ⇒ **没有必须升级的证据**。
  ⇒ §5.4④ 的「入场条件」判定为**不满足**，**不得**据「余量在聚类族」立 B。
- **新的第一顺位改为「参数化选择」**：针对已识别机制（**簇数上限 [2, 8] 挡路**），
  投入远小于 VBx，且直接打在病根上（判定五）。
- **诚实标注收益性质**：判定五测的是「**参数化能达到多少**」（oracle 上界），
  **不等于**任何具体启发式都能拿到。**可产品化**路线里 `kmeans_silhouette` 仍优于现行 AHC；
  这与「AHC 参数化上界更高」**同时成立**，两者不矛盾。

#### ⚠️ 本次复跑的边界（不得越界引用）

- **§5.1 的两语料对照表整体作废**（建立在「AMI oracle 越线」之上，见判定四/六）。
### §5.6 「参数化选择」的分因与反过拟合闸门（**2026-10-12 已执行：§5.5 的处方需修正**）

证据：`evidence/2026-10-12-w22-e-param-selection/`。**本文件不复述现役数字**（Rule 5），只记判定。

#### ① §5.5 判定五的处方**需修正**：瓶颈是「准则」不是「上限」

§5.5 判定五把余量定位在「参数化」，机制归为「簇数上限 [2,8] 挡路」。本步把这句话拆开测：

- **天花板确实在上限后面**——放开上限，**oracle 上界**显著改善；
- **但放开上限几乎不改善可产品化路线**——silhouette 的**实际选择**改善可忽略。

⇒ **修正**：不是「放开簇数上限」，而是「**修选择准则**」。
⇒ §5.5「新的第一顺位改为参数化选择」**方向保留**，但**具体处方改写**为「选择准则」。

#### ② 机制：silhouette 的最优解**卡在候选下界 K=2** 上

候选集下界是 2，而实测 **AMI 多数场** silhouette 的最优解**恰好落在 K=2**（中文少得多）。
且被选中的划分常是**退化**的：一个巨簇（≈99.9%）+ 一个极小远簇（≈0.1%）；
轮廓系数对这类划分**天然给高分**。

**⚠️ 但本门不据此开处方**：实测存在**反例**——个别场的**正确答案就是 K=2 且是平衡划分**，
而更高 K 才是退化的。故「拒绝退化划分」**未被采纳为规则**，只作为**机制记录**。

#### ③ **反过拟合闸门**（本步最重要的交付）

**问题**：本门验收语料的真值 K 覆盖极窄（**只覆盖 3–7**，且英文集中在 4、中文在 5–7）。
在这个语料上，一个朴素的**常数下限**（`K >= 4`）**两个语料的均值都最好**——
但它对 **2 人素材**（口播／对谈，**产品主场景**）会把**正确答案直接排除**。
⇒ **按本批性能拍板，就会把一个真机主场景上必错的规则写进产品。**

**处置**：把「结构安全性」做成**机器校验**，而非文档纪律——
新增 `structural_safety(rule)`：对每个 K 档构造理想候选集，检查规则是否仍**有可能**选中正确答案；
**登记进规则的准入门槛**，并配**负向对照**（已知不安全的规则必须被判不安全，
且安全规则必须判安全——防闸门恒真／恒假）。

#### ④ 新规则**未获批**（本门明确不代裁，且给出不批的理由）

本步找到一个**过了安全闸门且在本批两语料都更优**的规则（数据驱动下限，非常数）。
**但本门不批准将其落入 Core**，理由三条：

1. **它依赖的说话人数估计器从未被单独验证质量**——该规则的输入本身是未验证的；
2. **本批语料不覆盖 K ≤ 3**，而产品主场景恰在那里 ⇒ **不能**声称「真机上更好」；
3. §5.5 已证本包**没有必须升级的紧迫性**（oracle 已过门，B 无立项依据）⇒ 无仓促改动的理由。

⇒ **处置**：该规则作为**候选**登记，**须等覆盖 1–2 人档的语料**（见 §10 O6）后才能定案。

#### ⑤ 对 §10 O4（B 路径）的影响

**无变化**——本步进一步确认余量在**参数化/准则侧**（廉价），**不在聚类族**，
故 **B 仍无立项依据**（维持 §5.5 判定一与 O4 终稿）。
### §5.7 低人数档语料实测 + 反过拟合闸门的**实测检验**（**2026-10-12 已执行：O6 缺口部分关闭**）

证据：`evidence/2026-10-12-w22-f-voxconverse-lowk/`。**本文件不复述现役数字**（Rule 5），只记判定。

**语料**：**VoxConverse dev**（CC BY 4.0，公开可下载；真实对话）；本门**自行下载**
（音频 2.0 GB + GitHub 上的 RTTM），因为它的说话人数**横跨 1–21**，恰好补上
AMI（3–4 人）/ AISHELL-4（5–7 人）不覆盖的档。子集选择规则**先于看任何 DER 定死**
（时长 >=120 s，每档按名称排序取前 N），防挑选偏差。仓库工具已接入：`--corpus voxconverse`。

#### 判定一：**现行路线在低人数档并不差**——但失败模式是混合的

在 K<=3 的 24 场上，现行 silhouette 的均值**远好于**它在 AMI 上的表现。
⇒ **这不是「规则在低 K 上坏掉」，而是「低 K 本来就好分」**。

**但最差场仍会爆掉，且性质不同**：既有「K 选错」的场，也有「**K 选对了但划分本身错**」的场。
⇒ 后者**不是选择准则能修的**（属聚类/embedding 侧），本门据此划清边界。

#### 判定二：**机制与 AMI 相反**——低人数档上「欠分割有害、过分割无代价」

按 K̂ 与真值的关系分组后：**K̂ < 真值**时与上界有**实质缺口**；**K̂ > 真值**时缺口**为零**。

**⚠️ 这与 §5.4 ③ 在 AMI 上的结论方向相反**（AMI 上真值 K 的最差场**比**自动 K 更差，
即欠分割在 4 人会议上反而是「保护」）。⇒ **不得把 AMI 的「欠分割」结论外推到低人数素材**。
两处结论不矛盾——它们是同一个 U 形在不同区段的表现，但**处方相反**。

#### 判定三：**反过拟合闸门的预测被实测证实**（本步最重要的结果）

§5.6 用**纯结构推演**把「朴素常数下限 `K>=4`」判为**不安全**
（会排除 2–3 人素材的正确答案）。当时它**只有推演、没有实测**。
本步用真实 1–3 人语料直接测量四条规则：

- 被闸门判**不安全**的规则，在真实低人数语料上**既是均值最差、也是最差场最差**；
- 两条被闸门判**安全**的规则（数据驱动下限及其放宽变体）在 **mean 与 worst 上都不差于现行**。

⇒ **闸门从「结构推演」升级为「已被实测证实」**。
⇒ 这是本包**第一次**出现「结构判据先于性能排序给出正确取舍」的闭环。

**⚠️ 但必须同时写明样本局限（不得选择性引用）**：

- 有效场次仅 **23–24 场**；**mean 上的差异不足以声明统计显著**；
- **worst 上的改善由单个场主导**；
- 取的是 **dev** 集（test 集音频未下载），K=1 档只有 9 场可选，**样本最薄**；
- VoxConverse 是 YouTube 真实对话，**录音条件与产品素材不同** ⇒ 其 DER 绝对值
  **不可**与 AMI/AISHELL-4 比大小，只可比**同语料内的规则排序**。

⇒ **处置**：安全规则作为**候选**登记（**仍不批准落入 Core**，理由见 §5.6④ 不变）。
**下一步应先补足低 K 样本量**（test 集或更多语料）。

#### 判定四：`k_max = 8` 的适用边界被**实测**突破（修订 §10 O2）

§10 O2 曾据 AMI/AISHELL-4 断言 `k_max = 8`「高于全场最大值 7（有余量）」。
**该结论只在旧语料的 K 范围内成立**：VoxConverse dev 有大量 **K>8** 的会议。
在 K=9..20 的 18 场上，**上限 8 是硬约束**，代价**接近 20 个 DER 点**。

**⚠️ 但这与规则评测是两件事，本门分开记录**：

- **上限 8 的代价**是「**产品要不要支持 >8 人会议**」的产品决策，**不是**选择准则问题；
- 本门**不代裁**该产品边界（属架构裁决）；
⇒ **§10 O2 修订**：`k_max=8` 对**原语料**有余量这一条**仍成立**，
但「有余量」**不可**推广为「对所有真实会议的说话人数有余量」。

### §5.10 低人数档最差场的**机制溯源**（**2026-10-13 已执行：§5.6② 的解释被取代**）

证据：`evidence/2026-10-13-w22-h-criterion-trace/`。**本文件不复述现役数字**（Rule 5）。

**为什么做**：§5.9 判定一记录了一个 §5.6② **解释不了**的现象（K_true=1 被切成 7–8 簇）。
本门要求"先解释它，再对候选规则跑同一子集"。本步即该解释。

**判定一：真正机制是「准则方向反了」，不是「卡在下界 K=2」**

以 `ρ = Spearman(silhouette(K), −DER(K))` 为判据：一部分会话上 **ρ < 0**，
即 silhouette **把更差的解排在前面**，argmax 因此落在最差解上。
这些"方向相反"的会话与其余会话的 DER **相差约 5 倍**（见证据目录）。

**判定二：三个原本很像主因的假设被推翻**（每个都做过读数，见证据目录）

| 假设 | 判定 |
|---|---|
| cap 上限 [2,8] 挡路（§5.5 判定五） | ❌ **反而 cap 是保护**：仅少数钉在上沿；**放开 cap 会显著变差** |
| VAD 漏检缩小窗集合 | ❌ silero/oracle 窗数比中位接近 1 |
| K=1 被排除在候选外 | ❌ 加进候选窗**不改变任何一场**（silhouette 在 K=1 无定义） |

**判定三：§5.6② 的机制确实不适配本批**
§5.6② 说的是"一个巨簇 + 一个极小簇的退化划分拿高分"。
本批灾难场的簇大小**是相对平衡的**（最大簇仅占约两至三成）⇒ **不是退化划分**。
⇒ **§5.6② 保留为"AMI 上已观测到的机制"，但不得再被引用为低人数档最差场的解释。**

**判定四（新登记的产品级事实，独立于本批失败机制）**
现行 `silhouette+capK` 的候选窗是 **K ∈ [2, k_max]**，而 `silhouette` 在 K=1 处**无定义**
⇒ **现行准则结构性无法输出"1 个说话人"**。
这在产品主场景（口播/对谈）上是**已知的结构性偏差**。

> **⚠️ 2026-10-14 两处更正（ADR-0006 D6，本条其余部分保留）**：
> ① 原文"单说话人素材**最多报 K̂=2**"**已被实测证伪**——15 场 K_true=1 中 **4 场报 >2**
> （K̂ = 6/7/7/8）。⇒ "最多报 2"的措辞**作废**；成立的只有"无法输出 1"这半句。
> ② 原文"**不得**与 7–8 簇灾难混为一谈"**需修正**——实测两者**正是同一批场**：
> 灾难场即 K_true=1 的场，表达能力缺陷**就是**该灾难的机制（给 K=1 后 DER 低至 0.0002–0.1333）。
> ⇒ 本条**不是**独立于失败机制的旁支，而是**失败机制之一**。
> **注意区分**：把 K=1 **加进候选窗**确实 0/63 场改变（本判定"假设 3"的读数仍成立，
> 因 silhouette 在 K=1 无定义）——故修法**不能只靠放宽窗口**，须由**另一条判据**输出 K=1。
> 拆因读数与两条欠账的分离见 **ADR-0006**（`docs/adr/0006-w22-speaker-direction-ruling.md`）
> 与 `evidence/2026-10-14-w22-k-direction-ruling/`，**本文件不复述数字**（Rule 5）。

**判定五：候选规则（B1/E2）的适用性需要重新审视**
这两条规则是在"K 被低估"的诊断下设计的（下限约束 `K >= K̂`），
而本批的失败是**方向反了**——**下限约束治不了方向错误**。
⇒ §5.9 判定三"仍不批准落 Core"**维持**，且**新增一条前置**：
任何新准则登记前，除了既有的 `structural_safety` 闸门，还须**报告其在方向相反会话上的行为**。

**边界（如实）**：本批只覆盖 VoxConverse test K≤3（63 场），**未做** AMI/AISHELL-4 上的同款溯源自查；
未测"把 K̂ 作为下限压回 7–8"这类修法；**不开处方**（§5.6④ 三条理由未变）。

### §5.11 方向敏感准则 spike（**2026-10-13 已执行：三条采用条件全未通过，候选全部否决**）

证据：`evidence/2026-10-13-w22-i-criterion-spike/`（含 **看数之前写死**的 `PRE_REGISTRATION.md`）。
**本文件不复述现役数字**（Rule 5）。

**做了什么**：按 §5.10 判定五的要求「先设计一个方向正确的新准则」，预登记四条候选
（A0 现行 / G1 用 K̂_dm 作**上限** / G2 `distance_mixture` / G3 方向守卫），
在三语料上对照：主判定语料 VoxConverse **test** K≤3（63 场）+ AMI（16 场）+ AISHELL-4（20 场）。

**判定一（否决）**：**没有任何候选通过预登记的三条采用条件**（worst ≤0.55 / mean 不劣化 / 对照语料不退化）。
G1 在主判定语料上改善显著（worst 与 mean 双双改善），但**worst 差一点点未达标**，
且**在两个对照语料上都明确退化**（其中中文侧退化幅度很大）。
⇒ **本包不批准任何候选落入 Core**（§5.6④ 三条理由不变，且新增跨语料否证）。

**判定二（跨语料不可迁移，与 §5.7 一致）**：G1 的收益**只在低人数档**出现，
在多人会议（AMI/AISHELL-4）上普遍更差 ⇒ 与 §5.7 判定二记录的"机制相反"同向，
**不得**据低人数档的改善外推为"通用更优准则"。

**判定三（根因：K 估计是硬约束，而它会**低估**）**：G1 的残差 worst **不是"选错"**，
而是**"正确答案不在候选集里"**——实测相当比例的会话 `K̂_dm < K_true`，真值 K 被上限排除。
**这类失败任何选择准则都修不了**，只能靠更好的 K 估计，或**不把 K 估计当硬约束**。
⇒ §5.10 判定五的"下限约束治不了方向错误"**得到互补证据**：**上限约束也治不了估计误差**。

**判定四（负结果）**：G3（把 §5.10 的机制直接做成规则）**几乎不触发**（守卫触发率仅个位数百分比），
于是 G3 ≈ A0。机制是"曲线单调不减"**过严**（§5.10 用的是 ρ，两者不是同一个量）。
⇒ 本批**既未证实也未证伪**"方向诊断可做成规则"，**不得**据此宣布方向诊断无效。

**判定五（闸门盲区，本门纪律的增强项）**：§5.6 的 `structural_safety` **只检验
"hint 恰好等于真值"这一种情形**。实测**上限型规则 G1 通过闸门**，
而它在真实数据上有相当比例因 hint 低估而排除正确答案；
**已知不安全的对照规则仍被正确拒绝** ⇒ **闸门没坏，只是覆盖不全**。
⇒ **准入纪律增强（本条立即生效）**：任何**依赖 K 估计**的规则，
登记时**除 `structural_safety` 外**，还须报告「**估计器偏离真值时**（高估与低估两个方向）的行为」。
这条与 §5.10 判定五的"方向相反会话行为"**并列**，共同构成新准则的准入前置。

**边界（如实）**：主判定语料未做四层剥离；三语料采集条件不同，DER 绝对值不可互相比较；
预登记 §3.4 明确本 spike **不判**"能否输出 K=1"；**不开处方**（落 Core 属设计裁决）。

### §5.12 K 估计器验证（**2026-10-13 已执行：现役估计器无信息，四个候选全部否决**）

证据：`evidence/2026-10-13-w22-j-k-estimator/`（`PRE_REGISTRATION.md` + `PHASE1.md` + `PHASE2.md`）。
**本文件不复述现役数字**（Rule 5）。

**为什么做**：§5.6④ 的**第一条**不批准理由写着"依赖的说话人数估计器**从未被单独验证质量**"；
§5.11 把失败根因定位到估计器（"正确答案不在候选集里"）。本步同时补上这两课。

**判定一（现役估计器基本不携带信息）**：`K_hat_dm = round(1/w_same)` 与真值的相关性
在三语料上**全部低于预登记阈值 0.3**（其中中文侧为**负相关**）。
⇒ 它不是"有偏"，而是"**读不出这个量**"。

**判定二（反平凡性：英文两语料上不如恒取常数）**：估计器的命中率**低于**"恒取该语料的中位人数"。
⚠️ **本条只用于证明估计器无价值**，**不得**据此建议"改用常数"——那个常数的好成绩来自
语料人数分布极窄，正是 §5.6③ 记录过的"会致错的盲区"。

**判定三（中文侧是单侧崩溃，不是噪声）**：中文语料上估计器**系统性大幅低估**。
⇒ 与 §5.7/§5.8 的"中文链路另有 VAD/远场效应"一致，**该估计器不可跨语料使用**。

**判定四（四个候选全部否决）**：第一阶段的"无信息"结论，在三个预登记候选上没有修好——
**① PCA 有效秩结构性退化**（解释 90% 方差的主成分数恒为上限，高估 100%）；
**② 合并距离最大间隙**名义命中最高，但与真值相关性**仍为噪声**，其"命中"来自更常猜同一个值；
**③ 双半一致性投票**反而**放大了偏置**（一致成了错误的放大器）。
⇒ 按预登记"三条全过才建议落 Core"，**无候选入选，不提出任何落 Core 方案**。

**判定五（比 §5.11 更强的结论）**：§5.11 说"问题在估计器不在约束方向"；
本步进一步说——**在现特征空间上，"说话人数"这个量没有被这四个廉价判据读出来**。
⇒ 依赖 K 估计的规则（上限型、下限型、邻域型）**在本包内一律不具备准入条件**。

**⚠️ 未做（不得越界引用）**：候选估计器在 AMI / AISHELL-4 上的对照**未跑完**（计算量原因中止）。
因 K1/K2 在**主判定语料已全部不通过**，按预登记"三条全过才建议落 Core"，未跑的对照**不改变结论**；
但**不得**据此声称"候选在对照语料上也失败"（**未测**）。

**边界**：本步**只测量、不改任何生产代码**；**不判**"估计器变好是否等于 DER 变好"（属 S3）；
**不开处方**（下一步方向属设计裁决）。

### §5.13 方向裁决（**2026-10-14 已执行：失败拆因为两条独立欠账，ADR-0006**）

裁决：`docs/adr/0006-w22-speaker-direction-ruling.md`（**用户 2026-10-14 批准**）。
证据：`evidence/2026-10-14-w22-k-direction-ruling/`（输入全为**已归档**证据，可复算）。
**本文件不复述数字**（Rule 5），只记**判定**。

**为什么做**：§5.11/§5.12 连续两轮负结果后，上一步提出 A/B/C 三个方向选项。
本次裁决前先做**拆因**，发现三个选项**都在回答同一个被错问的问题**——
它们都把低人数档 worst 当成**一件事**（"选择准则不好"）。

**判定一（本门最重要）：低人数档 worst 是两条互不代替的欠账**

| | 欠账 | 性质 |
|---|---|---|
| **(a)** | **表达能力**：准则**结构上无法输出 K=1**（候选窗 `[2, k_max]`，silhouette 在 K=1 无定义） | 产品主场景（口播/对谈）上**输出是错的**，不是"精度低" |
| **(b)** | **判别能力**：正确答案**在**候选集里但没被选中（§5.10 的"方向反了"） | 已有四轮候选被否 |

**只修 (a)** 即可把 worst 从灾难值压到门限附近；**但 (a) 修好后仍不达标**，残差**全部**是 (b)。
⇒ 两条欠账**真实且独立**，任何一条修好都不自动带来另一条。

**判定二：§5.13 更正 §5.10 判定四（该条已就地修改）**
"单说话人素材**最多报 K̂=2**"**被实测证伪**（15 场里 4 场报 >2）；
且原文"**不得**与 7–8 簇灾难混为一谈"**需修正**——两者**正是同一批场**。
⇒ 表达能力缺陷**就是**该灾难的机制，**不是**独立旁支。
**保留**的部分：把 K=1 加进候选窗 **0/63 场改变**（silhouette 在 K=1 无定义）
⇒ **修法不能只靠放宽窗口**，须由**另一条判据**输出 K=1。

**判定三：门自身的"oracle 上界"也带 (a) 缺陷**
§5.9 的 oracle 用**同一个候选窗**，故在单人素材上**也报不出 K=1**（16/63 场非真最优）。
**好消息**：其 **worst 值不变** ⇒ §5.5「oracle 过双门」**仍成立且保守**；
**坏消息**：这一类素材上引用的"上界"**一律虚高**。

**判定四：§5.11 的 G1 与本拆因交叉印证**
G1（按 `K_hat_dm` 封顶）**独立地**把三个灾难场压回可接受值，
且与"只修 (a)"落在**同一个 worst 值、同一最差场** ⇒ **残差同源，均为 (b)**。
⚠️ 这**不**使 G1 可用（§5.11 已判它在对照语料退化、且依赖 §5.12 已证无信息的估计器）。

**判定五：`separation` 判据"回归口径无信息 ≠ 二元口径无信息"**
§5.12 判定的**是回归口径**（"用它估 K"）。同一统计量在**二元口径**（"是不是单人"）上
**携带信息**，且**控制录音时长后仍成立** ⇒ §5.12 **不推翻，只限定范围**。
⚠️ 与 §5.10 已否守卫**机制不同**（abstain vs 回答），该否决**不推翻**——见 ADR-0006 D5。

**裁决（六条）**：

| # | 裁决 |
|---|---|
| **D1** | (a)/(b) **拆为两条独立登记项**，各带验收线；S3 须**分别报告**，不得只报总 DER |
| **D2** | **否决 A（VBx/换特征）**——§5.5 入场条件仍未满足，且 (a) 类失败**不是特征问题**。**保留入口**：D5 的 (b) 若仍不过线，届时 B 第一次有明确依据 |
| **D3** | **采纳"不被 K 框住"的目标，否决其手段表述**——τ 网格**本就连续**，真正排除 K=1 的是**候选窗下界**；且 B **不解决 (b)** |
| **D4** | **C（降级交付）暂缓，且以 (a) 为前置**——现状口播会被切成 7–8 个说话人，而 **W2.3 拿 turn 切机位**，那是"输出是错的" |
| **D5** | **下一步做 (a) 的预登记候选实验**（优先于 (b)）：加"是否单人"前置分支。**须过** `structural_safety` + §5.11 双向偏离 + §5.10 方向相反会话**三道具**；阈值**不得在 AMI/AISHELL-4 上挑**（§5.6③）；**必须报假阳性代价** |
| **D6** | **更正 §5.10 判定四措辞**（已就地执行，见判定二） |

**对 W2.3 的影响（产品级）**：依赖不变，但**准入收紧**——(a) 落地前，
W2.3 消费 speaker turn **必须**对"单人素材被判成多人"设防，
否则单机位口播会产出密集切换。**这不是精度微调**。

**对 §10 O4（B 路径）**：**仍不立项**，但**入口条件被明确化**（D5 的 (b) 残差）。
**对 §10 O6**：由"定案路径未关闭"推进为**"定案路径已拆为两条"**；**仍未定案**（D5 未执行）。
**对 §10 O2（`k_max=8`）**：**不动**——未测得该上限是病根（§5.10 已实测"cap 是保护"）。

**边界（如实）**：本拆因**未预登记** ⇒ **探索性读数**，用途**仅限**"判断下一轮该设计什么实验"；
其"只修 (a)/(b)"各行均为**同网格内取最优的上界**，**不是可达精度**；
本步**只测量、不改任何生产代码**（零迁移 / 零契约 / 零 egress）。

### §5.14 (a) 表达能力 spike：单分支候选（**2026-10-14 已执行：不通过，但揭示了新的判据分辨率问题**）

证据：`evidence/2026-10-14-w22-l-single-branch/`（`PRE_REGISTRATION.md` + `spike.json` +
`k5-reports.json` + `README.md`）。**本文件不复述数字**（Rule 5），只记**判定**。

**做了什么**：按 ADR-0006 **D5** 预登记并执行单一候选 **S1**——
在现役 `silhouette+capK` 之外加"是否单人"前置分支，判据用现役**已在算但被丢弃**的
`separation`（`speaker.py:369`）。**T 只在 VoxConverse dev-48 上选**（与主判定语料
VC test K≤3 **不相交**），冻结后用于主判定与两对照语料。

**判定一（不通过）**：三条采用条件里 **K1a（主判定 worst 改善 ≥0.10）未过** ⇒ **不落 Core**。
其余五项（K1b / K2a / K2b / K3 / K4）**全过**——**两对照语料零退化、无假阳代价**。

**判定二（机制，决定性）**：worst 未动是因为**最差场没被触发**——
其 `separation` **高于**定参集选出的 T。该场单独可降 **0.77**，
本可把 worst 一举压到 ADR-0006 预言的 (a) 天花板。⇒ **不是"分支无效"，是"T 没覆盖到它"**。

**判定三（判据分辨率不足 —— ⚠️ 本门曾记错一次，已更正）**：
正确判定单元是**触发集合**（定参集 separation 排序后的前缀），不是"某个 T"。
按此枚举（**全部由定参集自身导出**），预登记规则**唯一选出 k=9**；
而 k=9 区间**两端都是定参集统计量** ⇒ **选到它无需任何主判定语料信息**。

> ⚠️ **更正记录**：本门曾写下"可过门的 T 必须偷看被判语料"——**该论断错误**，
> 已在提交后的复核中**自证伪**并更正。正确的问题是：
> **k=9 区间被主判定语料某一场的 separation 从内部切成两半**，
> 左半漏它（worst 不变、K1a 不过）、右半抓到它（worst 达标、K1a 过），
> 而**定参集对两半给出完全相同的读数** ⇒ **定参集无法分辨通过与否**，
> "取更小 T"或"取更大 T"**同样有据**。
> ⇒ 结论的正确表述：**候选未被证伪，而是本实验在定参精度上未判定它。**

**判定四（两处程序缺陷，均已登记，下一轮必须改）**：
① 预登记 §3.1 的 T 网格用**固定步长 0.10**，而通过子区间宽仅 **0.041** ⇒ **窗内零网格点**；
② argmin 在实现里**先把 mean/worst 降精度到 4 位** ⇒ 造出**假并列**，再被并列规则裁决
（全精度下严格更优者被淘汰）。
⚠️ **修掉二者都不改变预登记口径下的 `ADOPT=false`**（T=1.3 仍低于该场 separation，
其上方仅有不可行的 1.4），但**"降精度造并列"是真实缺陷**，须登记。

⇒ **新登记（共性风险）**：这不是本候选独有的问题，而是**任何"单阈值 + 小样本定参"
判据**的通病——**决策边界可能落在定参分辨率的噪声里**。
**后续候选登记必须正面处理**：① 网格由定参集分位点导出；
② argmin 全精度；③ **报告"通过与否对参数取位的敏感度"**，而非只报一个点估计。

**判定五（ADR-0006 拆因被独立证实）**：只修 (a) 的**天花板**与 ADR-0006 的预言**逐值相同**，
且残差最差场是**多人素材**（属 (b)）⇒ **(a) 可修，但修好后仍不够**，
**(b) 是独立且真实的欠账**。⇒ ADR-0006 D2 的"B 入口条件"**仍未满足**。

**判定六（K5 三项全报）**：双向偏离**两个方向都有实质误差**（低估为主）；
方向相反会话分组已落盘；反平凡性显示**恒取 K=2 在主判定语料上 mean 与 worst 均优于本候选**
⇒ ⚠️ **不得**据此建议改用常数（§5.6③ 的致错盲区），**本候选未获得优于平凡基线的稳健优势**。

**附带交付（门 §5.6③ 闸门的盲区修复）**：原 `structural_safety` **只枚举 K ∈ [2,8]**，
⇒ **无法认证** K=1 档、**无法区分**"无条件恒取 K=1"与"条件性输出 K=1"。
新增 `diarization_structural_safety_k1`（K=1 纳入枚举 + 触发条件建模），
**回归锁 8 项 + 负向对照 2 组**；原闸门**未被削弱**，**两个口径并列报告**。

**边界（如实）**：① 主判定与对照语料的 `separation` **在此前探索中被看过** ⇒
**非盲测 holdout**（预登记 §7 已声明）；唯一定参集在跑数前未被看过。
② 探索性读数（窗口内 T 的表现）**不是预登记判定**，**不得**引为候选可用性证据。
③ 本 spike **只测量、不改任何生产代码**；**未做** (b)、四层剥离、含重叠口径、真机链路。
④ 执行期**一处归因错误**已自证伪并登记（AMI 基线偏离真因是 **rttm 目录选错**，
**非**算法不等价；修正后三语料基线**逐值复现归档**）。

### §5.15 (b) 判别能力 spike（**2026-10-14 已执行：两个候选同败于反平凡性门槛**）

证据：`evidence/2026-10-14-w22-m-b-discrimination/`（`PRE_REGISTRATION.md` + `spike.json` + `README.md`）。
设计门：`W2_2_B_DISCRIMINATION_PLANNING_GATE_2026-10-14.md`。**本文件不复述数字**（Rule 5）。

**做了什么**：按 ADR-0006 D5 之后的后续，做 **(b) 判别能力**——目标改为
**选到 K\***（同候选窗内 **DER 最优**的 K）。两个**无自由参数**的候选：
**B1** 秩融合（`silhouette` 秩 + `|K − k_raw|` 秩）；**B2** `crossing` 直接当 τ。

**判定一（不通过，且同败于同一门槛）**：B1 与 B2 **都不通过**，
且**都失败在 K0**——**打不过"恒取 K=3"这个常数基线**。
⇒ **不落 Core**。B1 另在**两个对照语料都退化**（与 §5.11 的 G1 同型）；
B2 两个对照都过，但那**不是优点**（见判定四）。

**判定二（对 ADR-0006 的**结构性更正**，已回写）**：
① **固定 K 时划分唯一**（1159/1159 个 (场,K) 组合只有一个 DER）
⇒ **"K 选对了但划分错了"在这条流水线上不存在**。
⇒ ADR-0006 曾把 `bjruf` 记作"K̂ 正确而划分错"——**该定性错误**，已更正。
② **K\* ≠ 真值 K**：多人素材 48 场中 **19 场**不同
⇒ 目标应为 **K\***（DER 最优），**不是真值 K**。ADR-0006 的 (b) 定义已随之更正。

**判定三（可达域很窄——本步最有用的数字）**：最好的启发式与**常数基线**
只差约 **0.002**（mean）⇒ **几乎贴在一起**；而 **K\* oracle 仍有明显余量**
⇒ **余量存在但拿不到**。⇒ 一个需要额外机制的候选若**打不过常数**，
就**没有存在理由**（这正是 K0 的用途）。

**判定四（B2 的覆盖偏差，不得选择性引用）**：B2 在主判定语料上**只覆盖 44/63 场**
（其余场 `crossing` 给出的簇数**远超 `k_max`** ⇒ 表达力不足，**不是崩溃**）；
而**未覆盖的 19 场恰是现行方案表现好的那些** ⇒
B2 的"改善"**部分来自它避开了难场**，**不得**读作"更好的准则"。

**判定五（失败机制已分开识别）**：
- **B1**：`k_raw`（= `1/w_same`）**饱和在 ≈3**、对高人数素材**系统性低估**
  （K=7 时 bias ≈ **−3.7**）⇒ 融合被往下拽，在 AISHELL-4（K=5–7）上**10/20 场更差**。
- **B2**：`crossing` 与 τ **不同尺度**——其分布（median ≈0.51）**系统偏小于有用的 τ 区间**
  ⇒ 该 τ 处簇数常达数十，远超 `k_max`。

**⚠️ 执行期发现（已修，如实登记）**：首版把 K0 的公共子集算成
"B1 与 B2 都有解"而非"**该候选**与常数 K=3 都有解"⇒ 判据**算不出来**（`K0=null`）。
我**差点**把 `null` 读成"未判定"，而它其实是**实现错误**（两者含义完全不同）。
另：B2 首轮在主判定语料**完全无解**，真因是 **`crossing` 未在归档证据中**（输入缺失），
非算法问题——与 §5.14 的"AMI rttm 目录选错"**同族**。

**⇒ 本门方向结论**：**(b) 的两条候选路径走完且不成立**；
"(b) 的余量存在（K\* oracle 有余）但现有廉价判据拿不到"。
**与 (a) 合并读**：(a) **未判定**（§5.14）、(b) **两个候选否决**
⇒ 低人数档 worst 的**两条欠账都仍开放**，且**都没有可落 Core 的候选**。

**边界（如实）**：主判定语料的 K\* 分布与常数基线表**在此前探索中被看过** ⇒
**非盲测 holdout**（预登记 §7 已声明）；唯一定参集 dev-48 的 K\* 读数跑数前未被看过；
**K\* oracle 是上界、不是可达精度**；本步**只测量、不改任何生产代码**。

### §5.16 A 路径重新裁决（**2026-10-14 已执行：ADR-0006 D2 的否决解除，转为 O2 前置裁决**）

裁决：`docs/adr/0007-w22-a-path-recheck.md`（**部分反转 ADR-0006 D2**，用户指示起草）。
证据：`evidence/2026-10-14-w22-n-a-path-recheck/`（`recheck.py` + `finding.json`，
输入可复算）。**本文件不复述数字**（Rule 5），只记**判定**。

**为什么做**：ADR-0006 D2 曾以两条理由否决 A 路径（换特征/VBx）。
其后的 §5.14（(a) 未判定）与 §5.15（(b) 两候选否决、最好启发式与常数只差 0.0017）
使那两条理由需要重新检查。

**判定一（理由① 范围过宽）**：D2 理由① "(a) 类失败不是特征问题"的读数**正确**，
但它只覆盖 **(a)**；而 (a) 已判**未判定** ⇒ **不足以否决整个 A 路径**。

**判定二（理由② 的证据越界）**：D2 引用的"oracle 过双门"，其 **oracle 所选的 K
多数场落在产品边界 `k_max=8` 之外**（含远超 8 的值）⇒
该证据证明的是"**存在一个不允许使用的解**可过门"，
**不是**"产品可达域内有余量"。⇒ **该证据不再支持"没有必须升级的证据"。**

**判定三（决定性：AMI 最差场在 K ≤ 8 内不可达）**：
用**当前评分器**、**精确控制 K**（不经 τ 网格 ⇒ 不受 §5.14"网格太粗"缺陷影响）重算：
**即使把 K 选到完美（K\* oracle），AMI 的 worst 仍越线**；
而**跨越边界**（允许 K 远超 8）后即可过。
⇒ **瓶颈是"可达域"，不是"选择准则"**。
⇒ **这不使 A 路径自动成立**——可达域的边界是 **`k_max`（产品参数）**，**不是特征**。

**判定四（两语料不对称，O2 裁决必须分开）**：同一算法、同一 K 窗，
**中文侧 K\* oracle 可达门、英文侧不可达**
⇒ 与 §5.5 判定六"中文侧变化远小于英文侧"同向。
⇒ **不得用一条结论覆盖两侧。**

**裁决（四条）**：

| # | 裁决 |
|---|---|
| **D1** | **撤回 ADR-0006 D2 的两条理由**，A 路径的**否决解除** |
| **D2** | **先做"可达域"裁决（门 §10 O2），再谈 A**——三条选项 O2-a 放宽 `k_max` / O2-b 维持并重写门语义 / O2-c 换特征；**优先顺序：改边界先于改特征**（因边界是产品参数，而"K ≤ 8 内无解"不是特征问题）；**本门不代裁**，须用户拍板 |
| **D3** | **A 路径的失败边界**：embedding 天花板很高（完美标签远优于任何聚类），但**聚类拿不到**（可分性有限：窗间重叠高、同/异均值接近）⇒ A **可能**作用于此，但**不保证过门** |
| **D4** | **ADR-0006 其余裁决不变**（D1 两条欠账 / D4 C 的前置 / §10 O6 路径） |

**对 S3 的影响（重要）**：**S3 须等 O2 裁决**——因为"门限是否可达"取决于 `k_max`；
在 O2 裁决前跑 S3，**结论会被边界而不是算法决定**。

**⚠️ 附带发现（建议更正）**：`2026-10-12-w22-d-planA-recheck/README.md` 表格的
"k-means oracle" 数值**高于**同目录 JSON 的逐场均值为**更差**的那个却标为 oracle
⇒ **两值不可能同时成立**（疑似不同 K 范围/harness 版本）。
本门**只采用逐场可复算的 JSON**，并**建议核对更正该 README 表**。

**边界（如实）**：本步**只核查证据与裁决**，**未做**：放宽 `k_max` 的实测（属 O2-a 执行）、
A 路径的任何试验、真实会议人数分布调查（O2-a 的依据）。
**零迁移 / 零契约 / 零 egress / 不改生产代码。**

### §5.17 O2-a 验证实验（**2026-10-14 已执行：放宽 `k_max` 与剔小簇都不够；瓶颈是聚类形态**）

证据：`evidence/2026-10-14-w22-o-o2a-kmax/`（`PRE_REGISTRATION.md` + `spike.json` + `README.md`）。
依据：ADR-0007 **D2**（O2-a）。**本文件不复述数字**（Rule 5），只记**判定**。

**做了什么**：预登记并执行**两个分开**的机制验证——
**O2-a1 放宽 `k_max`**（扫 8/12/16/24/32）；**O2-a2 最小簇份额**（`k_max` 固定 8，
剔份额 < s 的簇并入最近大簇）。主判定 **AMI**（唯一边界受限语料），
对照 **AISHELL-4** 与 **VoxConverse test K≤3**。

**判定一（两个机制都不通过）**：**无任何配置过 K1a/K1b**，
且 **AMI worst 在所有配置上纹丝不动** ⇒ **O2-a 出局**。

**判定二（放宽 `k_max` 几乎无效 + 在别处变差）**：
**AMI 16 场中只有 1 场改变 K**（现行准则本就不怎么顶到 cap ⇒ 放开它没有东西可放）；
且 **VoxConverse 的 worst 随 cap 放宽单调恶化** ⇒ 与 §5.10"**cap 是保护**"**同向**。
⇒ **放宽 `k_max` 不是无代价的旋钮。**

**判定三（单独剔小簇也无效）**：在 `k_max=8` 的解上剔簇**几乎没有变化**——
因为**该解本就只有 2–8 个大簇**，没有小簇可剔。
⇒ "剔除小簇"**必须作用在细切的解上**才有意义。

**判定四（真正的机制：两步耦合，且结果不是任何 dendrogram 割）**：
好解来自 **"细切（大 K）→ 按份额合并碎片"两步**；
而该结果**不是任何 dendrogram 割**（**多数场上优于** `[2,8]` 内**最好的割**）
⇒ **任何 `k_max` 扫描都够不到它**。
⇒ 这是"两个旋钮单独为何都无效"的**直接解释**。

**判定五（对 ADR-0007 判定三的再次修正）**：
ADR-0007 说"瓶颈是可达域（`k_max`）"——**不准确**。
修正后的定位：瓶颈**既不是特征、也不是产品参数**，
而是**"单次余弦割"这一聚类形态本身**。
⇒ 这是比 ADR-0007 更强的定位，且它**指向聚类流程的结构**。

**⚠️ 不得越界（本门明确）**：本实验**只**证明
"**放宽 `k_max`**"与"**单独剔小簇**"这两个**便宜机制不够**；
**未测**"细切 + 合并"作为**产品化形态**的可行性（其自由参数、稳定性、代价均未评估）
⇒ **不得**据此宣布"需要 VBx"，也**不得**据此立项——
该形态需要**自己的预登记与判定**。

**边界（如实）**：预登记 §5 已声明设计阶段看过 AMI 的 oracle K 分布
⇒ **AMI 侧非盲测**；AISHELL-4 与 VoxConverse 的对应读数跑数前未查看。
**基线可信度**：脚本在 `k_max=8` 上**逐场复现归档基线 16/16**（4 位小数与 K 均一致）。
**本步只测量、不改任何生产代码**（零迁移/零契约/零 egress）。

**⚠️ 2026-10-14 复核更正（`docs/adr/0008-w22-o2-rerecheck.md`；**本块为判定四的最终口径**）**：

判定四的基准是「**`[2,8]` 内最好的割**」。把基准换成 **τ 网格上的全局最优割（任意 K）** 后
重算同一 16 场（证据 `evidence/2026-10-14-w22-p-finecut-recheck/recheck.json`）：

| 同一 16 场 | mean | worst |
|---|---|---|
| `[2,8]` 内最优割（**判定四的原基准**） | 0.3407 | 0.6882 |
| **全局最优割（任意 K）** | **0.2196** | **0.3905** |
| 「细切 + 合并」固定规则 | 0.2577 | 0.4345 |

⇒ **三条更正**：
①「**不是任何 dendrogram 割**」**不成立**——它是**同一棵树上的一个割**，只是**不在 `[2,8]` 窗口里**；
   且**全局最优割比它更好** ⇒ **不需要新的表示族**。
②「**任何 `k_max` 扫描都够不到它**」**成立**——`k_max` 改的是 **count 上界**，**不等价于遍历 τ**；
   判定四的实现正是 count 受限，故该句对它自己的扫描成立。
③「好解来自**细切+合并两步**」**部分成立**——该两步**能到达**好解，但**不是唯一路径**；
   它是**选割的一种手段**，不是「新算法族」。

⇒ **最终定位**：瓶颈是「**从一棵树上选哪个割**」（=选择准则，§5.15 的空间），
   **不是**特征、**不是** `k_max`、**也不是**聚类表示族。
⇒ **判定二（放宽 `k_max` 无效且在别处变差）与判定三（单独剔小簇无效）不受影响**，仍然成立；
   §10 O2 的「O2-a 已出局」结论亦不变。
### §5.18 O2 再裁决复核（**2026-10-14 已执行：定位收敛到「选割」；O2 可收口**）

证据：`evidence/2026-10-14-w22-p-finecut-recheck/`（`recheck.json` + `probe-ami.json` /
`probe-aishell4.json` / `probe-vc_lowk.json`）；裁决：`docs/adr/0008-w22-o2-rerecheck.md`。
**本文件不复述全部数字**（Rule 5），只记**判定**与**对门的改动**。

**做了什么**：把 §5.17 判定四的基准从「`[2,8]` 内最好的割」换成 **τ 网格上的全局最优割（任意 K）**，
并固化「细切 + 按份额合并」为一个**可复现的非生产工具**
（`tools/quality_eval/diarization_finecut_merge_probe.py`），在三语料上重算。

**判定一（定位更正，见 §5.17 更正块）**：该划分**是同一棵树上的一个割**，
只是不在 `[2,8]` 窗口里；**全局最优割比它更好** ⇒ **不需要新的表示族**。

**判定二（可达性）**：存在**固定规则**（细切上限 + 份额合并，**参数两段都固定**）使
**AMI 与 AISHELL-4 在两种重叠口径下都过门**，且其输出 **K 只有 2–4**
⇒ **门限在产品域 `k_max=8` 内可达**（与 ADR-0007 判定三相反）。

**判定三（代价，必须与判定二同读）**：
① 该固定规则在 **VoxConverse 低人数档退化**（mean 0.1739 → 0.2514）；
② 它**输出 K=1 的精确率仅约 1/3**（改对时 DER 0.03，改错时 mean 0.30 / worst 0.70）
⇒ **(a) 表达能力的这一修法有明确假阳性代价**，属产品裁决（ADR-0008 D2-c）。

**判定四（参数分辨率，本门最该被记住的一条）**：过门区间**是峰不是高原**
（细切仅 40–48；份额仅 0.05–0.10），且**合并的 guard 是规格的一部分**
（去掉 guard 会在低人数档输出 K≈40、DER 0.98）⇒ §5.14 判定四登记的「单阈值+小样本定参」共性风险
**再次命中**；任何后续候选**必须报通过区间与分辨率**，不得报点估计。

**判定五（反平凡性）**：现行基线在 AMI 上的过门**靠欠分割偏置**（K ≤ 真值−2 达 10/16），
新形态在中文侧偏置更重（13/20）⇒ **两者都不具备「分得更对」的主张**；
登记候选须与「恒取 K=c」常数基线对照（§5.15 的 K0）。

**对门 §10 O2 的处置（ADR-0008 D1，**2026-10-14 已批准**）**：
维持 `k_max=8`、**不放宽**（§5.17 判定二已证放宽有害）、**不降级/不重写门语义**
（判定二证门限可达）⇒ **O2 从「产品边界裁决」转为「已裁决项」**。

**对 §6 S3 的处置（2026-10-14 已批准解封）**：**S3 不再被 O2 阻塞**（「门限是否可达」已有答案）；
**新增前置（2026-10-14）**：S3 开跑前，须先接受本门**新一轮预登记实验**的判定结果
（`evidence/2026-10-14-w22-q-finecut-prereg/`）；若该实验不通过，S3 仍按**现行准则**跑，
**不得**把未通过的候选形态带进生产链路。
S3 须**两种重叠口径并报**，且按 ADR-0006 D1 **分别报 (a)/(b)**。
### §5.19 「细切 + 按份额合并」预登记实验（**2026-10-14 已执行：字面口径 ADOPT=true，但判据失守 ⇒ 不建议落 Core**）

证据：`evidence/2026-10-14-w22-q-finecut-prereg/`（`PRE_REGISTRATION.md` + `tuning-freeze.json` +
`judging.json` + `sensitivity.json` + `RESULTS.md`）；裁决：ADR-0008 D2-a / D3-a。
**本文件不复述全部数字**（Rule 5），只记**判定**。

**做了什么**：严格按门 §5.18 / ADR-0008 §4 的七条硬约束——**定参集 = AMI dev**（18 场，本仓从未使用），
**判定集 = VoxConverse 未读子集**（56 场，与已读集合**交集为空**），**对照 = AISHELL-4**；
参数在定参集上冻结（`Kf=24, s=0.05`，13/32 可过点中 margin 最大）后才首次接触判定集。

**判定一（字面通过）**：主判定 **M1**（不劣于现行，两口径）与 **C1**（中文不劣化）**通过**；
**采用条件 M1 ∧ M2 ∧ C1 = true**。该结果**不得事后推翻**（预登记 §4）。

**判定二（判据失守，本门最重要的一条）**：**M2（反平凡性）不成立为判据**——
**现行准则同样优于「恒取 K=2..5」常数基线**（NC4 实测）⇒ 「通过 M2」**不构成**「优于现行」的证据。
⇒ 预登记 §5.1 的 M2 **须在下一次预登记中替换为「与现行准则直接对照」**。

**判定三（NC1 无区分力）**：**去 guard 对照在本配置下从未触发**（三条语料的读数与带 guard 逐位相同）
⇒ §5.18 判定四登记的「guard 是规格的一部分」**仍然成立**（`Kf=40` 配置下实测 DER 0.98），
但**本配置**下它不构成一条对照。**下一轮预登记须给 guard 单独构造触发条件**。

**判定四（定参不稳健 + 两集不相交）**：**M5**（定参 margin 前 5 名逐判）5 点中 **1 点不达 M1**；
**NC5** 显示 AMI test 上仅 5/32 可过、且**会冻结到另一个点**，而 dev 冻结点在 AMI test 上**不可过**
（margin 为负）⇒ **dev 与 test 的可用区几乎不相交**。
⇒ 与 §5.14 判定四 / ADR-0008 发现四登记的「单阈值 + 小样本定参」共性风险**同型，再次命中**。

**判定五（产品含义）**：该形态的收益**只出现在真值人数 ≥7 的档**（判定集 7–9 档 13/20 改善、10+ 档 10/16 改善），
却在 **4–6 档净损失**（9 好 11 差）；且在**参考集 VoxConverse test K≤3（产品主场景）上大幅退化**（47/63 更差），
**K=1 分支退出**（ADR-0008 发现五的 (a) 修法**在冻结配置下不存在**）。
⇒ **该形态不能同时服务低人数档与高人数档**；这是**产品取舍**，不是可以靠调参抹平的差距。

**处置（2026-10-14 用户已批准）**：**不落 Core**——理由**不是** M1/M2/C1 未过，
而是 ① 判据失守使「通过」的证据强度不足；② 定参不稳健、无法冻结可信操作点；
③ 低人数档退化触及产品主场景。**S3 仍按现行准则开跑**（§6 的 S3 解封条件维持）。
**§6 切片的推进纪律（本门新增，防"绕过精度门直接进产品"）**：
S3 的精度门必须在**生产链路上**（`SpeakerDiarizationService`，而非 spike harness）
对两语料跑出 DER，**且满足 §5 门限**，才允许进入 S4/S5。
S2 已把"生产链路可跑通"证明到**机制层面**（真实 ffmpeg + 真实 Silero + 真实 CAM++），
**但没有跑 DER**——故 **S2 完成 ≠ 精度可用**，两者不得混读。

## 9. 不做什么（边界）

- **不做 W2.3 机位切换规划器**（依赖本包 + W2.1，另行立项）；
- **不做说话人身份识别/命名**（本包只产**匿名说话人编号** + 轮次）；
- **不做实时**（离线作业，与 `beat_analysis` 同型）；
- **不引入新的 egress 面**（全本地；模型经受信直链 + sha256）；
- **不引入 C++ 扩展**（fbank 走纯 numpy，已证逐值等价）。
