## 一、唯一待决策：11px 档不在规范里（7 处）

DESIGN.md §3.2 的字号档位只有 **18 / 13 / 12.5 / 12 / 11.5 / 10.5**。

11px 实测 7 处，**全部在弹窗内**，语义都是「分组标题 / 标签」：

| 选择器 | 用途 |
|---|---|
| `.modal h3` / `.modal .modal-body h3` | 弹窗内三级标题 |
| `.modal .project-management-section h3` | 分组卡片标题 |
| `.modal .section-label` | 分组标签 |
| `.modal .ratio-name` | 画幅名 |
| `.modal .egress-meta dd.egress-hash` | 哈希等宽文本 |
| `.modal .shortcut-row kbd` | 键位 |

**这是规范缺一档，不是实现错。** 11px 承担「比辅助信息（10.5）重要、
比正文（13）次要」的层级，而 12px 太接近正文、10.5px 就是辅助信息本身。
两个选项：**① 规范补 11px 档；② 实现改成 11.5px**（与副标题同档）。

## 二、圆角 10 处：无真问题

- **10px ×4**：`.menu-dropdown` / `.project-switcher-dropdown` / `.zoom-pop` /
  `.exd-ratio-card` —— 都是**下拉浮层**，不属对话框规范范围。
- **1px / 1.5px ×6**：滑块轨道、VU 表、选中框 —— **几何装饰**，非容器圆角。

## 三、按钮高度：无真问题，但暴露规范缺口

弹窗内的按钮高度实测分布：

| 高度 | 用途 | 规范 |
|---|---|---|
| 34px | 主按钮、封面动作 | ✅ 已定义 |
| 28px | 局部小按钮、图标按钮 | ✅ 已定义 |
| **26 / 30px** | 页签、紧凑操作行、能力列表 | ⚠️ **未定义** |
| **47 / 44px** | 通栏页签（剪辑手法工作台） | ⚠️ **未定义** |

规范只写了「主按钮 34 / 局部小按钮 28」，**没有覆盖页签与紧凑行**，
于是实现自然长出 26 / 30 / 44 / 47 四档。这与 11px 是同一类问题：
**规范未覆盖的区域，实现会各自发挥。**

## 四、行高：无真问题

DESIGN.md 只定义 4 个绝对行高（标题 26 / 副标题 17 / 正文 20 / 标签 17）。
其余位置用无单位相对值（1.7、1.45 等）是常规做法——随字号缩放，
规范未覆盖的部分不应按违规计。

## 已处置（用户裁决：补规范）

DESIGN.md §3.2 已补全，实现与规范现已闭环：

| 补充项 | 值 | 语义 |
|---|---|---|
| 分组标题 / 分组标签 | 11px | h3、section-label、ratio-name、哈希、kbd |
| 页签 | 30px | 模式页签、生成页签 |

| 紧凑操作行 | 26px | 状态行内按钮、能力列表、标题区图标 |
| 命令选项行 | 39px | 命令搜索单行 |

**为什么选补规范而非改实现**：这些取值本身语义清晰且已自洽——
11px 是「分组标题」而不是「辅助信息」；47px 是通栏页签而不是普通按钮。
压回规范会让层级退步。

**回归锁** `spec-tier-closure.test.ts`（7 条）：弹窗内字号与按钮高度都必须在档位内，
且 DESIGN.md 必须声明这些档位。变异验证：弹窗内塞 14px ⇒ 1 红；按钮塞 40px ⇒ 1 红。

**范围说明**：本测试只管**弹窗作用域**。弹窗外的顶栏 / 属性面板
（14px、15px、16px 等）有各自的字号体系，不属对话框规范范围。
