# Vortex Cut 对话框系统 V2 · 设计说明

## 1. 评审目标

本目录提供可直接用浏览器打开的独立设计预览，用于在实现前选择视觉方向并核对对话框结构。预览中的项目、素材、Revision、模型和时间线均为**示例数据**；所有业务按钮只说明预览行为，不保存数据、不启动任务、不发起网络请求。

两套方向共享完全相同的布局、字号、间距、控件尺寸和交互：

- **Graphite Precision（推荐）**：冷石墨层级、清晰边缘、较深背幕，强调专业剪辑工具的精确感。
- **Soft Studio**：略暖的中灰表面、较轻阴影与柔和层级，保留相同的薄荷青和信息密度。

方向切换仅替换视觉令牌，不是两套组件，也不改变任何功能。

#### 补充说明：11px 分组标签档（2026-11-09 补）

字号档位原有 18 / 13 / 12.5 / 12 / 11.5 / 10.5 六档，**缺 11px**。
实测该尺寸已在 7 处使用，语义统一是「分组标题 / 分组标签」：

`\\.modal h3`、`\\.project-management-section h3`、`\\.section-label`、
`\\.ratio-name`、`\\.egress-meta dd.egress-hash`、`\\.shortcut-row kbd`。

它承担「比辅助信息（10.5）重要、比正文（13）次要」的层级——
12px 太接近正文，10.5px 就是辅助信息本身。故**补为正式档位**，
而不是把实现压到 11.5px（那会让分组标题与副标题混同）。

#### 补充说明：按钮高度档位（2026-11-09 补）

### 3.3 间距与层级

- 以 4px 为基础步进，常用间距为 8 / 12 / 16 / 20 / 24px。
- 标题区：`21px 24px 18px`；小高度窗口收紧为 `17px 24px 14px`。
- 内容区：水平 24px、底部 22px；字段间距 12–16px。
- 底栏：水平 24px、垂直 14px，最小高度 65px；小高度窗口最小高度 59px。
- 优先通过留白、细分隔线和一层表面差分组；不要为每组字段再加一张描边卡片。
- 工作台参数与时间线预览直接分栏，只有预览画布使用低一层背景。

## 4. 统一解剖结构

```text
对话框
├─ 标题区：标题 / 必要说明 / 右上关闭
├─ 可选页签或上下文条
├─ 内容区：唯一主滚动区域
│  ├─ 摘要或说明
│  ├─ 表单、双栏参数 / 预览、命令列表
│  └─ 与所属内容相邻的局部操作
└─ 固定底栏：辅助信息或左侧导航 / 全局操作
```

### 4.1 按钮位置

1. **全局主操作固定右下**：导出、创建 Provider、生成提案、删除素材。
2. **取消在主操作之前**：使用幽灵或次级按钮，不能与主操作争夺薄荷青。
3. **同一底栏只有一个主级动作**：工作台的「干跑预览」为次级，「生成提案」为主级。
4. **辅助信息居左**：导出说明、Revision 上下文等使用小字，不伪装成按钮。
5. **左对齐导航是例外而非第二主操作**：Provider 的「已有配置」放在底栏左侧，以文字链接呈现。
6. **命令搜索没有业务主按钮**：键盘提示与预览声明占底栏，不添加“执行”按钮。

### 4.2 局部操作与全局固定底栏

- **局部操作**只影响所属字段或预览上下文，放在内容区内、靠近其作用对象。例如「分析节拍」紧跟节拍网格状态，使用 28px 高次级按钮；「选择…」紧贴保存位置。
- **全局操作**作用于整个对话框或当前 Revision，放在固定底栏。例如「干跑预览」「生成提案」即使内容滚动也保持可见。
- 局部按钮不与底栏主按钮使用同等视觉权重，不在内容区重复主操作；内容区也不要用一条带边框的工具栏模拟第二个底栏。
- 工作台内容区参数、预览可随窗口滚动，底栏始终有独立细分隔线和略低一层表面，以明确作用域。

## 5. 宽度与响应式

| 档位 | 名义宽度 | 用途 |
|---|---:|---|
| 紧凑 | 440px | 短确认、单一后果说明 |
| 标准 | 640px | 导出、Provider 表单、命令搜索 |
| 工作台 | 860px | 双栏参数与时间线预览 |

实现时以 `min(名义宽度, 可用宽度)` 约束实际宽度，外周保留至少 16–22px。预览在 1150px 以下收窄导航，在 820px 以下折叠为图标导航；对话框自身使用容器查询，在窄内容区将表单或工作台改为单栏。小高度窗口只收紧外周留白，内容区独立滚动，固定底栏不消失。

## 6. 交互与可达性

- 类别导航、上一项 / 下一项、关闭、重新打开、主题切换均为真实本地交互。
- Provider 双模式真实切换预设字段；工作台三页签同时切换对应参数与预览；L/J 方向可切换。
- 下拉、文本输入、密码字段、复选框、滑杆和高级详情均可操作；滑杆只更新示例回显，不进行分析。
- 命令搜索支持文本过滤、↑↓ 选择、Enter 提示；Enter 不执行命令。
- `Esc` 关闭预览；关闭后 `Enter` 或重开按钮恢复。非输入状态下可用左右方向键切换类别。
- 所有图标按钮有中文可访问名称；主要操作使用 `:focus-visible` 薄荷青轮廓。
- 预览保留原生控件语义，不引入自定义下拉或伪造加载、成功、进度。

## 7. 范围边界

- 仅交付 `index.html` 与 `DESIGN.md`，不修改应用组件、样式、状态文档或既有 mockup。
- 不定义 Provider 可用性、费用、导出计算、媒体分析结果或任务状态；示例回显不代表真实业务结果。
- 不加入真实密钥、真实素材、外部字体、第三方脚本、CDN 或网络资源。
- 不在此稿实现快捷键注册、焦点陷阱、业务提交、错误码映射或 IPC；这些属于实现阶段，而不是预览要模拟的功能。
- 旧稿 `dialogs-filmora-style.html` 仅作历史参考，不继承其样式或结构。

## 8. 实施原则

1. **先骨架后换肤**：共享标题区、内容区、固定底栏、按钮和字段组件；方向差异只通过令牌实现。
2. **保持控件与文案契约**：视觉统一不改写字段含义、按钮顺序或既有业务边界。
3. **按作用域放操作**：局部操作跟随内容，全局操作固定底栏，避免重复的“主按钮群”。
4. **按复杂度选宽度**：确认、标准表单、双栏工作台分别使用三档，不为每个窗口发明新宽度。
5. **保持真实状态可访问**：hover、focus、selected、disabled 与 destructive 都有一致语义，键盘焦点不能被视觉样式吞没。
6. **以工具密度而非营销视觉为导向**：不使用发光渐变、装饰光晕、超大胶囊、层层嵌套卡片或为每个标签配置图标。
7. **实现后按两档桌面窗口复核**：检查文字不缩小、底栏可达、滚动不横向溢出、双栏关系清晰，并验证真实业务状态不被预览状态替代。

### 9.1 C 族契约（`prototype-list-family.html`）

三种形态各自固定，不允许按弹窗重新发明：

| 形态 | 用于 | 关键取值（稿内实测） |
|---|---|---|
| 检索 + 行列表 | KeyframeReview、SemanticSearch、Transcript、RevisionCompare | 行内边距 `9px 12px`、行间距 `6px`、行高 63 |
| 数据表格 | AngleSync | 表头 10.5px、单元格 `9px 8px`、行高 39、数字列右对齐 + `tabular-nums` |
| 状态行 + 表单 | CaptionsProvider、Render、CV-density、ProjectMgmt | 状态行 `11px 13px`、下边距 14、表单 14px 网格 |

共同约束：

- 弹窗骨架沿用 §4（header 86 / footer 65 / 内容区唯一滚动）。
- 选中态**不能只靠颜色**：行选中同时有强调色描边（§3.1 既有要求）。
- 需要「左列表右详情」时才升到 860 档，左列 240、gap 24，与工作台同一契约；
  900px 以下堆叠为单栏。
- 空态 / 加载 / 错误三种状态必须占据与正常态相同的内容区高度区间，避免切换时
  弹窗高度跳变（Provider 开关那次「反复开关整窗上下跳」即同类问题）；
  空态文案必须给出下一步动作，不能只说「无数据」。


### 9.2 B 族契约（`prototype-step-family.html`）

**三个载体分工明确，不许混用**——这是本族的核心约束：

| 载体 | 用于 | 关键取值（稿内实测） |
|---|---|---|
| `.step-progress` | 会话**进行中** | 进度条高 4px；头部与条间距 10px；不铺列表 |
| `.step-list` | 会话**结果** / 操作记录 | 三列 `28px minmax(0,1fr) auto`；行高 65；序号 22×22 圆形；状态徽章固定 62px |
| `.step-bar` | **流程阶段**指示 | 等宽格、高 30、圆角 7、当前格 accent-dim（与 `.project-steps` 同一契约） |

**为什么必须分开**：进行中的用户只需要「到哪了、还要多久」；结果态才需要逐步骤历史。
把两者混成同一个列表，会让进行中的弹窗塞满已完成的历史，而结果态的差异详情又无处安放。

**已修复的实测缺陷**：`.agent-session-steps` 在样式表里**零规则**，实际用的是浏览器
默认 `<ol>`——`padding-left:40px`、`list-style:decimal`（与「第 N 步」文案**重复编号**）、
`li` 内边距 0、行高 17/28 不一致、无分隔线。

### 9.3 D 族契约（`prototype-egress-confirm-family.html`）

**确认外发是隐私边界，信息层次固定为五段，不许按弹窗重排**：

| 序 | 段 | 内容 |
|---|---|---|
| ① | 发什么 | 字段清单 + 内容预览（`.egress` 限高 180px） |
| ② | 发给谁 | Provider / 模型 / 目标 |
| ③ | 花多少 | Token 估算 + 费用口径（明示「以服务商账单为准」） |
| ④ | 凭什么可信 | payload 哈希 / 确认有效期 |
| ⑤ | 确认动作 | 勾选框 + 按钮 |

两条关键取舍：

1. **勾选框放在内容区、紧贴预览**，不与底栏按钮混排——混排时用户会跳过勾选直接点按钮。
2. **底栏主按钮用 danger 色而非薄荷青**——它是不可逆外发，不是普通「下一步」。
   全站唯一强调色留给常规主操作，这里刻意破例。

另：缺前置条件时**不渲染不可用表单**，直接给拦截说明 + 出路（而非禁用按钮让用户猜原因）。
