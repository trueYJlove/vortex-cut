## 关于「卡顿片段自动补渲染」的决定：不做

原本计划借鉴 openfilm 的 `preview-cache`：播放统计掉帧 → 后台渲染滞后区间 → 播放时用渲染产物替换。

实测后判定**不需要**，理由：

1. 代理路径解码 p95 已降至 7.2 ms，仅为实时预算的 22%，没有"画不动"的区间可补；
2. 补渲染必须给 Core 增加区间渲染能力与新的 `render_artifacts.kind`，会触发迁移版本变化并需同步 `STATUS.md` §1 —— 与本长任务"不改 Python Core 架构"的硬约束冲突；
3. 在已有 4.5 倍性能余量下引入跨进程渲染、磁盘缓存、区间替换的复杂度，属于 YAGNI。

若未来出现代理仍画不动的场景（如大量 3D/特效合成），再按此记录重启该项，并走"扩展 Core 能力 + 迁移 + STATUS 同步"的完整流程。
