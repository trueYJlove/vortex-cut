# 编辑器 UI 与交互改造汇总（2026-11）

> **历史实施与验收摘要。** 本文合并 2026-11-10 同一轮 UI 改造的阶段稿；只记录当轮方案、测量和验收。当前能力边界见 [`STATUS.md`](../STATUS.md)。后续正式视觉验收与浅色主题治理仍分别由 P221/P224 的记录支撑：`TIMELINE_PARITY_2026-11-11.md`、`LIGHT_THEME_FIXES_2026-11-11.md`。

## 设计与实现决策

| 区域 | 合并后的设计结论 |
|---|---|
| 预览播放 | 播放时以 `AudioContext.currentTime` 为主时钟，播放头用 `t + elapsed × rate` 外推；用户 seek 与播放回报分开处理。合成帧与 UI 时钟解耦，避免每帧驱动 React 重绘。 |
| 大素材代理 | 按素材尺寸自动选 540/720/1080 档，用户可关闭自动代理或指定档位。测试素材 3840×2160 下，720p 代理解码 p95 从 190.4ms 降至 7.2ms、上传 p95 从 935.2ms 降至 5.3ms；因此当轮否决额外的 Core 区间补渲染方案。 |
| 时间线 | 标尺 20px；轨道行高按当轮规格为视频 56px、音频 44px，行间距 2px。后续 P221 复核将工具栏规格改为 34px；历史数值不可拼成当前规格。 |
| 主题与设置 | 三态主题（浅色/深色/跟随系统），持久化用户选择、系统主题变化跨窗口同步；设置页采用左侧导航、分区和搜索。DOM 与 Canvas 共用语义色令牌，不能只改 CSS 而遗漏 Canvas 绘制色。 |
| 主界面拆分 | 样式令牌与主题结构完成分层；组件拆分只覆盖当轮识别出的独立区域，顶栏与三栏仍因耦合较深而未拆。后续拆分需先明确状态边界，不能把该轮记作整体组件化完成。 |
| 画布命中 | 画中画 9 个手柄曾有 2 个被遮挡/错位；按层级与命中几何修复后 9/9 可用。交互排查使用 `elementFromPoint` 验证真实命中目标，而非只看视觉位置。 |
| 标记与区间 | 标记行浮在轨道顶部，高 16px；时间区间通过 Shift+拖动创建。该轮标记只存 localStorage，不随 Revision 回滚；区间只表示选区，没有绑定导出、删除或循环操作。 |

## 验收交叉核对

| 验收项 | 结果与依据 |
|---|---|
| 代理路径播放流畅度 | 4K60 素材实测零丢帧；720p 代理解码 p95 7.2ms，低于 33.3ms 帧预算。 |
| 时间线、预览与画布交互 | 14 类主界面控件命中扫描 0 blocked；窄窗 1024×720 无横向溢出；9 个画中画手柄均可命中。图片素材进入合成预览后，点选端到端约 102ms。 |
| 播放头时钟与音画同步 | 当轮 12/12 采样持续前进；音频时钟驱动下位置增量稳定在 12–13px；连续拖动 24/24 次更新画面。 |
| 主题与设置 | 浅色/深色/系统主题切换及跨窗口同步通过真实桌面验证；设置页导航、搜索和分区在窄窗下可用。 |
| 回归 | 当轮记录为桌面 143 文件/1327 项通过，typecheck/build 通过。此数值是当轮记录，不代表当前测试总量。 |

## 明确保留的边界与待决策

- 时间区间该驱动什么操作当时未定，因此没有接入导出、删除或循环播放。
- 标记未进入 Core 文档与 Revision，跨机器迁移、撤销和重做不覆盖标记。
- JKL 穿梭、逐帧步进等快捷键属于后续产品选择，不应从视觉对齐工作推断为已交付。
- 主题/尺寸精调若与后续 P221/P224 记录冲突，以 STATUS.md 登记的正式验收记录为准。

## OpenFilm 对照的修正结论

2026-11-10 的早期差距清单把若干已存在的时间线能力误判为缺失；后续通过真实交互和画布像素核验纠正。那轮真正新增的是标记行和时间区间两项；标记的存储边界、区间尚未绑定操作见上表。吸附提示、框选、边缘滚动、锚点缩放和轨道排序属于既有能力，不应从早期 grep 结果推断为未实现。该轮留下的方法教训是：先验证真实交互，再判断能力缺失。
