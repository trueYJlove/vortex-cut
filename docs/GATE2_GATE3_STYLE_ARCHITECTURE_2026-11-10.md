## GATE-2 样式架构分层（已完成）

### 做了什么

1. **删除 30 个 100% 被下级覆盖的死令牌**。原文件第 972 行有整块弹窗令牌
   （`--dlg-bg` / `--dlg-primary` / `--dlg-fs-*` 等），但文件末尾"令牌终值"
   块重新定义了同名 30 个变量，逐条生效。用 `comm -23` 比对两个块的变量集合，
   第 972 行的独有变量数为 **0** —— 该块对渲染输出零影响，属纯死代码。
   删除后在同一位置留下注释说明原因，避免后人再次往那里加令牌。
2. **`--ws-*` 令牌从 `:root` 收紧到 `.editor-shell`**。这批值的语义是
   "主工作区材质"，挂在 `:root` 会让它们对弹窗子树同样可见，日后误用即可
   穿透到已冻结的弹窗。收紧后任何 `--ws-*` 消费者必然在工作区内。
3. 因令牌收紧，`body` 取不到 `--ws-*`，改为等价字面量 `#101518`（同一色值）。

## GATE-3 主界面组件拆分（部分完成，边界已记录）

### 已抽取

`WorkspaceFooter`（`src/app/workspace/WorkspaceFooter.tsx`）：底栏整块搬出，
只读 17 个 props、无本地状态、无副作用。DOM 结构、类名、
`role`/`aria-label`/`title` 全部逐字保留。

**验收**：`pnpm typecheck` 通过；`pnpm test` 143 文件 / 1327 测试通过。
11 个测试直接挂载 `App` 并按可访问名称
（"保存状态" / "Core 连接状态" / "设置" / "多平台导出" 等）取元素，
全部继续通过，证明可访问契约未变。

### 未抽取：顶栏与三栏，以及原因

`App.tsx` 现有 **265 个 state/ref/effect/callback/memo**、**28 个 `useEffect`**，
11 个测试直接挂载 `App` 组件。继续拆分不是"搬 JSX"，而是要把这些状态
重新组织成 props 或 context——那是架构级手术，与"行为不变"的验收标准直接冲突。

具体到顶栏：菜单渲染依赖 `menuItems` / `activeMenu` / `dropdownIndex` /
`menuButtonRefs` / `menuActionRefs` / `handleMenuBarKeyDown` / `isMenuDivider` /
`isMenuGroup`，项目切换器还依赖 `projectSwitcherRef`（外部点击关闭）。
抽出去要把这十余项打包成接口，而其内部逻辑仍需留在 `App`。

**判定：不做。** 依据是收益/风险比——抽取不改变任何用户可见行为，
却要动 265 个状态的生命周期。真正的可维护性收益来自"减少状态总量"，
那是另一个量级的工程，应当作为独立立项，而不是塞进 UI 改造里。

### 若要继续拆分，前置条件

1. 先把 `App` 的 265 个状态按职责聚类（播放 / 时间线 / 素材 / AI / 弹窗），
   能下沉到各自 hook 的先下沉；
2. 状态收敛后，顶栏与三栏才具备"薄壳 + 纯展示组件"的抽取条件；
3. 每步都必须保持 11 个挂载 `App` 的测试通过，作为行为不变的硬证据。
