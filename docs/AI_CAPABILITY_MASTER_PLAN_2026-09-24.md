## 0. 为什么需要这份文档

2026-09-24 的方向讨论暴露了三类漂移风险。本文件的首要作用是堵住它们。

**漂移 1｜认知漂移：把"AI 粗剪"等价于"LLM 从转录里选段"。**
代码现状确实如此（Stage 2A 唯一通路），但这是**五条通路里的一条**。行业成熟产品的另外几条
（视觉叙事、卡点、多机位、声画分离）各有独立信号源与决策规则，其中多数**不需要 LLM**。
一旦团队把现状当作定义，后续每一单都会围绕"如何让 LLM 选得更准"打转，而真正的缺口在别处。

**漂移 2｜能力漂移：没有冻结的目标能力集，每单各自定义"完成"。**
同类问题已经发生过一次：`AI_PATCH_OPERATIONS` 因"差集"写法从 13 种被动漂移到 24 种
（已由 `AI_WHITELIST_EXPANSION_PLANNING_GATE_2026-09-22` 治理为显式冻结 + 三处同步准入）。
能力清单若没有同样的冻结纪律，"与成熟软件对齐"会变成不可证伪的口号。

**漂移 3｜阶段漂移：`docs/PROJECT_RELEASE_STATUS.md` 已失真。**
该文档仍停在基线 `38bdcfd`、分支 `codex/stage8-post-release-planning`、"下一阶段不新增业务功能"，
而实际分支为 `ai/stability-polish`，AI 线已合入并推进到白名单治理、AI 面板 diff 浏览、
导出弹窗全链路。下一个接手的会话（人或 AI）会据此误判当前阶段。已登记为 W0.1。

## 1. 目标判定标准："与成熟软件基本对齐"的可证伪定义

**没有这一节，本方案不可验收。** 七条维度全部需要量化门，逐项可验证。

| 维度 | 判定标准 | 验证方式 |
|---|---|---|
| **C1 能力覆盖** | §4 能力矩阵中所有 **P0** 项可用且通过各自验收 | 逐项 e2e（真实素材 + 真实 provider） |
| **C2 理解深度** | 支持自然语言检索画面语义（对标 DaVinci IntelliSearch） | 检索评测集命中率 |
| **C3 剪辑语法** | A 类四手法（卡点 / L-J cut / 跳切 / 多机位）各自产出**可采纳**提案 | 合成 fixture 断言 + 真实素材端到端 |
| **C4 质量** | 自有评测集上粗剪"**结构可用率**"达标——用户只做微调、不改结构 | 人工标注基准（§11） |
| **C5 性能** | 素材分析 p95 ≤ 10s/分钟源（1080p30 档）；语法层提案 < 1s | 性能门 + evidence 归档 |
| **C6 稳定性** | script 与 json_schema **双适配器通路**均可用；探测无挂起毒化 | 真实 provider 矩阵复跑 |
| **C7 可解释** | 每个 AI / 语法决策可追溯到具体信号或规则来源 | 提案 payload 与决策依据落盘检查 |

**C4 是"成熟"的真正标志。** 前六条是能力，C4 是质量。没有 C4，"能跑"和"能用"分不开——
这正是当前状态（真实样本 3 条素材、其中 2 条切点为 0）的问题。

**C6 是当前最实的短板。** `AI_VALIDATION_REPORT_2026-09-20.md` 记载：json_schema 类适配器
在网关层被 `oneOf` 拒绝（400），**script 类适配器是唯一通路**。这意味着 provider 兼容面
比设计时窄，是产品级风险而非实现细节。

### 2.2 缺口清单（本方案要解决的）

| 缺口 | 证据 | 影响 |
|---|---|---|
| **无"剪辑语法层"** | 信号层与 LLM 之间无中间层；`prepare` 直接由 LLM 出候选 | 所有确定性手法无归属，全靠 LLM 猜 |
| **CV 只是兜底，不是一等公民** | `candidate_source: auto` = 有转录用转录、否则 CV | CV 信号无法参与转录素材的排序与决策 |
| **无节拍分析** | 全 core grep 无 `beat`/`bpm`/`downbeat` | 卡点完全缺失 |
| **无说话人分离** | 全 core grep 无 `diariz`/`speaker`/`active_speaker` | 多机位、说话人驱动剪辑完全缺失 |
| **无声画链接模型** | 全 core grep 无 `linked`/`link_group`/`group_id` | L/J cut 与多机位均受阻；后续 trim 不联动 |
| **L/J cut 有原语无 op** | `insert_asset_clip(as_audio)` + `position_clip` 可表达，但 `insert_asset_clip` 在 AI 白名单外 | AI 做不出 L/J cut |
| **无画面语义** | Layer 0 无任何语义信号 | 理解深度与行业头部存在结构性代差 |
| **无质量评测 harness** | 无评测集、无基线指标快照；`_select` 权重"以测试钉死"但真实样本 3 条 | 一切权重/提示词调优无依据 |
| **性能门 4K60 档未标定** | 1080p50 档已达标（4.3s/分，`a349866`），但 4K60 从未测量 | 高分辨率素材的现实可用性未知 |
| **无工作单编排** | `agent_session.py` grep 无 `worklist`；仅"失败重试循环" | ADR-0003 D2 承诺的步骤链未落地 |
| **provider 兼容面窄** | json_schema 适配器被网关 `oneOf` 拒绝 | 商业可用性风险 |
| **文档阶段失真** | `PROJECT_RELEASE_STATUS.md` 停在 `38bdcfd` / stage8 | 后续会话误判阶段 |

### 2.3 硬架构约束（写方案时必须遵守，否则会做出跑不通的设计）

- **V1 是唯一权威视觉轨**（`rendering/ffmpeg.py:168`）。非 V1 视频轨一律按**画中画 overlay** 处理
  （`rendering/ir.py:353`）。**多机位不能用"多轨切激活轨"表达。**
- **转场只作用于 V1 相邻片段**（`timeline.py:1686`）；**关键帧只允许 V1**
  （`rendering/ir.py:115`）。多机位必须展平到 V1，否则拿不到转场与动画能力。
- **时间线文档是 JSON**（存在 revision 内），不是关系表。新增 clip 字段 = 文档 schema + 契约变更，
  **不是** SQL 迁移；只有分析类数据（信号/节拍/embedding）才需要迁移。
- **迁移已到 v22**（`database.py:911`）。新分析表从 v23 起。

### 5.2 三条组合路径（**这是本方案的核心结构**）

| 路径 | 组成 | 适用能力 | egress | 延迟 | 现有机制 |
|---|---|---|---|---|---|
| **P-A 纯语法** | 信号 → 规划器 → patch | 卡点 / L-J cut / 跳切 / 多机位 | **零** | < 1s | 复用采纳链，**无需 consent** |
| **P-B 纯 LLM** | 信号/转录 → payload → LLM → patch | 蒙太奇 / 自然语言修改 / 转录选段 | 有 | 秒~十秒 | Stage 2A/2B/AI-1 现成 |
| **P-C LLM 编排语法** | LLM 决定用哪个规划器与参数 → 规划器出 patch | 复合任务（"剪个带卡点的 Vlog"） | 有（仅编排意图） | 中 | 需 W1.1 + W4.1 |

**P-A 是一个被低估的产品优势**：卡点、L/J cut、跳切是**本地确定性计算**，
不发送任何数据，因此**不需要 egress preview、不需要 consent 对话框**，可以做成
"点一下，1 秒出提案"。行业产品里这些功能之所以要联网，是因为它们把决策交给了云端模型；
Vortex Cut 的架构允许它们在本地完成。**这是 I1 隐私承诺反过来带来的体验优势**，
应在产品叙事中明确占据。

### 5.3 剪辑语法层的设计约束（冻结）

1. **纯函数**：输入（信号快照 + 目标 + 基线文档）→ 输出（TimelinePatch + 决策依据）。
   **同输入必须产出逐字节相同的 patch**，可断言、可复算、可预览。
2. **零网络**：模块内不得出现任何网络调用（单测以 monkeypatch 断言 egress 为零）。
3. **决策依据落盘**：每个 patch 附带 `rationale`（命中了哪条规则、依据哪个信号、
   哪个参数），服务 C7 可解释性与 D5。
4. **统一输出格式**：一律产出 TimelinePatch，走既有采纳链。**不新增交付机制。**
5. **不写时间线**：规划器只产出提案，采纳由用户触发（I2）。
6. **工具化**：每个规划器同时暴露为可被编排层调用的工具（名 + 参数 schema + 前置条件），

## 11. 质量评测体系（横向，W0.4 起贯穿全部 Wave）

### 11.1 评测集结构

| 分档 | 用途 | 最小样本 |
|---|---|---|

| 音乐素材 | E4 卡点质量 | ≥3 素材（不同 BPM） |
| 长 GOP 素材 | W0.2 采样策略回归 | ≥2 素材（GOP > 5s） |

### 11.2 指标定义

| 指标 | 定义 | 归属 |
|---|---|---|
| 切点检测 P/R | 与人工标注场景切点的精确率/召回率 | U2 |
| 召回相关性 | nDCG 或人工排序相关 | U2/U4/U7 |
| 卡点命中率 | 切点落在 beat 容差内的比例 | E4 |
| 偏移正确率 | L/J cut 偏移方向正确率 + 不越界率 | E3 |
| 切换一致率 | 多机位切换时机与人工剪辑的一致率 | E5 |
| 叙事连贯性 | 人工 1–5 分 | E6 |
| **结构可用率** | **用户只微调、不改结构的提案占比（C4 主指标）** | 端到端 |
| 双声/静音缺陷率 | 渲染后音频缺陷（预览=导出一致性） | E3 |

### 11.3 回归纪律

任何改动**信号算法、融合权重、规划器规则或提示词**的提交，必须跑评测基线并附对比。
**指标回退即红**，不得以"主观感觉更好"通过验收。

## 16. 一页速览

- **目标**：以 §1 七条可证伪标准定义"与成熟软件基本对齐"，而非口号。
- **关键结构**：新增**剪辑语法层**（确定性、零 egress、纯函数、统一输出 TimelinePatch），
  与 LLM 编排层并列，形成 P-A / P-B / P-C 三条组合路径。
- **关键认知修正**：CV 不是转录的兜底，是**一等信息源**（DEC-9）；
  "AI 粗剪"不等于"LLM 选段"，而是五条通路。
- **优先顺序**：地基（性能门 + 评测体系 + 链接模型）→ A 类确定性手法（卡点 / L-J / 跳切）
  → 多机位 → 画面语义 → 编排与生态 → 总对标验收。
- **不变量**：I1–I8，其中 I5（确定性优先）与 I8（可解释）为本总纲新增。
- **最大差异化**：A 类能力**零 egress、无需 consent、1 秒出提案**——隐私承诺反向带来的体验优势。
- **最大风险**：W2.2 diarization 选型失败（多机位线受阻，已隔离在 Wave 2 内，
  不阻塞 Wave 1）；4K60 档未标定（素材到位即测）；C4 质量基线缺失（W0.4 解决）。
