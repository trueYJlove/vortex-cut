# Provider 紧凑弹窗实施记录（2026-10-07）

本记录描述本次改动与验证；当前状态以 [STATUS.md](STATUS.md) 为准。

## 1. 用户反馈与设计

原界面在同一页堆叠已有配置、密钥操作、新建表单和预设卡片，在非全屏窗口中占比过大。改为单任务视图：

- 无配置默认进入新建；有配置默认进入管理。
- 新建沿用参考截图的单列字段顺序：提供商模式、预设下拉（仅预设模式）、显示名称、地址、协议、密钥、模型 ID。
- 已有 Provider 也用下拉选择；新建与管理内容不同时渲染。
- 宽度上限 480px；高度由视口 80% 及 600px 上限约束，正文独立滚动，标题与操作栏不随正文滚动。
- 删除重复提示盒、预设卡片网格及误导性的「Provider ID / 显示名称」合并标签；后端 ID 自动生成，不伪造可编辑 ID。
- 协议仅展示已实现的 OpenAI Chat Completions，不暗示 Anthropic 已可用。

## 2. 安全与兼容性

新建时可填写密钥，通过既有 Main-only secret API 提交，绝不放入 createProvider 请求或 Provider DTO。新建成功但密钥同步失败时保留配置、提示重试，避免重复创建；输入在提交及视图切换时清空。管理页切换 Provider 会清空尚未保存的密钥，防止写入其他配置。既有保存密钥后的三组能力状态重置不变。

## 4. 视觉验证
