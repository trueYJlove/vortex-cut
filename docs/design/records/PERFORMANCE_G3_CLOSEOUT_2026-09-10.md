## 2. C23:不实施分块倒放,交付护栏(实证决策)

### 2.1 实证依据(2026-09-10 同机实测)

FFmpeg `reverse` 滤镜将单段全部解码帧驻留内存:

| 场景 | 实测峰值 RSS | 理论上界(未压缩帧) |
|---|---:|---:|
| 10s 1080p 段,`-f null` | 137 MiB | ≈890 MiB |
| 60s 1080p 段,`-f null` | **4868 MiB** | ≈5339 MiB |

结论:60s 倒放段已逼近常见工作站内存上界,长源倒放现状**不可用**
(用户可从 UI 触发——属性面板有倒放开关,合成预览拒收倒放、导出走
`reverse` 滤镜)。分块方案(reduce 重启多 pass)是 FFmpeg 滤镜级改造,
涉及无损中间缓存、磁盘预算、原子发布、调度接入——实验成本大,且
当前无用户诉求(倒放为导出端小众特性,合成预览本就不支持)。

### 2.2 交付的护栏(而非无声失败)

- `build_timeline_args` 构图前对可见视频倒放段按 `REVERSE_MEMORY_
  BUDGET_BYTES`(2GiB,1080p ≈ 22s 段长)估算驻留;超出 → 显式
  `DomainError("RENDER_REVERSE_TOO_LONG")`,文案含实际估算与建议
  (缩短片段/拆分倒放)。不伪装成"能跑但很久/中途 OOM"的任务。
- 错误码已注册 contracts `ERROR_CODES`;jobs 层错误文案已映射。
- 预算估算按导出规格 30fps × yuv420p(1.5B/像素);隐藏轨段与
  正向段不受影响(单测锁定)。
- 短倒放段(预算内)行为与旧版逐字符一致(既有 25 项 ffmpeg 构图
  单测全过,含倒放参数图断言)。

### 2.3 不实施项的诚实边界

- 长源倒放(> 预算)当前**明确失败**并给出可操作文案——不是"已优化"。
  若未来需要,分块倒放按计划 C23 设计推进(reduce 重启 + B10 缓存
  接入),并重新过正确性门(帧编号夹具跨块边界)。
- 合成预览对倒放持续拒收(`PREVIEW_IR_UNSUPPORTED`,R11 白名单),
  UI 回退交互预览——既有语义,未改动。

## 3. C24:不实施,实验未启动

进入条件(计划原文):"分阶段 profile 证明 CPU decode/filter 占导出
主要时间,并且目标硬件支持拟用路径"。

现状:尚无分阶段导出 profile 证据(F03 实测轮只有 encode/validate
两段拆分,decode 供给未单列)。硬件编码器矩阵(NVENC/QSV/AMF)也未
在性能轮覆盖。两项进入条件均不满足,启动 GPU 滤镜实验属于无证据
投入——按计划"结论允许是'不上线'"结项,现有 CPU 图保持默认,
`gpu_pipeline.py` 未创建,无实验残留路径需要维护。
