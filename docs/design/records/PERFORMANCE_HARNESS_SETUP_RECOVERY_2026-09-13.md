## 1. 交付内容(`performance-editor.spec.ts` setup 段重构为有界恢复循环)

- **原状**:"预览状态 synthetic 但 canvas 不可见/不存在"的已知脆点
  (C20T AB §8.1 登记,本轮 3 现场升级)无恢复路径——60s 可见性检查
  超时即整轮失败。
- **现行为**:setup 序列(reload → perf 等待/配置 → 项目断言 → 状态
  轮询 → 票据竞态重试环 → canvas 可见性)包进 **≤3 次有界循环**;
  canvas 超时**且状态仍为 synthetic**(= 竞态形态)→ `page.reload()`
  重建装配再试(≤2 次恢复,计入 `setup_recovery_count`——分析时剔除
  该 run 的 ready 绝对值,与既有票据竞态恢复的计数披露同型)。
- **响亮失败边界**:超限(setupAttempt ≥ 2)或状态非 synthetic
  (fallback/其他 = 非本脆点)→ 按原样抛出,不掩盖。最坏情形 =
  原行为(恢复分支 bounded + 失败即抛);真实竞态现场的恢复经计数
  可审计。
- **机会性验证口径**(如实登记):竞态无法按需复现,恢复分支由真实
  轮次机会性验证——后续任一轮若出现恢复,`setup_recovery_count ≥ 1`
  的样本即为直接证据;常规路径回归由本工作单冒烟覆盖。
