**A6 最初没有任何测试**——是本次收口审计时发现的缺口。
补测时**第一次写错**：负向对照把外发代码注入到**模块导入期**，那时拦截器尚未安装，
导致「注入后测试仍全绿」——**该测试当时是恒真的**。
修正为注入到**函数体内**后，注入 ⇒ 2 项红、恢复 ⇒ 4 项绿，判据才有区分力。

## 4. A8（C2 命中率）——为什么不能标「达标」

**这不是敷衍，是定义问题。**

门 §3 A8 原文：「本门不设数字 —— 须先有语义语料」。此后语料问题已由两轮评测解决：

| 实验 | 内容 | 结果 |
|---|---|---|
| v2（品类词） | 59 张真实图片 / 10 类 | S1–S5 全过；**S5 同类簇聚 59/59 = 1.000**；top1 10× 随机 |
| v3（句子级） | 58 张、Commons 编辑者独立书写的英文描述 | T1–T5 全过；**T5 打乱配对 top1 = 0/58**（真实 42/58）；top1 **42×** 随机 |

⇒ **「语义检索在真实素材上有效」已被证明**（两个独立维度：同类聚拢 + 描述定位）。

**但 C2 的数值门限在总纲 §1 里从未定义**（只有「检索评测集命中率」这句话，无数字）。
本门与两份预登记都明确禁止自设 C2 数字（避免 W2.2 的「拍门槛」失败模式）。
⇒ **正确表述**：语义有效性已证；**C2 达标与否取决于一把尚不存在的尺子**。

## 5. 环境与踩坑记录（供后续复用）

### 5.1 网络（本次最大的时间成本）

**根因不是「网络不通」，而是「测试方法错」**：

| 现象 | 真相 |
|---|---|
| `curl https://github.com` → DNS 超时 | curl/git **不读 Windows 系统代理**，自己去解析 DNS，TUN 的 DNS 劫持未覆盖它们 |
| `curl --resolve github.com:443:<ip>` → **200** | 网络本身通畅 |
| 加 `-x http://127.0.0.1:10808` → 5/5 稳定 200 | 走代理即正常 |

**10808 是混合端口**（http + socks5 均可），无需 `socks5h://`。
**教训**：判断「网络不可达」前，必须先用 `--resolve` 或显式代理验证，否则会把配置问题误判成网络问题。

### 5.2 素材下载

- Pexels / Pixabay / Mixkit / Coverr / archive.org / HuggingFace：**实测全部不可用**；
- **Wikimedia Commons 可用**（视频 1.45 万条 / 图片 2267 万条）；
- **HTTP 429 限流**：Wikimedia 明确要求「改用官方推荐尺寸的缩略图」，原图大并发必被限流；
  改缩略图 + 严格节流后 59/60；
- Commons API 用 `titles=` 逐条查 imageinfo 时，非 ASCII 标题（`ß` 等）编码损坏 ⇒ 大面积 missing；
  **改用 `generator=search` 一次取回**可绕过。
