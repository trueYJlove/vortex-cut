# Vortex Cut UI/UX 设计基线

> 日期：2026-08-23  
> 状态：待用户审阅  
> 适用范围：桌面端 Renderer UI/UX 首轮重构  
> 产品定位：专业能力与易用性平衡

## 1. 目标与非目标

### 1.1 目标

Vortex Cut 采用“专业编辑骨架 + 任务模式 + 受控 AI 辅助层”的交互模型，服务中国用户的短视频、口播、电商、课程、营销和政企内容生产，同时保留进入精确时间线编辑的能力。

首轮 UI/UX 重构需要解决：

- 用户是否能快速理解项目、素材、预览、时间线和属性之间的关系；
- 素材预览与项目预览是否明确区分且保持联动；
- 当前焦点、选中对象、保存状态、预览状态和任务状态是否始终可见；
- AI 粗剪、AI 修改、图片生成和其他自动化结果是否可审查、可确认、可撤销；
- 现有能力是否被统一到较少的任务入口，而不是继续堆叠独立面板。

### 1.2 非目标

本轮不新增以下业务能力，也不把尚未实现的能力伪装成已完成：

- 完整多轨音频编辑；
- 转场、关键帧、变速、倒放等 M2 高级编辑能力；
- 全新的时间线数据模型或 Core 命令协议；
- 真实 Provider 能力扩展、网络策略变更或费用能力变更；
- 任意停靠式工作区和多显示器布局系统；
- 平台发布 API 或平台规则的硬编码。

现有功能仍使用已有 Contracts、Electron IPC、Core 和 SQLite 链路。若某个 UI 改动需要新命令或状态事件，应单独进入实现计划和合同设计，不在视觉改造中隐式添加。

## 2. 用户与核心任务

### 2.1 主要用户

- 需要快速完成中文口播短视频的普通创作者；
- 需要批量处理素材、字幕和平台版本的内容运营人员；
- 需要检查 AI 建议并保留人工控制权的专业用户；
- 需要本地优先、可审计、可控制外传的团队或组织用户。

### 2.2 主路径

```text
创建/打开项目
  -> 导入或检索素材
  -> 素材级预览、转录或筛选范围
  -> 加入时间线
  -> 项目级预览与编辑
  -> 生成权威预览
  -> 导出或生成平台版本
```

AI 路径插入在素材准备或时间线编辑阶段，但不绕过正式项目状态：

```text
输入目标
  -> 显示外传/处理预览
  -> 用户确认
  -> 生成候选或任务
  -> 查看结果与影响范围
  -> 显式采用
  -> 创建 Revision
```

## 3. 信息架构

### 3.1 三层结构

Vortex Cut 使用三层结构：

1. **项目层**：项目选择、项目管理、保存状态、全局命令、导出任务状态。
2. **工作区层**：剪辑、字幕、AI 工作台、导出四种有限模式。
3. **对象层**：素材、转录句子、时间线片段、字幕、AI 提案、导出任务等当前对象。

工作区只控制工具和信息密度，不复制项目数据。切换工作区不得丢失当前播放位置、选中对象、草稿和任务状态。

### 3.2 顶部区域

顶部采用两行结构：

- **项目栏**：Vortex Cut 标识、项目名称/项目选择、保存状态、当前任务摘要、窗口控制。
- **命令栏**：文件/编辑/查看/帮助菜单、工作区切换、命令搜索、撤销/重做、预览过期提示、导出入口。

顶部必须稳定显示：

- 当前项目；
- `已保存`、`保存中`、`保存失败`、`草稿冲突`；
- 权威预览是否过期；
- 正在运行的导出、转录或 AI 任务数量；
- 当前工作区。

顶部不承载完整属性表单，也不放置会遮挡时间线的长文本状态。

### 3.3 主编辑区

默认布局保留现有四区骨架：

```text
左侧媒体区 | 中央预览区
-----------+-----------
时间线     | 右侧上下文属性区
```

实际窗口中，时间线横跨中央区域并固定在底部；右侧属性区从主预览区延伸到时间线顶部。左、右侧栏和时间线高度可以调整，但调整范围必须有稳定最小值，避免预览、时间线或属性内容不可用。

- **左侧媒体区**：媒体库、转录、生成素材、镜头需求，通过标签或模式切换；不为每项能力永久增加独立栏。
- **中央预览区**：根据焦点显示素材预览或项目预览，显示播放状态、时间码、预览类型和过期状态。
- **底部时间线**：正式编辑状态的主要可视化区域，显示轨道、片段、字幕、播放头、选中状态和拖放目标。
- **右侧属性区**：只显示当前对象相关属性；无选中对象时显示项目摘要、常用下一步和状态检查。

### 3.4 工作模式

#### 剪辑

默认模式，包含媒体库、素材预览、项目预览、时间线、片段属性和基础编辑命令。普通用户打开项目后直接进入此模式。

#### 字幕

聚焦转录、字幕句子、文本校对、时间范围和字幕样式。字幕模式仍显示项目预览和字幕轨道，不打开独立于正式时间线之外的“字幕副本”。

#### AI 工作台

聚焦 AI 粗剪、AI 修改、镜头需求、图片生成和候选结果。AI 工作台可以使用模态或侧栏，但结果必须返回候选、提案或任务状态，并提供进入正式时间线的显式操作。

#### 导出

聚焦权威预览、平台/画幅目标、编码参数、输出路径、任务队列、失败原因和产物操作。导出模式不允许隐藏未保存修改、预览过期或缺失素材警告。

## 4. 核心交互规则

### 4.1 素材预览与项目预览

预览区必须明确显示当前预览上下文：

- **素材预览**：素材库或转录句子获得焦点时使用；播放、设置范围和加入时间线不会自动修改正式时间线。
- **项目预览**：时间线或项目获得焦点时使用；播放头定位到正式时间线并反映当前草稿。
- **权威预览**：由 Core/FFmpeg 生成的可复核产物；时间线修改后标记为过期，不能继续显示为最新结果。

同一个预览容器中可以切换三种上下文，但必须显示标签和来源，避免用户误以为素材预览已经进入时间线，或把交互预览误认为权威产物。

### 4.2 选中、焦点与上下文属性

选中对象与输入焦点分别可见：

- 时间线片段：显示清晰边框/高亮，右侧显示片段属性；
- 字幕：显示字幕对象高亮，右侧显示文本、时间和样式；
- 素材：显示素材选中状态，中央切换素材预览，右侧显示素材状态和可用动作；
- AI 提案：显示影响范围、变更摘要、来源和采用按钮；
- 导出任务：显示任务状态、进度、取消/重试和产物入口；
- 未选中：右侧显示项目概览、保存/预览/媒体检查和下一步动作。

快捷键只作用于当前明确焦点。文本输入、选择框和命令搜索获得焦点时，删除、空格等编辑快捷键不得误操作时间线。

### 4.3 时间线

本轮时间线 UI 只规范现有能力的可理解性：

- 视频/图片片段与字幕片段使用稳定的轨道颜色和对象标签；
- 播放头始终可见，并与预览时间码同步；
- 拖放素材时显示目标轨道和插入位置；
- 选中片段、锁定片段、缺失素材和待采用对象使用不同状态；
- 所有改变正式时间线的操作都能进入撤销历史，并在保存状态中反馈；
- 不在本轮引入磁性时间线或隐藏轨道碰撞规则；轨道关系继续保持显式。

### 4.4 AI 结果

AI 相关操作统一遵循：

1. 收集输入与目标；
2. 显示将要外传或处理的数据摘要；
3. 用户显式确认；
4. 生成任务、候选或提案；
5. 展示结果、来源、影响范围、失败原因和费用/网络状态；
6. 用户显式采用；
7. 采用后创建 Revision，并支持撤销或版本对比。

任何“采用”“应用到时间线”按钮都必须说明作用范围，不能仅使用模糊的“确定”。

### 4.5 保存、预览和任务反馈

反馈分为三类，不相互替代：

- **保存状态**：当前草稿是否已持久化；
- **预览状态**：交互预览是否可用，权威预览是否最新；
- **任务状态**：转录、AI、渲染、导出等异步任务的队列、进度、失败和取消。

状态显示优先靠近相关对象，同时顶部保留摘要。失败信息必须安全、可行动，不暴露底层堆栈、密钥或完整 Provider 响应。

## 5. 视觉方向

### 5.1 视觉基调

- 采用深色桌面工作站风格，降低长时间编辑的视觉疲劳；
- 使用蓝色作为主要交互强调色，使用绿色/黄色/红色表达状态，而不是把所有信息都做成强调色；
- 面板边界、选中边界和状态提示具有稳定层级；
- 保持紧凑密度，但给时间线、预览和主要操作留出足够空间；
- 圆角只用于控件、浮层和明确的内容容器，避免连续嵌套卡片；
- 图标按钮必须有 `aria-label` 和 tooltip，陌生图标不得只依赖图形含义。

### 5.2 视觉状态词汇

- 蓝色：当前模式、可执行主要动作、选中对象；
- 绿色：已保存、已完成、可用；
- 黄色：待确认、过期、处理中或需要注意；
- 红色：失败、缺失、冲突或不可恢复风险；
- 灰色：禁用、未配置、辅助信息。

同一状态在按钮、标签、时间线对象和通知中使用相同含义，不能只通过颜色表达，必须同时有文字或图标语义。

## 6. 可程序化性约束

UI 不直接改写隐藏状态。每个面向用户的主要动作都应映射到稳定命令或现有 IPC：

- 创建/打开/重命名/归档项目；
- 导入、预览和检索素材；
- 选择范围、加入时间线、编辑片段；
- 生成和采用 AI 候选/提案；
- 生成权威预览；
- 创建、取消、重试和查看导出任务；
- 撤销、重做和查看 Revision。

命令应拥有稳定 ID、用户可读名称、可用上下文、快捷键（如有）和结果事件。视觉重构不得为了方便 UI 而绕过 Core、Electron preload 白名单或现有 Revision 机制。

## 7. 实施阶段与验收

### 阶段 1：骨架和反馈

- 统一两行顶部栏和四区布局；
- 统一工作模式入口和当前模式状态；
- 明确素材预览、项目预览、权威预览标签；
- 重整媒体区的标签、搜索/筛选入口和状态显示；
- 重整右侧上下文属性空态与对象态；
- 强化时间线播放头、选中、锁定、缺失和拖放反馈；
- 统一保存、预览过期和任务摘要反馈。

**验收条件：** 用户可以从项目到素材、时间线、预览和导出完成主路径；任一时刻都能判断当前焦点、保存状态、预览状态和任务状态；现有业务测试不回归。

### 阶段 2：任务模式

> **状态（2026-08-27 定案）：本阶段已实现并随后裁撤，正式放弃。**
> 四任务模式导航（剪辑/字幕/AI 工作台/导出）曾在阶段 2 落地，但真机验收显示它对当前
> 功能体量是多余的层级——所有能力在单一编辑骨架内已有清晰入口，模式切换反而增加导航成本。
> 相关代码已移除；测试 `apps/desktop/tests/editor-shell.test.tsx` 现断言模式按钮不存在。
> 3.4 节与第 75 行的"四种工作模式"描述保留为历史设计参考，不再作为实现目标；
> 若未来功能规模重新需要任务分区，应以新的提案重启，而不是恢复本阶段方案。

- 将剪辑、字幕、AI 工作台和导出入口收敛为稳定模式；（已放弃）
- 保证模式切换不丢失项目状态；（随裁撤一并失效）
- 让字幕、AI 提案和导出任务使用统一的上下文属性和状态反馈。（仍有效：由单骨架内的属性面板、Dialog 与任务中心承担）

**验收条件（作废，仅存档）：** 每种模式有明确任务目标和主要动作；从模式进入对象详情后可以返回原上下文；AI 结果仍经过确认和 Revision。

### 阶段 3：命令和效率

- 建立统一命令注册表；
- 增加命令搜索、快捷键展示和冲突提示；
- 为素材、转录范围和时间线片段补齐一致的键盘与鼠标操作。

**验收条件：** 菜单、按钮、快捷键和 AI 可调用命令使用同一语义；命令作用域清晰，输入框不会误触发时间线命令。

### 阶段 4：真实窗口验收

- 在 Electron 桌面窗口验证默认尺寸、最小尺寸和调整大小；
- 验证典型中国用户流程：口播字幕、短视频竖屏、电商素材、AI 候选采用、导出任务；
- 验证浅层错误、缺失媒体、权威预览过期、Provider 未配置和任务取消状态；
- 使用桌面截图和自动化测试确认无重叠、溢出、不可见状态或失焦操作。

## 8. 测试策略

- React/Vitest：模式切换、对象选择、空态、保存/预览状态、AI 确认状态和安全错误展示；
- Contracts/Core 定向测试：仅在新增命令或状态事件时扩展，不因纯视觉变更修改业务语义；
- Electron/Playwright：项目打开、素材导入、素材预览、时间线拖放、字幕选择、权威预览过期、导出任务和窗口尺寸；
- `pnpm lint`、`pnpm test`、`pnpm build`、`git diff --check`；
- 对工作区交互保留人工视觉验收，重点检查窄窗口、长项目名、长素材名、错误提示和多任务并行。

## 9. 决策与取舍

- 借鉴 Premiere Pro 的命令化和专业编辑效率，但不首期开放任意面板停靠；
- 借鉴 Resolve 的任务阶段和快速/精确双密度，但只保留四种用户可理解的工作模式；
- 借鉴 Final Cut Pro 的媒体语义组织和范围对象，但保留显式视频/字幕轨道；
- 借鉴剪映的目标驱动、模板/AI 双入口和中文口播工作流，但 AI 结果必须可审查并进入正式 Revision；
- 保留 Vortex Cut 的本地优先、受控外传、权威预览和安全错误边界。
