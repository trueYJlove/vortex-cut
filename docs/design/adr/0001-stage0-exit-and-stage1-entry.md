# ADR-0001：阶段 0 退出状态与阶段 1 准入

- 状态：已批准
- 日期：2026-08-09
- 决策人：用户（产品负责人）、LiuWei（架构师）

## 背景

`docs/design/STAGE0_DETAILED_DESIGN.md` 原始退出条件要求第 20 节全部通过后才能确认阶段 0 完成并进入阶段 1。当前只有一台开发机，无法提供独立干净 Windows 环境和 NVIDIA、AMD、Intel 全部硬件编码器的验证证据。

本机真实 Core、FFmpeg、打包 Electron E2E、安装包和软件编码链路已经形成可用基线，但仍有以下本机可解决问题：

- Python Core 覆盖率 78.10%，低于 80% 门槛。
- VFR 和中文路径真实媒体矩阵未完整闭环。
- Windows 打包仍依赖未统一的前置资源准备。

若把无法取得的外部环境证据与本机工程缺口等同处理，阶段 1 会被无限期阻塞；若直接宣布阶段 0 完成，则会伪造验收状态。

## 决策

1. 阶段 0 保持“本机集成验收通过、全量验收未通过”，不标记为 complete。
2. 阶段 1 的需求确认和详细设计立即开展。
3. 阶段 1 功能编码开始前，必须关闭以下本机门禁：
   - Core 覆盖率不低于 80%。
   - VFR、无音轨和中文路径完成真实 proxy/竖屏输出验证。
   - Windows 构建依赖可以通过受支持命令统一准备和校验。
   - LiuKeAi 对上述门禁出具独立验收报告。
4. 干净 Windows、无开发环境安装和暂时不可获得的 GPU 矩阵转为明确的发布前验证项，不阻塞阶段 1 编码。
5. 任何未验证项必须持续记录为“未验证”，不得用本机结果或软件编码结果替代。
6. 如果后续发现 Sidecar 生命周期、VFR 时间映射、原素材安全、取消清理或安装包独立运行存在结构性问题，立即暂停相应阶段 1 切片并返工，不得以本 ADR 绕过。

## 影响

- `docs/design/STAGE0_DETAILED_DESIGN.md` 保留原始验收要求，作为阶段 0 设计和历史基线。
- 本 ADR 只调整阶段 1 的准入顺序，不将阶段 0 状态改写为完成。
- `docs/design/STAGE1_DETAILED_DESIGN.md` 第 4 节定义可执行门禁，第 25 节继续保留发布和质量要求。
- LiuWei 根据 LiuKeAi 的独立验收报告做阶段决策。

## 否决方案

- **直接把阶段 0 标记完成**：否决，因为缺少干净机、完整 GPU 和部分媒体矩阵证据。
- **等待第二台机器后才做任何阶段 1 工作**：否决，因为外部环境暂不可得，且不影响本地领域设计和开发。
- **完全取消未验证项**：否决，因为这些项目仍影响安装发布和兼容性承诺。
