# 时间区间选取实施记录（2026-11-10 · Round 13）

## 交付
在标尺上 Shift + 拖动即可框出一段时间，视觉表达对齐 OpenFilm 的 range band。

### 新增文件
- src/app/timeline/time-range.ts：TimeRange 类型、归一化、时长、格式化、
  最小可见阈值（MIN_RANGE_US = 50ms，拖太短视为误触）

### 交互设计（为什么是 Shift）
标尺拖动本身已被「擦洗播放头」占用，两者共用同一块命中区。
用 **Shift 区分意图**：普通拖动 = 擦洗，Shift + 拖动 = 框选区间。
Shift 在滚轮上用于横向平移，但那是滚轮手势，与按下拖动不冲突。

### 视觉
- 标尺那 20px 段**实心加深**（rgba(53,214,174,.28)），与 OpenFilm 的 28% 一致
- 轨道区淡填充（.10）+ 两端 2px 亮色把手
- 角标文本：`0:01.00 – 0:03.00（2.00s）`
- 右上角清除按钮

### 刻意不做的事
**不接任何操作。** 区间驱动什么（导出该段 / 删除静音 / 循环播放）尚未定义。
未定用途就接操作，会做出一个「拖出来不知道干什么」的空壳。
OpenFilm 的区间可以拖到聊天里作为引用，但我们的产品还没有那个入口。

### 与既有选择模型的关系
`TimelineSelection` 是判别联合（clip / clips / caption / transition / null），
表达的是「选中了哪个对象」。时间区间是「选中了一段时间」，两者正交。
因此用**独立状态**（`timeRange`），不往那个联合里加分支——
否则所有既有 `selection.kind` 分支都要改一遍，风险远大于收益。
