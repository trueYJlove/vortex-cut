## 0. 现状走读结论（2026-09-24 代码级）

### 0.1 评测资产全缺（总纲 D4 判定成立）

- 全仓库**无**评测集目录、标注 schema、质量指标 harness、基线指标快照。
- 现有 `tools/m3_0/baseline_harness.py` 是**预览画面对拍**（FFV1 基准 + 帧比对），
  属渲染正确性，不是 C4 质量评测。
- 现有 `evidence/` 只有 `cv_sampling` / `m3_0` / `m3_2` / `performance`——均为性能或
  渲染证据，无质量指标快照。

### 0.2 真实样本稀缺（调参无依据的根因）

- 总纲 §1/§2 记载：真实样本 **3 条**，其中 **2 条切点为 0**。
- `planning.py` `_select` 的权重**以单测钉死**，但单测断言的是"实现符合写死的权重"，
  **不是**"权重使真实素材召回更准"。二者不可混同——前者永远绿，后者当前**无法测**。

### 0.3 可复用基座（勿重建）

| 资产 | 位置 | 复用方式 |
|---|---|---|
| 合成素材生成惯例 | `test-assets/generated/`（4K60 等） | 长 GOP / 节拍 / 静音 fixture 照此扩展 |
| 证据归档惯例 | `evidence/<域>/<时间戳>.json` | 质量基线快照入 `evidence/quality_eval/` |
| 切点检测实现 | `media/cv_signals.py` | 切点 P/R 的被测对象 |
| 召回排序实现 | `planning.py` `_cv_scenes` / `_select` | 召回相关性的被测对象 |
| 信号版本与密度 | `cv_analyses`（含 `density_status`） | 评测报告须记录被测分析的密度状态，禁止把 sparse 当 full 比 |

### 0.4 指标依赖分层（决定骨架能测什么）

§11.2 八项指标中，**只有两项在 W0.4 就有被测对象**；其余依赖 Wave 1/2 交付物。
骨架的职责是：**schema 先覆盖八项，harness 先测两项，未就绪项诚实标记 `unavailable`
而不是算出假分数**。

| 指标 | 被测对象现状 | W0.4 骨架 |
|---|---|---|
| 切点检测 P/R | ✅ `cv_signals` 场景切点 | **可测** |
| 召回相关性（nDCG） | ✅ `planning` 排序 | **可测**（有排序标注时） |
| 卡点命中率 | ❌ 无 beat / 无规划器 | schema only → `unavailable` |
| 偏移正确率 | ❌ 无 `split_edit` | schema only → `unavailable` |
| 切换一致率 | ❌ 无多机位 | schema only → `unavailable` |
| 叙事连贯性（人工 1–5） | 无评分表 | schema + 人工评分表模板 |
| **结构可用率**（C4 主指标） | 无端到端粗剪基线 | schema + 人工评分表模板；**不假装自动生成** |
| 双声/静音缺陷率 | 渲染链路已有 | **开放问题 5**（默认不进骨架） |

### 0.5 回归纪律（§11.3）当前零执行面

"改信号算法 / 融合权重 / 规划器规则 / 提示词必须跑评测基线并附对比"——
今天没有可跑的基线，该纪律**不可执行**。W0.4 的 harness 与快照格式就是它的执行面。

## 1. 范围

### 1.1 必须实现

1. **评测集目录结构 + manifest**
   - 五档槽位严格对齐 §11.1：`spoken_single` / `spoken_multi` / `life_no_voice` /
     `music` / `long_gop`；
   - `manifest.json` 登记：`asset_id`、分档、媒体相对路径、`source_fingerprint`、
     时长、编码摘要、是否合成、备注；
   - **媒体文件不强制入 git**（见开放问题 1）；manifest + 标注必须可入仓。

2. **标注 schema（JSON Schema，入仓）**
   - 任务型标注：场景切点列表、召回排序（分级相关度）、静音区间、beat 网格、
     说话人轮次、L/J 偏移（方向 + Δ）、多机位人工切换点；
   - 主观型标注：叙事连贯 1–5、结构可用率（是否只微调不改结构 + 修改备注）；
   - 公共字段：`annotator`、`annotated_at`、`schema_version`（标注 schema 自身版本）、
     `notes`；
   - schema 变更必须递增 `schema_version`，旧标注文件保持可读（可选字段缺省）。

3. **评测 harness CLI**
   - 建议路径：`tools/quality_eval/run_quality_eval.py`（与 `tools/m3_0` 同级，
     **不进** `services/core` 运行时——评测是开发工具，不是产品面）；
   - 输入：manifest + 标注目录 + 可选既有 `cv_analyses`/召回结果缓存；
   - 输出：`evidence/quality_eval/<UTC时间戳>.json` 基线快照；
   - 快照必须自描述：git 提交号、`algorithm_version`、各素材 `density_status`、
     样本数、指标值、样本量、**缺失原因**。

4. **可测指标 v1（仅此两项）**
   - **切点检测 P/R**：预测切点 vs 人工标注切点，容差窗口（默认 ±200ms，写入快照）；
   - **召回相关性**：对有分级相关度标注的 query，算 nDCG@k（k 写入快照）。
   - 两项都必须在**合成 fixture**（已知真值）上有自检——harness 自身的正确性先于跑真实素材。

5. **诚实基线语义（与 ADR-0005 D2 同精神）**
   - 分档样本数 < §11.1 最小样本 → 该分档指标标记 `insufficient`，**不得**输出数值分；
   - 指标依赖能力未就绪 → `unavailable`（见 §0.4）；
   - `insufficient` / `unavailable` 必须带机器可读 `reason`；
   - **禁止**用 3 条真实样本算出一个"基线分"然后当作 C4 证据。

6. **基线指标快照**
   - 对**当前实际持有**的素材（含合成）跑一轮，产出首个快照入 `evidence/quality_eval/`；
   - 快照中明确哪些分档 `insufficient`——这张"缺什么"的表本身就是 W0.4 的交付物，
     用于驱动后续补素材，而不是掩盖它。

7. **回归纪律接入面**
   - 文档化：哪些改动必须跑 harness（对齐 §11.3 四类：信号算法 / 融合权重 /
     规划器规则 / 提示词）；
   - 提供 `compare_baselines.py`（或 harness 子命令）：两份快照对比，
     **指标回退即非零退出**（阈值写入快照/配置，不做运行时可调）；
   - CI 强制挂钩见开放问题 3（骨架不默认上 CI）。

8. **隐私**
   - harness **零 egress**：禁止网络调用；评测素材与标注仅本地；
   - 验收含"无网络出口"断言（静态检查 + 测试环境断网跑通一次）。

### 1.2 明确不做（边界）

- **不实现** Wave 1/2 的任何规划器、beat、diarization、`split_edit`；
- **不实现**自动"结构可用率"评分——那是人工标注 + 端到端产物，骨架只提供评分表与字段；
- **不调** `_select` / sparse 降权等任何生产权重——本单只测不改；
- **不做** Desktop 评测 UI、不做云端评测服务、不传任何素材出本地（I1）；
- **不引入** librosa / 重型评测框架（numpy 足够；对齐 W1.2 的体积纪律）；
- **不把** 预览画面 IoU（M3_0）并入本 harness——不同问题域，避免评测口径混装。

## 2. 设计要点

### 2.1 目录布局（建议，实施可微调但须在实施记录中对照）

```
eval_set/
  README.md                 # 如何补素材、如何标注（人读）
  manifest.json             # 机器可读清单
  schema/
    annotation.schema.json  # 标注 JSON Schema（含 schema_version）
  assets/
    spoken_single/          # 或指向仓外路径的 pointer 文件
    spoken_multi/
    life_no_voice/
    music/
    long_gop/
  annotations/
    <asset_id>.json
tools/quality_eval/
  run_quality_eval.py
  compare_baselines.py
  selfcheck/                # harness 自检用合成真值 fixture
```

### 2.2 标注 schema 要点

- **一文件一素材**，文件名 = `asset_id`；
- 任务标注可缺省——未标注的任务在报告中为 `unavailable`，不是 0；
- 召回标注用**分级相关度**（0–3），以支持 nDCG，而非二元相关；
- 切点标注为时间戳列表（微秒），与 `cv_samples` 时间基一致，避免单位漂移。

### 2.3 指标定义（可测项写死，防止口径漂移）

| 指标 | 公式要点 | 固定参数（写入快照） |
|---|---|---|
| 切点 Precision | 匹配预测 / 预测总数 | 匹配窗 `tol_us`（默认 200_000） |
| 切点 Recall | 匹配标注 / 标注总数 | 同上；一对一贪心匹配（按时间序） |
| nDCG@k | DCG/IDCG，线性折扣 | `k`（默认 10）；rel 为 0–3 |

**禁止**在实现中悄悄改容差或 k 来"救指标"——改参数必须改 schema/快照字段并走本门禁修订。

### 2.4 与 `density_status` 的关系（ADR-0005 衔接）

- 评测跑 CV 相关指标前，读取分析记录的 `density_status`；
- `sparse` 素材的切点 P/R **单独分组统计**，不得与 `full` 混池平均后当作同一基线；
- 理由：D2 的诚实降级已声明 sparse ≠ full 信号；混池会把"降级损失"算进"算法退步"。

### 2.5 回归纪律执行语义

- **谁触发**：提交说明或 diff 触及 §11.3 四类之一 → 实施者本地跑 harness + compare；
- **什么算红**：任一可测指标相对基线回退超过快照中的 `regression_tolerance`
  （默认 0——即不允许回退；放宽必须在规划门/实施记录中论证）；
- **红了怎么办**：不得以"主观感觉更好"关闭（§11.3 原文）；要么改回，要么走基线更新
  并附人工质量说明（叙事连贯/结构可用评分表）。

## 3. 验收（LiuKeAi）

### 3.1 schema 与清单

1. 五档槽位在 manifest 中强制存在（可为空数组，但键与 `min_samples` 元数据必须在）；
2. 标注 schema 对 §11.2 八项均有定义；JSON Schema 校验正/负用例；
3. `schema_version` 变更策略有测试：旧标注（缺新字段）可加载。

### 3.2 harness 自检（合成真值，先证明尺子准）

1. 已知切点 fixture → P=R=1.0（容差内）；故意偏移超窗 → P/R 下降可断言；
2. 已知相关度 fixture → nDCG 与手算值一致；
3. 同输入跑两次 → 快照指标逐字节一致（确定性）；
4. 空标注 / 未标注任务 → `unavailable` + `reason`，不抛未捕获异常、不输出假 0 分。

### 3.3 诚实基线

1. 人为构造"样本不足"分档 → `insufficient` + `reason`，无数值分；
2. 首个真实快照中，**至少**如实暴露：口播单机位/音乐/无语音等分档的缺口；
3. 快照含 `git_commit`、`algorithm_version`、逐素材 `density_status`。

### 3.4 隐私与边界

1. harness 源码无网络客户端依赖；断网环境完整跑通；
2. 不改动 `planning.py` / `cv_signals.py` 生产权重与算法（diff 面检查）；
3. 不引入新增 egress、不动 `PROTOCOL_VERSION`、**无 SQL 迁移**。

### 3.5 回归工具

1. `compare_baselines`：改进时退出 0；任一指标回退超容差时非零退出且指出指标名；
2. 文档列出 §11.3 四类强制跑评测的改动类型（可被 CI 日后引用）。

## 4. 风险

| 风险 | 对策 |
|---|---|
| 真实素材补不齐 → 基线长期 `insufficient` | **允许**——诚实缺口表是交付物；风险对策是"不足则先补素材再调参"（总纲 §13），不是填假样本 |
| 标注主观、不一致 | 切点/静音等任务型标注优先；主观型双人标注字段预留（开放问题 4） |
| harness 口径与未来规划器口径漂移 | 指标公式写死在 §2.3 并进快照元数据；改口径必须改门禁 |
| 把评测做成重型框架、拖慢开发 | CLI + JSON 快照；无服务、无 UI、无框架依赖 |
| 合成 fixture 自检通过但真实素材测不动 | 自检只证"尺子准"；真实跑通以首个快照的**部分成功 + 明确失败项**为验收，不要求一次全绿 |
| 开发者绕过评测直接改权重 | 骨架阶段先靠纪律 + compare 工具；CI 强制见开放问题 3 |

## 5. 开放问题（**已裁决 2026-09-24**，LiuWei 代决，用户授权按最佳判断选择）

> 用户 2026-09-24 授权：开放问题按最佳判断选择。以下五项按原倾向冻结；实施若与裁决冲突，
> 须回本节修订，不得在实施中偏移。

1. **评测媒体存放策略 → (b)**：可合成素材入 `test-assets/generated/`（可复现、入仓）；
   真实素材走仓外 pointer（manifest 登记绝对或相对 pointer 路径 + `source_fingerprint`）。
   fingerprint 以**内容摘要**为准，不以路径为准——路径变化不得使标注失效。
2. **样本不足是否阻断 Wave 1 调参验收 → 阻断质量分验收，不阻断功能合成断言**：
   W1.x 可用合成 fixture 断言功能正确性并合入；**不得**在分档 `insufficient` 时
   声称"真实素材上结构可用率/召回质量达标"。
3. **是否 CI 强制 → 骨架阶段不上 CI 强制**：先 `evidence/quality_eval/` 惯例 +
   本地 compare；素材托管稳定后再议 CI。
4. **主观标注 → v1 单人 + `annotator` 字段**；schema 预留 `secondary`；
   双人一致性指标留到有样本后。
5. **双声/静音缺陷率 → 不进骨架指标集**；标注 schema 仅预留字段，
   指标实现独立小单（避免与 M3_0 预览对拍口径混装）。
