# 多信号融合粗剪需求规格

> 承接 [`AI_CAPABILITY_MASTER_PLAN.md`](../design/AI_CAPABILITY_MASTER_PLAN.md) §6 W4.2 / §14 DEC-9；当前实现与边界统一见 [`../STATUS.md`](../STATUS.md)（P147 / P148）。

---

## 1. 语义裁决背景：DEC-9 与 `fused` 新增（已裁决 A）

总纲 DEC-9 原议题是把缺省值 `candidate_source='auto'` 改为融合并同时要求「旧客户端不传新字段行为不变」。由于不传字段即走 `auto`，两者字面上冲突；最终用户裁决采用 **方案 A**（见 §6 D1）：**`auto`/`transcript`/`cv` 保持逐字节不变，新增 `candidate_source='fused'` 触发多源融合**。

## 2. 范围（D1 = A 生效口径）

### 2.1 必须包含

- 新增 `candidate_source = 'fused'`：**转录 + CV + 节拍** 三源融合排序；
- 融合打分函数**纯函数化**（可单测，无 I/O），照抄 `media/semantic.py` 的分层纪律；
- `fused` 的可用性语义：**至少一源有数据即可运行**，缺失源记录在 `stats` 里（不静默）；
- 旧值 `auto` / `transcript` / `cv` **行为逐字节不变**（回归锁）。

### 2.2 不在本门范围

- **说话人源融合**：见 §3 D2（`quality_status` 恒 `unvalidated`，ADR-0009 已冻结）；
- Desktop 显式来源选择 UI —— 独立切片；
- 融合效果的**质量评测**（需要 ground truth，属独立评测集工作）。

## 3. 设计要点（冻结项，D1 裁决后生效）

### 3.1 融合打分（纯函数）

每段候选携带**已归一化的分项分**：

| 源 | 分项 | 归一化方式 |
|---|---|---|
| 转录 | 关键词命中率、confidence | 命中数 / 关键词总数；confidence 已是 [0,1] |
| CV | 人脸分、运动能量、清晰度 | 各自在**本次候选集内** min-max 归一（跨项目不可比） |
| 节拍 | 切点是否落拍 | 二元（落拍 = 1），按最近 beat 距离阈值判定 |

融合分 = Σ(w_i × score_i)，权重为**显式常量**并写入契约版本，**不得**在实现里散布魔数。

**关键纪律**：归一化必须在**本次候选集内**做（cross-project 归一化会产生不可比分数，
与 W3.1 的 `cosine_rank` 同款教训）。

### 3.2 缺失源语义

- 无转录音频 → 转录分项整体缺席，权重**重新归一**（不是按 0 计）；
- 无 CV 分析 → 同上；
- 无节拍网格 → 同上；
- **三源全缺 → 报 `PLANNING_NO_SEGMENTS`**（与既有「预筛未得到可用片段」同语义）。

**为什么权重重新归一而不是补 0**：补 0 会让「有 1 源」的候选被系统性压低，
与「有 3 源但都一般」的候选不可比。

## 4. 验收（D1 裁决后据此实现）

| # | 验收项 | 判据 |
|---|---|---|
| F1 | `fused` 可用 | 三源齐全时产出候选，`stats.candidate_source == 'fused'` |
| F2 | 缺失源降级 | 逐源缺失（7 种组合）均可运行且 `stats` 记录缺失源 |
| F3 | 三源全缺 | 报 `PLANNING_NO_SEGMENTS` |
| F4 | **旧值行为不变** | `auto`/`transcript`/`cv` 输出与改动前**逐字节相同**（回归锁） |
| F5 | 归一化在候选集内 | 同素材不同项目产生**不同**归一化分（证明非全局归一） |
| F6 | 权重是显式常量 | 权重表可被测试读取并断言，不得内联魔数 |

**每项须配负向对照**（还原实现即红），否则判恒真。

## 5. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| **R1** | 融合排序**无 ground truth**，无法证明「比单源更好」 | 总纲验收项写「融合排序相对单源的可断言提升」——**本门不承诺该断言**，因为不存在客观真值。改为：①结构正确性（F1–F6）②**人工盲评协议**（另立门） |
| **R2** | 权重靠拍脑袋 | 权重表**显式化 + 版本化**，允许将来据评测调整；**本门不声称当前权重最优** |
| **R3** | 契约变更影响旧客户端 | 受 D1 约束；A 方案下无影响 |
