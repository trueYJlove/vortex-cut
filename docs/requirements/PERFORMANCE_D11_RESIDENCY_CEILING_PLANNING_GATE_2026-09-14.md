## 1. 问题重述(性质变化)

B13-R 判别:F02 16.6GiB 为 Chromium 层有界池高水位(~600KB/unique 帧 + ~0.4GB
base,实测 B11-D1 校准 ~631KB/帧,分辨率无关),应用 JS 层无泄漏(framesLive=0),
应用侧无可修对象。R3 变体护栏(`predictResidencyBytes` + 超档位预算一次性预警)
已在产品接线:`preview-session.ts` create 时计算,经 `lastError` →
`.synthetic-metrics` 面板渲染;**该预警在 F02 量级是否真实触发从未验证**(采集面
不在 harness 内)。

**性质变化(v2 默认 on 之后)**:v1 时代 27000 帧是 IR 协议硬上限,16.6GiB 是
封顶值;v2 解除协议上限后,631KB/帧的池成本成为事实天花板——54000 帧(30 分钟
unique 内容)项目协议上可建,实际上 ~33GiB 直接 OOM。D11 不是修 bug,是
**为 v2 的新能力标定边界**:把"能建但会 OOM"变成"建之前就知道",并用便宜的
测量判定 Chromium 上游是否已改变该行为。

## 2. 范围(两步走,只测不承诺)

### 第一步:显式天花板(半天,零风险,独立价值)

1. **产品约束登记**(本文档 §5 表 + 主计划更新·十四):实用 unique 帧数上限
   ≈ (Tab 可用内存预算 − ~0.4GB base) ÷ 631KB,按机器档位给参考值;
   `predictResidencyBytes` 预警为产品内侧表面。
2. **R3 预警真实触发验证**:harness 增加预警采集点(仅 harness 改动——
   ready 后读取 `.synthetic-metrics` 面板文本,进样本 JSON 新字段
   `residency_warning`),F02 最小轮(1 run 冒烟形状)验证预警真实出现在
   完整 App 面板上。预警在 create 时按 IR 帧数计算(不依赖实际解码量),
   冒烟形状即可验证,无需 300s 全速播放。

### 第二步:Chromium 池行为测量型 spike(1–2 天,纯测量,不碰产品承诺)

1. **Electron 新版对拍**:bench 分支(不动工作分支)升一版 Electron
   (当前 36.2.1 → 当期 stable,升幅 ≥2 个大版本;`process.versions.chrome`
   随样本 environment 留证),重跑 F02 驻留 A/B,对拍基线 16,649MB
   (c20t 轮 F02P 同形状实测)。
2. **Chromium flags 探测**:现有二进制加开关对拍(候选:GPU 内存预算类
   `--force-gpu-mem-available-mb`、discardable memory 相关开关、VideoFrame/
   解码池相关 feature flags——候选清单以 Chromium 当期文档/源码核对为准,
   几小时一轮,纯配置)。
3. **顺带收益(不另开工)**:spike 每一轮都为装配竞态根因排查积累现场
   (`setup_recovery_count` ≥1 样本 + desktop.log/user-data 留证)。

### 明确不在本轮(防范围蔓延)

- **不立项 Electron 升级**:对拍命中后才另立工作单(那才是重决策,届时
  有对拍证据可直接提上游 issue);未命中则数据留证,D11 关闭。
- **不做 27k 上限压力验证轮**(C20c Gate §7.9):只有 spike 命中(天花板
  移动)才有立项价值。
- **不做预算硬上限/自动降级**:R3 口径维持"预警不阻断"(B13-R 裁定:
  分配不回收主体在 Chromium 层,应用侧硬上限只制造超预算回退,不影响泄漏)。
- 不改 `predictResidencyBytes` 常数,除非验证暴露明显失配(见 §4 风险)。

## 4. 风险与边界

- **预测常数敏感性**:`predictResidencyBytes` 用 600KB/帧 + 400MB base,与
  B11-D1 实测 631KB 同量级;F02(27000 帧)预测 ~15.8GiB,对三档预算
  (1/2/4GiB)全部超限,**任意机器必然触发**——若 F02 轮未触发,视为产品
  缺陷响亮登记(不静默调常数)。
- 预警文本经 `lastError` 通道,decode 失败会覆盖之;采集点在 ready 后即时
  读取(1s 指标轮询内),冒烟负载无 decode 失败,不构成干扰;若现场被覆盖,
  采集值为 null——如实披露,不视为验证失败。
- spike 升版 Electron 只在 bench 分支,不进工作分支/不改锁文件主口径;
  对拍轮与基线轮同机同电同夹具(F02 fixture sha256 锁定)。
- flags 探测的开关名以当期 Chromium 为准,禁用未文档化的实验 flag 做结论
  (可探索,不作判定依据)。

## 5. 产品约束登记:D11 显式天花板(v2 默认 on 后的有效边界)

**约束**:预览合成会话的解码驻留 ≈ 0.4GB + unique 帧数 × ~631KB(Chromium 池
高水位,分辨率无关、v1/v2 无关、长测无晚发增长)。v2 解除 IR 协议上限后,
这是建长项目前必须核算的事实边界:

| 机器内存 | Tab 可用预算(留系统/App 余量) | 实用 unique 帧上限 | 等效 unique 内容@30fps |
|---|---|---|---|
| 16GiB | ~10GiB | ~1.6 万帧 | ~9 分钟 |
| 32GiB | ~20GiB | ~3.2 万帧 | ~18 分钟 |
| 64GiB | ~45GiB | ~7.1 万帧 | ~40 分钟 |

(当前 IR 协议 27000 帧上限在 32GiB 机器上恰好贴合本约束;16GiB 机器上
27k 项目会逼近 OOM——预警按档位预算更早提示。)

**产品内侧表面**:`predictResidencyBytes` 会话预警(超档位预算一次性提示,
不阻断)——F02 量级真实触发由 §3 验证轮坐实。
