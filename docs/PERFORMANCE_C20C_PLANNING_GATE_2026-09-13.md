## 1. 问题重述(默认 on 后升级为用户可感)

v1 数据面在"同输入 revision 变更"(transform/关键帧/时间编辑)时**会话
保活就地换 IR**:worker/GL 全保留,零黑屏(preview-lifecycle 单测覆盖)。
**v2 数据面无此路径**——`SyntheticPreview` 装配 effect 依赖
`[projectId, revisionId, outputRatio]`,manifest_id 变化 = 新帧源,
**每次 revision 切换(每次编辑/撤销/重做/AI 应用提交)都整会话重建**:
dispose 会话 → 重建 worker/GL/池(inject 段 F01 137ms/F02 201ms)→
manifest 重新投影(**随源缩放:900s 源 1.8s、3600s 源 4.1s**)→ 窗 0
重取 → 全部窗口缓存作废重取。

v2 默认 on 后,这条全量重建链是长项目编辑的常发路径:F02 类项目每次
编辑付出 ~2.2s 装配段 + 1.8s manifest 投影;undo/redo 也不例外。
"输入绑定未变时沿用会话/解码器"正是主计划 C20c 的原始定义(§7.6),
当前具备开工条件(v2 行为正确性经独立验收 + 默认 on 已裁决)。

## 2. 范围(两步,一次 Gate;次序按主计划 §7.6)

### C20c-1:revision 换 manifest 沿用会话(Desktop,无契约改动)

- 判定"input 绑定未变"(沿用 v1 既有 sig 判定:输入集合/音频配置/
  画幅),未变时 revision 切换**不 dispose 会话**:worker/GL/池全保留,
  新 manifest 换发后**帧源就地换装**(新 manifest_id 生效,失配丢弃
  语义不变),窗 0 预热与 manifest 并行(T2 既有模式)。
- 输入变化、项目切换、画幅变化仍走完整重建(保守,与 v1 判定一致)。
- 契约/IPC 零改动。

### C20c-2:dirty-range 窗口复用(Desktop;指纹判定,宁重算不猜测)

- revision 切换时,按**依赖指纹**(主计划 §7.6:源片段映射、转场借用、
  字幕样式、输出规格、相关关键帧)判定未变帧区间,**证明未变的缓存窗
  口跨 manifest 复用**;受影响区间及其后继全部失效(移动/trim/变速使
  后继时间位移,dirty 区间必须覆盖后继——§7.7;全局样式/画幅变化 =
  全部失效)。
- **无法证明未变时一律重算**,不猜测复用;manifest 失配整体丢弃语义
  保留为兜底。
- 拖动中 PiP override 在 revision 提交后清除/重基(§7.8 语义重审,
  会话沿用后 override 生命周期需对齐)。

### 明确不在本轮(登记,防范围蔓延)

- **Core manifest 投影缓存/增量**(ready <2s 方向②,契约层):与
  C20c-2 指纹机制共享依赖,但属 Core/契约改动,待 C20c-1/2 落地后
  按实测另立;
- **F02 段外启动链残差 ~2.9s**(ready <2s 方向①):独立候选,另立
  分段测量工作单;
- **F02 随机 seek 取窗等待**(窗口尺寸/契约层):默认 on 裁决已登记,
  产品反馈驱动;
- **提高 27000 帧上限**(§7.9):需专门的时长/帧数/边界/资源压力验证
  轮,v1 上限不动,不在本轮。

## 3. 验收口径

| 项 | 判定 |

| 回归 | Desktop typecheck + 全量单测通过;v1 路径单测不动即过 |
| 基准口径 | v2 构建为缺省;对照轮按更新·九口径显式设 `VITE_AIVS_PREVIEW_IR_V2=0` 取 v1 |

## 4. 风险与边界

- **复用即错帧是最高风险**:指纹必须覆盖主计划 §7.6 全部依赖项;
  任何无法证明未变的区间一律重算(宁慢不错);golden 帧对拍为硬门。
- 会话沿用后,abort/epoch/stale 语义跨越 manifest 换装仍须成立
  (A01 回归锁复用);旧 epoch 窗口响应可入共享缓存但不得驱动当前播放。
- 音频配置(`SegmentAudioConfig`)变化按输入变化处理(完整重建),
  不做音频链的增量复用。
- 性能呈现不得把 Core manifest 投影成本表述为可由本轮消除——本轮
  只消除 Renderer 重建链,投影成本留待契约层候选。
